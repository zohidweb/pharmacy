# ADR-0004: Выбор Next.js для фронтенда

- **Статус:** accepted
- **Дата:** 2026-09-29
- **Авторы:** Zohid Saidov (z.saidov@eskhata.com), команда проекта Pharmacy

## Контекст

Проект Pharmacy (см. docs/architecture/stack.md и ADR-0003): два веб-фронтенда — клиентский
продукт (касса/склад, сенсорные POS-экраны, буфер офлайн-операций) и админка оператора
платформы — в Nx-монорепо с бэкендом на NestJS (ADR-0003). Жёсткий срок — запуск первой волны
MVP до конца 2026 года. Команда владеет и Next.js, и Angular.

Честная фиксация: это самый спорный выбор стека — есть зрелые альтернативы, и одной из них
(Angular) команда владеет. Решение принято командой осознанно.

## Рассмотренные варианты

1. **Angular** — Плюсы: команда владеет; зрелый «всё включено» фреймворк с LTS. Минусы: второй
   фреймворк в монорепо рядом с React-экосистемой Next.js/NestJS; меньше переиспользования
   кода (формы, стейт, UI-кит) между приложениями; смешанная экосистема повышает стоимость
   сопровождения одной командой.
2. **React (SPA)** — Плюсы: та же экосистема, что у Next.js. Минусы: «голый» React требует
   самостоятельной сборки инфраструктуры (роутинг, сборка, code-splitting), которую Next.js
   даёт из коробки; наиболее вероятная запасная альтернатива.
3. **Next.js (React-фреймворк)** — Плюсы: команда владеет; единая React/TypeScript-экосистема
   с NestJS-бэкендом и общими библиотеками в Nx; готовая инфраструктура (роутинг, сборка,
   оптимизация). Минусы: серверная часть Next.js (SSR) для внутренних приложений (касса,
   админка) не нужна — используется как статический/клиентский фреймворк, что ослабляет
   аргументацию.

## Решение

Выбран Next.js (актуальная стабильная версия, режим SPA/static export) для `apps/web` и
`apps/admin`. Определяющий аргумент — единая React/TypeScript-экосистема с бэкендом и
максимальное переиспользование кода в монорепо одной командой при сроке до конца 2026 года.
Запасные альтернативы — React или Angular: смена фронтенд-фреймворка на этапе проектирования
не влияет на модель данных и API.

## Последствия

- Положительные: один UI-стек на оба приложения; общий UI-кит и формы в `libs/*`;
  ускорение разработки командой с существующими компетенциями.
- **Отрицательные (обязательно):**
  - отказ от Angular при наличии компетенций — прецедент «выбор по предпочтению команды»;
  - Next.js развивается быстро и ломающе (App Router и т.п.) — стоимость обновлений выше,
    чем у Angular LTS;
  - SSR-возможности фреймворка в проекте не используются — платим сложностью фреймворка
    за инфраструктуру сборки.

Управление решениями — ADR-0011 (проект вне банковского контура).
