# Шаги 4–5 вручную: ревью и финализация

## Шаг 4 — Ревью архитектуры (обязательный, человеческий)

Ревью проводит архитектор проекта. Как подать: pull request с архитектурными артефактами
(stack.md, C4, ADR) или прямое обращение к архитектору проекта. Результат ревью записывается
в `docs/architecture/APPROVAL.md`.
Без файла APPROVAL.md со строкой `Статус: APPROVED` финализация запрещена (в Claude Code
её заблокирует /04).

**Lite / post-factum:** если `Статус: APPROVED (post-factum)`, APPROVAL.md обязан также
содержать строку `Дедлайн фактического ревью: YYYY-MM-DD` — без неё финализация запрещена
(это тот же гейт, что и в /04). Архитектор проекта проводит фактическое ревью до
дедлайна и отражает его дату в APPROVAL.md — без этого проект остаётся непроверенным
продакшн-релизом.

## Шаг 5 — Финализация

1. Сохраните стартовый CLAUDE.md: скопируйте его в `docs/architecture/bootstrap-claude-md.bak`.
2. Создайте новый `CLAUDE.md` из `templates/project-claude-md.template`: замените все
   `{{ПЛЕЙСХОЛДЕРЫ}}` данными из stack.md и VERSION.
   Первая строка файла — `<!-- generated by /04 -->`.
3. Создайте пустой файл-маркер `docs/architecture/.workflow-complete` — он снимает
   блокировку кода в hook-предохранителе.
4. Удалите `.claude/commands/01-*.md`, `02-*.md`, `04-*.md` (оставьте `03-adr.md` —
   он нужен весь срок жизни проекта).
5. Удалите папки скиллов невыбранных стеков из `.claude/skills/` — оставьте только скилл(ы)
   вашего стека (например, C# + Angular — оставить `dotnet-dev` и `angular-dev`, остальные
   удалить).
6. Закоммитьте всё. Дальше — разработка по правилам нового CLAUDE.md.

## Несколько кодовых репозиториев

Если в stack.md «Репозитории кода» — отдельные (например, ...-api и ...-web): создайте по
CLAUDE.md на каждый кодовый репозиторий из templates/project-claude-md.template (стек,
структура и команды — только этого репо; в шапке — ссылка на этот репозиторий архитектуры),
скопируйте в корень каждого репо вместе со скиллом его стека (.claude/skills/<стек>-dev/).
Новые архитектурные решения всегда фиксируются здесь (/03-adr), потом код в кодовых репо.
