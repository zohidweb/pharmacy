Дата: 2026-10-15. Статус: утверждена архитектором 2026-10-15 (вместе с решениями автора A1–A21, поправками модели

Связано:

  (`tenants`, `stores`), `README.md` (классы таблиц);
- ADR-0013 (классы таблиц, §4 «Биллинг», §5), ADR-0015 (web, admin), ADR-0016 (сомони), ADR-0018 (права владельца);
- спецификации `2026-10-05-tenants-module-design.md` (сети, блокировка), `2026-10-14-owner-cabinet-design.md`

- готовые экраны на моках:
  - админка — «Счета и платежи», «Услуги», «Настройки», карточка и список компаний;
  - кабинет владельца — «Точки» → «Оплата» и «Услуги».

## 1. Цель и критерии успеха

Оператор платформы выставляет сетям счета за пользование системой и ведёт их оплату в админке на настоящем API. Владелец
видит в кабинете свои счета, долг и аванс, печатает счёт для оплаты и заказывает дополнительные услуги. Сейчас всё это
на моках, а в списке сетей стоят заглушки («оплачено до» пусто, начисление 0).

Успех:
- **Счета за месяц.** После окончания месяца оператор нажимает «Сформировать счета». Каждая сеть, у которой есть что
  выставить, получает один счёт. В счёте:
  - строка на каждую облачную аптеку с продажами в этом месяце; за неполный месяц — пропорционально дням;
  - строки оказанных услуг;
  - скидка сети;
  - НДС отдельной суммой.

  Повторное нажатие новых счетов не создаёт.
- **Сверка вручную.** На тестовом сценарии сумма счёта сходится с расчётом вручную до дирама:
  - первая продажа точки 20-го — 12/31 тарифа;
  - скидка 20 % на три месяца — в этих трёх счетах, в четвёртом её нет;
  - НДС 14 % от суммы без НДС.
- **Распределение платежей.** Оператор вносит платёж на сеть. Платёж сам закрывает самые старые неоплаченные счета:
  - счёт, покрытый не полностью, получает статус «частично оплачен»;
  - лишнее становится авансом и гасит следующие счета сразу при их формировании.

  Отмена или правка платежа пересчитывает распределение, и итог тот же, как если бы платёж сразу внесли правильно.
- **Деньги сходятся.** Сумма по каждой сети: Σ активных платежей = Σ оплаченного по счетам + аванс.
- **Список сетей.** Вместо «оплачено до» — долг и аванс. Фильтр «Не оплачено» показывает сети с просроченным долгом.
- **Услуги.**
  - Владелец заказывает услугу из каталога. Оператор подтверждает её с итоговой ценой или отклоняет с причиной,
    владелец видит решение.
  - Оказанная услуга попадает в счёт за месяц, в котором её оказали.
  - Если услугу отметили оказанной после того, как счёт за тот месяц уже сформирован, строка попадает в ближайший
    следующий счёт.
- **Печать.** Счёт открывается страницей для печати в админке и в кабинете владельца: реквизиты получателя,
  плательщик, строки, НДС, итог, срок, назначение платежа. Из браузера его печатают или сохраняют в PDF.
- **Просрочка.** Владелец получает уведомление о просроченном счёте со следующего дня после срока оплаты.
- **Режим `partial`.** Экраны «Счета и платежи», «Услуги», настройки тарифа и реквизитов, вкладки «Счета», «Платежи»
  и «Услуги» карточки сети, а также блоки «Оплата» и «Услуги» в кабинете владельца работают с API, пометка
  «Демо-данные» на них исчезает.

## 2. Решения, принятые при обсуждении (2026-10-15)

| # | Вопрос | Решение |
|---|---|---|
| B1 | Как платят сети | По-разному: частями, авансом, сразу за несколько месяцев |
| B2 | Платёж и счета | Платёж вносится на сеть. Он закрывает самые старые неоплаченные счета, недоплаченный счёт — «частично оплачен», остаток — аванс сети, аванс гасит новые счета при формировании. Оператор может направить платёж сначала на конкретный счёт. Ошибочный платёж отменяется с причиной и остаётся в истории; правка суммы тоже пересчитывает распределение |
| B3 | Просрочка | Напоминание владельцу в кабинете. Блокировка — вручную, существующей кнопкой в карточке сети. Писем и SMS нет: канала нет, нужен ADR |
| B4 | Какие точки в счёте | Только облачные аптеки с хотя бы одной продажей в месяце; склады не оплачиваются |
| B5 | Неполный месяц | Пропорционально дням: точка открылась 20 октября — 12 дней из 31 |
| B6 | Офлайн-точки | Тариф и счета — отложены до синхронизации (ADR-0014) |
| B7 | Какие услуги | Разовые работы: перенос данных, выезд инженера, обучение персонала. Свободный каталог оператора. Пять пунктов в кабинете владельца (1С, фискализация, уведомления, агент печати, этикетки) — возможности продукта, а не услуги: из блока услуг уходят |
| B8 | Цена услуги | В каталоге базовая цена, итоговую оператор назначает при подтверждении заявки |
| B9 | В какой счёт услуга | По дате оказания: подтвердили 28 октября, провели 5 ноября — в ноябрьский. Не отмеченная оказанной в счёт не идёт |
| B10 | Скидки | Процент на тариф точек сети на срок; услуги скидка не уменьшает |
| B11 | Документ счёта | Страница для печати из браузера; PDF на сервере не нужен (и ADR на библиотеку не нужен) |
| B12 | Список сетей | Вместо «оплачено до» — сколько сеть должна сейчас и её аванс |
| B13 | Как считать продажи точек | При нажатии оператора («Сформировать», предпросмотр), без фоновых задач: по каждой сети в её контексте |
| B14 | Тариф и НДС | Новые значения действуют для счетов, сформированных после изменения; выставленные счета не меняются |
| B15 | С какого дня считать новую точку | С её первой продажи: точку завели 25 сентября, первая продажа 20 октября — за октябрь 12 дней из 31 |
| B16 | Счета заблокированной сети | Заблокированная сеть по-прежнему не входит в систему; её счёт распечатывает и передаёт оператор. Входа «только для оплаты» нет |
| B17 | Добавление услуги сети оператором (2026-10-15, после PR 1) | Идемпотентно, как платёж (A9): `id` (UUIDv7) создаёт клиент; повтор с тем же телом — тот же ответ, с другим — 409 `idempotency_conflict` |
| B18 | Удаление строк на таблицах платформы (2026-10-15, план PR 2) | Не удаляются: правило ADR-0013 и тест каталога (у `pharmacy_platform` на классе `platform` только `SELECT`, `INSERT`, `UPDATE`) не меняются. Снятая строка счёта и удалённая скидка помечаются `removed_at`, история остаётся. Распределения платежей обновляются на месте: сумма 0 — строка больше не покрывает счёт |

## 3. Решения автора (на утверждение вместе со спецификацией)

| # | Тема | Решение |
|---|---|---|
| A1 | Когда можно формировать | Счёт за месяц M — с 3-го числа месяца M+1 по времени `Asia/Dushanbe`: два дня на чеки, накопленные кассой при перебоях связи (модель 06, ADR-0013 §4). Раньше — только предпросмотр (409 `period_not_closed`) |
| A2 | Дни точки | Дни точки — с даты первой продажи точки за всё время (B15) или с 1-го числа, если она продавала раньше, по дату закрытия (бизнес-дата `stores.closed_at`) или по конец месяца, обе даты включительно. Точка в счёте, только если в `store_usage_monthly` за месяц есть хотя бы один чек (`receipts.business_date` в месяце). Закрытие точек как функция ещё не готово: биллинг его не ждёт и берёт дату закрытия из точки, когда она есть |
| A3 | Округление | Строка точки = `round_half_up(тариф × дни / дней_в_месяце)`; скидка строки = `round_half_up(строка × процент_bp / 10000)`; НДС = `round_half_up(Σ строк × НДС_bp / 10000)`; итог = Σ строк + НДС. Всё в целых дирамах, функции — в `libs/shared/domain` (как `prorateExpense`) |
| A4 | Срок и номер | Срок оплаты — 15-е число месяца M+1, но не раньше даты выставления + 10 дней: счёт, сформированный 20-го, не просрочен с первого дня. Номер — `СЧ-ГГГГ-ММ-NNN`, NNN по порядку в периоде по всем сетям (сети по названию), уникален; при пересчёте не меняется |
| A5 | Снимок в счёте | Счёт хранит, что было при выставлении: тариф, ставку НДС, реквизиты получателя, название и ИНН сети, название точки и процент скидки в строке. Печать и пересчёт берут их из счёта |
| A6 | Пересчёт | Только у счёта без оплаты (оплачено 0). Пересчитывает активность сети за месяц и строки точек по тарифу и ставке из самого счёта (а не текущим) и по скидке, действующей на месяц счёта сейчас: так скидка, данная задним числом, попадает в неоплаченный счёт. Строки услуг остаются, кроме отменённых. Текст экрана «по текущим точкам и тарифу» меняется на «по текущим точкам и скидке; тариф и ставка — из счёта» |
| A7 | Распределение | Распределение пересчитывается целиком по сети при каждом изменении (платёж, правка, отмена, новые счета, пересчёт). Активные платежи идут по `(paid_on, created_at, id)`: сначала на «свой» счёт, если указан и не оплачен, потом на счета по `(период, номер)`. Расчёт детерминирован и выполняется под блокировкой строки сети (`tenants … FOR NO KEY UPDATE`: проверки внешних ключей вставок самой сети её не ждут). Таблица распределений производная, её строки пересчитываются на месте (B18) |
| A8 | Статус счёта | Не хранится, выводится: `paid` (оплачено = итог), `partially_paid` (0 < оплачено < итог), `issued` (0). Просрочка — `due_on` < сегодня и оплачено < итог: в списках это фильтр и пометка, а не статус. Отменённых счетов нет (вне объёма) |
| A9 | Идемпотентность | Платёж: `id` (UUIDv7) создаёт клиент, это ключ идемпотентности, как у оплат поставщикам: повтор с тем же телом — тот же ответ, с другим — 409 `idempotency_conflict`. Формирование: уникальность `(tenant_id, period_month)` и advisory-блокировка периода; повтор создаёт 0 счетов. Correlation ID — из запроса, как везде |
| A10 | Скидка | Скидки сети — отдельные сроки в таблице `tenant_discounts`: процент (1–100 %, в bp) и срок «с месяца по месяц» включительно. Сроки одной сети не пересекаются (проверка в сервисе под блокировкой строки сети). Новая скидка на январь–март не отменяет действующую на октябрь–декабрь. Скидку можно дать задним числом: она попадает в ещё не сформированные счета и в неоплаченные — при пересчёте. Удалить можно скидку, ни разу не попавшую в счёт; у попавшей можно сократить срок «по» не раньше последнего выставленного месяца. Строка счёта берёт скидку, срок которой покрывает месяц счёта |
| A11 | Услуги в счёте | В счёт месяца M попадают все оказанные и ещё не выставленные услуги с датой оказания ≤ конец M. Поздняя отметка за уже выставленный месяц уходит в ближайший следующий счёт; описание строки — с датой оказания. Ежемесячных услуг нет: тип оплаты из каталога и контракта убирается |
| A12 | Заявка владельца | Заявка с комментарием (до 500 символов). Пока решения нет, владелец может её отозвать. Новая заявка на ту же услугу — после решения по прежней |
| A13 | Решения оператора | По заявке: подтвердить с ценой (> 0) или отклонить с причиной (≥ 5 символов). Оператор может сам добавить услугу сети без заявки (сразу «подтверждена»). «Оказано» — с датой (не позже сегодня и не раньше подтверждения). Исправление ошибок: пока услуга не попала в счёт — изменить цену, снять отметку «оказано» (назад в «подтверждена»), отменить с причиной. Если строка уже в неоплаченном счёте — только отменить: строка уходит из счёта, его суммы пересчитываются в той же транзакции. В оплаченном или частично оплаченном счёте строку не изменить |
| A14 | Название услуги | RU обязательно, TJ — необязательно (показывается RU); описание так же. Скрытая из каталога услуга не видна владельцу, но её можно добавить сети |
| A15 | Права оператора | Просмотр — `tenants:view`, все действия по деньгам и услугам сетей — `tenants:manage`, каталог и настройки — `platform:manage`. Повторный вход (step-up) — для изменения настроек (тариф, НДС, реквизиты) и скидки сети. Платежи — без step-up: частая работа, всё в журнале |
| A16 | Права владельца | `billing:view` — оплата и печать счёта; `services:view` — каталог и свои заявки; `services:create` — заявка и её отзыв. Права уже есть в каталоге (ADR-0018) |
| A17 | Уведомления владельца | Два новых вида (спецификация кабинета, E10–E12): `invoice_overdue` — состояние: снимается, когда счёт оплачен, получатели с `billing:view`; `service_decided` — событие: подтверждена с ценой, отклонена с причиной, отменена; получатели с `services:view`. Выводятся при обновлении уведомлений из своих строк `invoices` и `tenant_services`: платформа в таблицы сети не пишет |
| A18 | Счётчик в меню админки | `attention.counts` на API: `serviceRequests` — заявки без решения; `expiringLicenses` и `unreadNotifications` — 0, пока нет лицензий и уведомлений оператора |
| A19 | Оценка текущего месяца у владельца | Тот же расчёт, что у счёта (A2, A3, A10), за 1-е … сегодня, с текущим тарифом и ставкой; подпись «оценка, окончательная сумма — в счёте» |
| A20 | Реквизиты получателя | Название, ИНН (9 цифр), расчётный счёт (20 цифр), банк, БИК (9 цифр), корреспондентский счёт (20 цифр), шаблон назначения платежа с `{number}`. Все попадают в снимок счёта (A5) |
| A21 | Склады и офлайн в подсчёте | Платформа не видит вид точки (`stores.kind` ей не выдан, ADR-0013), поэтому отбор делается в контексте сети: в `store_usage_monthly` попадают только облачные аптеки (`kind = 'pharmacy'`, `mode = 'online'`) |

### 3.1 Поправки модели данных (утверждаются вместе со спецификацией)

1. **`platform_settings` → класс `shared`** (было `platform`).
   - Сеть читает тариф и ставку для оценки текущего месяца. Реквизиты получателя секретом не являются: они печатаются
     в каждом счёте.
   - DML — только `pharmacy_platform`. Офлайн-колонки (`offline_store_*`, `feed_window_days`, `revoked_key_grace_days`)
     пока не создаются: офлайн отложен (B6).
2. **`store_billing` не создаётся.** «Оплачено до» убрано (B12). Перевод офлайн-точки в облако с полем `paidUntil`
   откладывается вместе с офлайн-точками.
3. **`tenants`** получает колонку `billing_advance_dirams` — аванс, её пишет пересчёт распределения.

   Сеть читает свою строку уже сейчас (политика `tenant_self_read`). Платежи и распределения сеть не читает:
   оплаченное и остаток она видит в своих счетах.
4. **`invoices`** вместо хранимого `status`:
   - `paid_dirams` и `paid_on` (дата полной оплаты) — их пишет пересчёт распределения;
   - снимок A5;
   - `due_on`;
   - `recalculated_at`.
5. **`services`** — только разовые; `billing_kind` не создаётся.
6. **`service_requests`** (tenant-export) — заявка сети.
7. **`tenant_services`** — решения оператора по заявкам и услуги, добавленные самим оператором (раздел 4).
8. **`tenant_discounts`** (platform) — сроки скидок сети (A10).
9. **Поправка ADR-0013** (одна строка): в классе `platform` к таблицам, свои строки которых читает тенант (`tenants`,
   `invoices`, `invoice_lines`, `tenant_services`, `license_keys`), добавляется `tenant_discounts` — для оценки текущего
   месяца и показа скидки владельцу.

### 3.2 Поправка схемы для PR 2 (2026-10-15)

По B18 и решениям автора плана PR 2 (`docs/superpowers/plans/2026-10-15-billing-services-pr2.md`):
- `invoice_lines` — `removed_at`, `removed_reason` (`recalculated` / `service_cancelled`). Пересчёт (A6) и отмена
  услуги (A13) снимают строки, а не удаляют. Счёт показывает и суммирует только действующие строки. Уникальность
  `tenant_service_id` — среди действующих.
- `tenant_payment_allocations` — `amount_dirams ≥ 0`. Пересчёт распределения (A7) обновляет суммы на месте и обнуляет
  пары, которые больше не покрывают счёт.
- `tenant_discounts` — `removed_at`, `removed_by`. Удалённая скидка не действует и не участвует в проверке пересечений.
- `store_usage_monthly` — плюс `closed_on`: бизнес-дата закрытия точки в часовом поясе сети (A2). Её считает пересчёт в
  контексте сети, потому что платформе `tenant_settings` недоступна.
- `tenant_services` — плюс `request_hash` для повтора добавления услуги (B17) и уникальность `(tenant_id, id)` для
  составной ссылки из `invoice_lines`.
- `invoice_lines.discount_id` — скидка, которую взяла строка точки. «Попавшая в счёт» скидка (A10) — та, на которую
  ссылается действующая строка; скидка, данная задним числом, до пересчёта счёта в него не попала и удаляется.

## 4. Схема

Деньги — `bigint` в дирамах; проценты — `integer` в базисных пунктах; месяц — `date` (1-е число). Ключи и RLS — по
классам ADR-0013, каждая таблица — в `table-classes.ts`. `id` — UUIDv7 из приложения.

**`platform_settings`** (shared, одна строка, `id smallint primary key check (id = 1)`):
- `store_monthly_price_dirams > 0`;
- `vat_bp` (0–10000, по умолчанию 1400);
- `supplier_name`, `supplier_inn` (9 цифр), `supplier_bank_account` (20 цифр);
- `supplier_bank_name`, `supplier_bank_bik` (9 цифр), `supplier_bank_corr_account` (20 цифр);
- `payment_purpose_template` — содержит `{number}`;
- `updated_at`, `updated_by`.

Строка создаётся миграцией с тарифом по умолчанию и пустыми реквизитами. Пока реквизиты не заполнены, формирование
счетов отвечает 409 `requisites_missing`.

**`store_usage_monthly`** (tenant-export) — ключ `(tenant_id, store_id, month)`:
- `receipts_count > 0`;
- `first_sale_date`, `last_sale_date` — в месяце;
- `first_sale_ever_date` — первая продажа точки за всё время (B15; минимум по `receipts_store_date_idx`);
- `computed_at`.

Только облачные аптеки (A21).

Пишется в контексте сети (`pharmacy_app`, RLS): строки месяца удаляются и вставляются заново из `receipts` по
`business_date` (индекс `receipts_store_date_idx` уже есть). Платформа читает (`FOR SELECT TO pharmacy_platform`).

**`invoices`** (platform; сеть читает свои строки) — ключ `id`, уникальны `number` и `(tenant_id, period_month)`:
- `tenant_id`, `period_month`, `number`;
- `issued_at`, `due_on`;
- `price_per_store_dirams`, `vat_bp`;
- `subtotal_dirams`, `vat_dirams`, `total_dirams`;
- `paid_dirams` (0 … total), `paid_on null`;
- снимок: `tenant_name`, `tenant_inn`, реквизиты получателя (A20), `payment_purpose`;
- `recalculated_at null`, `created_by`.

**`invoice_lines`** (platform; сеть читает свои строки):
- `id`, `invoice_id`, `tenant_id`, `position`;
- `kind` — `store` / `service`;
- для точки: `store_id null`, `store_name`, `days`, `days_in_month`, `base_dirams`, `discount_bp`;
- для услуги: `tenant_service_id null` (уникален среди действующих строк, 3.2), `description`, `provided_on null`;
- `amount_dirams`.

**`tenant_payments`** (platform):
- `id` — ключ идемпотентности;
- `tenant_id`, `amount_dirams > 0`, `paid_on`;
- `method` — `bank_transfer` / `cash`;
- `comment`, `preferred_invoice_id null`;
- `status` — `active` / `cancelled`; `cancel_reason`, `cancelled_by`, `cancelled_at`;
- `recorded_by`, `created_at`, `updated_at`, `request_hash` (сверка повтора).

**`tenant_payment_allocations`** (platform) — ключ `(payment_id, invoice_id)`, `tenant_id`, `amount_dirams ≥ 0` (3.2).

**`services`** (shared):
- `id`;
- `name jsonb` (`ru` обязательно, `tj` необязательно), `description jsonb`;
- `base_price_dirams > 0`;
- `visible boolean`, `archived boolean`;
- `created_at`, `updated_at`.

**`service_requests`** (tenant-export; пишет сеть):
- `tenant_id`, `id`, `service_id`;
- `comment`, `requested_by` (сотрудник), `requested_at`.

Заявку без решения сеть может удалить (A12): удаление закрыто, если на неё ссылается `tenant_services`.

**`tenant_services`** (platform; сеть читает свои строки):
- `id`, `tenant_id`, `service_id`;
- `request_id null unique` — ссылка на заявку, пусто у добавленной оператором;
- `price_dirams > 0` (для отклонённой — пусто);
- `status` — `approved` / `rejected` / `cancelled` / `provided`;
- `reason`, `decided_by`, `decided_at`;
- `provided_on`, `provided_by`.

Строка счёта ссылается на неё через `invoice_lines.tenant_service_id`.

**`tenant_discounts`** (platform; сеть читает свои строки — поправка ADR-0013, 3.1 п. 9):
- `id`, `tenant_id`;
- `percent_bp` (100–10000);
- `from_month`, `to_month` (1-е числа, `from_month ≤ to_month`);
- `created_by`, `created_at`, `updated_at`.

**`tenants`** — колонка из 3.1 п. 3.

## 5. Расчёты

**Предпросмотр и формирование за месяц M:**
1. По каждой сети (активной или заблокированной) в её контексте пересчитывается `store_usage_monthly` за M. Делается
   как задача по тенанту по ADR-0013 §4: `runWithContext({ tenantId, correlationId })`, затем `tenantTransaction` под
   `pharmacy_app`.
2. Тенантский модуль `billing` экспортирует порт пересчёта; платформенный модуль биллинга вызывает его по очереди.
3. Затем, под `pharmacy_platform`, строятся строки:
   - точки — по A2 и A3 со скидкой A10;
   - услуги — по A11.
4. Сеть, у которой нет ни строк, ни услуг, счёт не получает.
5. Предпросмотр ничего не пишет, кроме сводной таблицы. Формирование в одной платформенной транзакции:
   - создаёт счета, которых ещё нет;
   - присваивает номера;
   - пересчитывает распределение каждой затронутой сети: аванс сразу гасит новые счета.

**Пересчёт распределения сети** (A7) — после любого изменения платежей или счетов, в той же транзакции:
- обновляет `invoices.paid_dirams` и `paid_on`;
- обновляет `tenants.billing_advance_dirams`.

**Долг сети** — Σ (`total` − `paid`) её счетов. **Просроченный долг** — то же по счетам с `due_on` < сегодня.

- **«Настройки»** — тариф, НДС, реквизиты (с банком, БИК и корр. счётом). Офлайн-блок и «пропорционально дням» скрыты.

- Все маршруты раздела 6.1 — в `REAL_API_ROUTES`; моки повторяют API: те же коды, поля и расчёт.
- Тексты RU/TJ; TJ — в общую вычитку носителем.

## 11. Ошибки (RFC 7807)

| Код | Где |
|---|---|
| 400 `validation_failed` | Поля (суммы ≤ 0, дата платежа в будущем, процент вне 1–100 %, месяц «по» раньше «с», ИНН и счёт не той длины, шаблон без `{number}`) |
| 404 `not_found` | Сеть, счёт, платёж, услуга, заявка |
| 409 `period_not_closed` | Формирование раньше 3-го числа следующего месяца |
| 409 `requisites_missing` | Реквизиты получателя не заполнены |
| 409 `invoice_paid` | Пересчёт счёта с оплатой; выбранный для платежа счёт уже оплачен |
| 409 `payment_cancelled` | Правка или отмена отменённого платежа |
| 409 `idempotency_conflict` | Повтор платежа с тем же `id` и другим телом |
| 409 `service_requested` | Повторная заявка на услугу, по которой нет решения |
| 409 `service_decided` | Отзыв заявки, по которой уже есть решение; повторное решение |
| 409 `service_not_approved` | «Оказано» у услуги не в статусе «подтверждена» |
| 409 `service_invoiced` | Цена, снятие «оказано» у услуги в счёте; отмена услуги из оплаченного или частично оплаченного счёта |
| 409 `discount_overlap` | Срок скидки пересекается с другой скидкой сети |
| 409 `discount_invoiced` | Удаление скидки, попавшей в счёт; сокращение срока раньше последнего выставленного месяца |
| 403 `fresh_auth_required` | Настройки и скидка без повторного входа |

## 12. Вне объёма

  `.superpowers/admin-gap.md`).

## 15. Проверка

Новые тесты отложены до MVP (решение проекта), долг перечисляется в PR. Обязательно:
- **Сценарий на отдельной временной базе со всеми миграциями**, сверенный вручную до дирама:
  - месяц с точкой, впервые продавшей 20-го (заведённой раньше), и точкой, закрытой 10-го (дата закрытия задаётся
    в базе: функции закрытия ещё нет);
  - точка без продаж;
  - склад;
  - две скидки подряд и скидка задним числом с пересчётом неоплаченного счёта;
  - услуга, отмеченная поздно; отмена услуги из неоплаченного счёта;
  - частичный платёж, аванс, отмена платежа.
- **Повтор формирования и повтор платежа** (идемпотентность).
- **Сумма по сети:** Σ платежей = Σ оплаченного + аванс.
- **Изоляция:** сеть видит только свои счета, услуги и заявки (RLS); платформа не читает таблиц сети, кроме сводной.
