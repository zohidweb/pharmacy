# Шаг 1 вручную: выбор стека (без Claude Code)

Результат шага: заполненный `docs/architecture/stack.md`.

0. Есть готовое ТЗ/PRD/бизнес-требования? Возьмите из него ответы для секций 1, 2 и 4 и
   заполняйте только оставшееся. Противоречия и неясности ТЗ — в секцию 6 «Открытые
   вопросы», а не по догадке. Технология из ТЗ вне радара — через EXCEPTIONS.md.
1. Скопируйте `templates/stack-decision-template.md` в `docs/architecture/stack.md`.
2. Определите **тип проекта**: веб-приложение / мобильное приложение / десктоп-приложение /
   API-сервис (без UI) / интеграция-«клей» — впишите в секцию 1, строка «Тип проекта».
   Мобильное → в секции 3 вместо строки Frontend две строки: «Mobile — Android (Kotlin)» и
   «Mobile — iOS (Swift)»; отдельно решите, входит ли BFF (мобильный бэкенд) в этот проект
   (тогда добавьте строку Backend) или это отдельный проект ai-project-start (тогда это
   внешняя система в C4, не строка в стеке). API-сервис (без UI) → строку Frontend не
   заполняйте. Десктоп-приложение → категория Desktop в радаре «На утверждении»: выбор
   технологии — через Архитектурный комитет и `tech-radar/EXCEPTIONS.md` (ускоренно), это не
   блокирует остальные шаги.
3. Определите класс проекта: **Full** (продуктовая система — заполняются все 6 секций) или
   **Lite** (прототип/утилита — секции 1, 3, 5, 6 и одна строка о данных в секции 2; если данные
   чувствительные (ПДн/банковская тайна) — секцию 4 «Интеграции» заполнить обязательно).
4. Заполните секцию 1 «Профиль проекта» — подсказки прямо в ячейках шаблона (для критичности
   используйте тест «система лежит день — что произойдёт?»). Не знаете ответ — запишите
   вопрос в секцию 6, не выдумывайте.
5. Заполните секцию 2 «Чек-лист безопасности». Если данные = персональные или банковская
   тайна — поставьте «Флаг апрува ИБ: ДА». Для мобильных проектов заполните также
   мобильные строки чек-листа (хранение на устройстве, биометрия, certificate pinning,
   root/jailbreak-детект, удалённый сброс).
6. Заполните секцию 4 «Интеграции». Помните: только через утверждённый API-слой, прямой
   доступ к БД АБС запрещён.
7. Выберите стек (секция 3) СТРОГО из `tech-radar/RADAR.md`: статус «Утверждено», при
   наличии «Приоритет» — берите его. Для каждого слоя запишите обоснование и отклонённую
   альтернативу из радара. Технологии со статусом «На утверждении» использовать нельзя.
   Нужно что-то вне радара — `tech-radar/EXCEPTIONS.md`, до апрува не использовать.
7a. Определите репозитории кода (секция 1, строка «Репозитории кода») по правилу
   «один деплой-юнит = один репозиторий»: веб Full — отдельные `-api` и `-web` (обычная
   практика банка); мобильное — отдельные по платформам; API-сервис/интеграция/десктоп —
   один; Lite-прототип — монорепо.
8. Впишите в секцию 5 версию радара (шапка RADAR.md) и версию шаблона (файл VERSION).
9. Если работаете с другим AI-ассистентом: откройте `.claude/commands/01-select-stack.md`
   и вставьте его текст в чат как промпт — он проведёт то же интервью.
