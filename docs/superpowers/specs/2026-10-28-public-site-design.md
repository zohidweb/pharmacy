# Публичный сайт продукта (лендинг, тарифы, блог, заявки на подключение)

- **Дата:** 2026-10-28
- **Статус:** черновик, на согласовании у архитектора
- **Затрагивает:** новое приложение `apps/site`, `apps/api` (публичный контур, модули платформы), `apps/admin`
  (разделы «Заявки» и «Сайт»), `libs/shared/dto`, `libs/shared/domain`, `docker/` (образ, compose, Caddy)
- **Требует ADR:** да — ADR-0023 «Публичный сайт с серверной отрисовкой» (поправка к ADR-0004; затрагивает ADR-0005,
  ADR-0012, ADR-0015). Код — только после `accepted`

## 1. Зачем

Сейчас у продукта два приложения: клиентское (`app.nurmed.online`) и админка оператора (`admin.nurmed.online`).
Корневой домен `nurmed.online` только перенаправляет на `app.` (`docker/proxy/profiles/cloud.caddy`). У продукта нет
лица: владелец аптечной сети не может узнать, что это, сколько стоит и как подключиться.

Нужен третий проект — **сайт для продаж**: возможности, услуги, тарифы, публичная оферта, блог; заявка на подключение,
которую оператор разбирает в админке. Статьи блога пишет человек без навыков разработки — в редакторе админки.
**Индексация поисковиками (Google, Яндекс) обязательна**: блог должен приводить новых клиентов.

Образец пользователя — tijorat.pro (на момент обсуждения сайт был недоступен, ошибка 522; не изучен).

## 2. Цели, не-цели, анти-цели

**Цели**

1. Главная страница, страницы «Тарифы и услуги», «Публичная оферта», «Политика обработки персональных данных», «Блог»
   (список и статья), «Заявка на подключение» — на RU и TJ.
2. Любая страница сайта приходит поисковику готовым HTML с заголовком, описанием, canonical, hreflang; есть
   `sitemap.xml` и `robots.txt`.
3. Оператор публикует статью, оферту или политику в админке — на сайте она появляется не позже чем через минуту, без
   сборки и выкладки.
4. Заявка с сайта попадает в админку; оператор из неё создаёт сеть (мастер «Новая компания» заполнен данными заявки)
   или отклоняет с причиной.
5. Тарифы на сайте — из настроек биллинга (`platform_settings`, каталог `services`): цифры не расходятся со счетами.

**Не-цели (в этой работе)**

- Самостоятельная регистрация с мгновенным доступом, пробный период без оператора — подключение остаётся решением
  оператора.
- Онлайн-оплата на сайте (эквайринга нет, CLAUDE.md).
- Отправка e-mail и SMS: код активации, как и сейчас, передаёт оператор (интеграций нет; новая — через ADR).
- Редактирование текстов блоков главной из админки: тексты главной — в сообщениях i18n в коде.
- Веб-аналитика — **второй этап** (решение пользователя 2026-10-28), со своей спецификацией и ADR: Google Analytics
  и Яндекс.Метрика — внешние SaaS (ADR-0011, IP и cookie посетителей), поэтому выбор между ними и аналитикой на
  своём сервере решается там. На первом этапе сайт не должен мешать её добавить (CSP, место под баннер согласия).
  Подтверждение прав в Search Console / Яндекс.Вебмастере — DNS-записью, без кода на сайте.
- Комментарии к статьям, рубрики и теги, поиск по блогу, рассылка.
- Отзывы и кейсы клиентов — после пилота (сейчас настоящих нет).
- Офлайн-профиль прокси: на точке сайта нет.

**Анти-цели (провал, даже если всё работает)**

- Сайт обещает то, чего продукт не умеет: 1С-выгрузку и фискализацию (исключены на пилоте), офлайн-точки как
  готовый продукт.
- Персональные данные из заявок уходят во внешний сервис (ADR-0011), в том числе через капчу или аналитику.
- Сервер сайта получает доступ к базе, секретам или cookie сотрудников и операторов.
- Публичная форма становится каналом спама в админку или способом перебрать занятые телефоны и логины.
- Вымышленные отзывы, логотипы клиентов, цифры «нам доверяют 500 аптек».

## 3. Ограничения

- Стек проекта (CLAUDE.md, «Fixed technology stack»): Next.js, React, TypeScript strict, Tailwind v4 на токенах
  `--ph-*`, `libs/ui`, FSD (ADR-0017), use-intl, React Hook Form + zod. Новая библиотека — только через ADR.
- ADR-0011: никаких внешних SaaS для ПДн, никакой самописной криптографии.
- Данные сайта (статьи, документы, картинки, заявки) — только в нашей PostgreSQL; попадают в ежедневные копии
  (ADR-0019) без отдельной настройки.
- Один VPS (ADR-0020): процесс сайта должен быть лёгким (ориентир — до 256 МБ памяти).
- Деньги — integer в дирамах, только сомони (ADR-0016).
- Контейнеры — только для чтения, без capabilities, `no-new-privileges` (S3); порты — только на `127.0.0.1`.
- Прокси — Caddy (ADR-0012); заголовки безопасности и CSP — как у web/admin, с поправками ниже.

## 4. Рассмотренные подходы

| | Подход | Плюсы | Минусы | Итог |
|---|---|---|---|---|
| 1 | **Next.js с серверной отрисовкой** (`next start`, ISR с `revalidate`), новое приложение `apps/site` в своём контейнере | Готовый HTML для поисковиков; публикация видна через ≤ 60 с без сборки; тот же стек, `libs/ui`, токены | Ещё один постоянный процесс на VPS; обновления безопасности Next-сервера; поправка к ADR-0004 | **Выбран пользователем** |
| 2 | Статичный Next.js (`output: 'export'`), пересборка при публикации | ADR-0004 почти не меняется; на сервере только файлы | `next build` на продуктовом сервере: контейнер-сборщик с исходниками и зависимостями, минуты сборки, память у API; ломает правило «образ собран заранее»; ошибка сборки ломает публикацию | Отклонён |
| — | Tilda / внешняя CMS | Быстро | ПДн заявок во внешнем SaaS (ADR-0011); редактор не в нашей админке | Отброшен |
| — | HTML-шаблоны в NestJS | Нет нового процесса | Второй шаблонизатор (новая библиотека), дублирование стилей, React-кит не переиспользуется | Отброшен |

Подход 1 — единственный, который даёт одновременно индексацию и публикацию без пересборки на прежнем стеке.

## 5. Архитектура

```
браузер / поисковик
   │ https://nurmed.online
   ▼
Caddy (proxy) ── /api/v1/public/* ─────────────► api:3000  (публичный контур, без сессии)
   │            └─ всё остальное ──► site:3000  (Next.js, next start)
   │                                    │ серверные запросы (сеть compose, http)
   │                                    └──────► api:3000/api/v1/public/*  (только чтение)
   ├─ app.nurmed.online   (как сейчас: web + /api)
   └─ admin.nurmed.online (как сейчас: admin + /api/v1/operator/*; новые разделы «Заявки», «Сайт»)
```

- `apps/site` — **без доступа к базе, Redis и секретам**. Всё, что ему нужно, он читает у API по публичному контуру
  `/api/v1/public/*` — тому же, что видит любой посетитель. Утечка процесса сайта ничего, кроме публичного, не даёт.
- Заявку браузер отправляет напрямую в API (`POST /api/v1/public/connection-requests`) запросом `fetch` с клиента.
  Server Actions, Route Handlers для бизнес-логики и middleware в `apps/site` **не используются** (ADR-0023 разрешает
  только серверную отрисовку страниц и metadata-маршруты `sitemap.xml`, `robots.txt`).
- Свежесть: страницы с данными API — `revalidate = 60`. Активная инвалидация из API в сайт не делается (не нужен
  обратный канал и секрет между ними).
- Сборка образа API не видит: страницы с данными не пререндерятся при `next build` (`generateStaticParams` не
  обращается к API), а отрисовываются при первом запросе и дальше кешируются на 60 с.
- Лимит запросов: все серверные запросы сайта приходят к API с одного адреса контейнера. Публичные `GET`
  (`public/site-info`, `articles`, `legal-documents`, `sitemap`, `media`) получают свой throttler-бакет с повышенным
  лимитом по IP (ориентир — 1200 в минуту) для любого клиента, без привилегий сайту: данные публичны и кешируются.
  `POST public/connection-requests` — свой строгий лимит (7.3).

### 5.1 Решение для ADR-0023 (что фиксирует ADR)

- Для `apps/site` разрешена серверная отрисовка Next.js (`output: 'standalone'`, `next start`, ISR по времени);
  `apps/web` и `apps/admin` остаются static export.
- Запрещены в `apps/site`: Server Actions, middleware, Route Handlers, кроме metadata-маршрутов; `next/image` с
  оптимизацией (нужен `sharp` — новая зависимость) — картинки `unoptimized`.
- Новый образ `pharmacy/site`, сервис `site` в compose (ADR-0005), маршрутизация корневого домена (поправка ADR-0012:
  apex больше не редирект).
- Публичный контур API `/api/v1/public/*` без сессии.
- Отрицательные последствия: ещё один процесс и образ; следить за обновлениями безопасности Next.js-сервера; у сайта
  своя CSP.

## 6. Сайт (`apps/site`)

### 6.1 Страницы и адреса

Русский — без префикса, таджикский — `/tg/...` (моё решение: RU — основной язык аудитории, короткие адреса для RU; код языка — `tg`, как в i18n `apps/web` и в hreflang).

| Адрес | Страница | Данные |
|---|---|---|
| `/`, `/tg` | Главная | i18n + `GET public/site-info` |
| `/tariffs`, `/tg/tariffs` | Тарифы и услуги | `GET public/site-info` |
| `/blog`, `/blog?page=2` | Список статей (по 12) | `GET public/articles` |
| `/blog/<slug>` | Статья | `GET public/articles/<slug>` |
| `/offer`, `/privacy` | Публичная оферта, политика ПДн | `GET public/legal-documents/<kind>` |
| `/connect` | Заявка на подключение | `POST public/connection-requests` |
| `sitemap.xml`, `robots.txt` | Для поисковиков | статьи и документы из API |

Неизвестный адрес или снятая статья — 404 со своей страницей. Статья без TJ-версии на `/tg/blog/<slug>` — 404 и
отсутствует в TJ-части sitemap; hreflang ставится только на существующие версии.

### 6.2 Главная — блоки сверху вниз

1. **Шапка:** логотип, меню («Возможности», «Тарифы», «Блог», «Контакты»), RU/TJ, «Войти» (→ `app.`),
   «Оставить заявку» (→ `/connect`).
2. **Первый экран:** одна фраза о пользе для сети аптек, подзаголовок, кнопка заявки, скриншот кассы.
3. **Для кого и какие боли:** сроки годности и партии, недостачи, несколько точек, касса при перебоях связи.
4. **Возможности:** касса, склад и партии, закупки и поставщики, цены и скидки, перемещения, инвентаризация и
   списания, отчёты и Excel, роли и права, загрузка каталога из файла. Только то, что работает в облачном пилоте.
5. **Как подключиться:** заявка → звонок оператора → создание сети и код активации → загрузка каталога → первая
   продажа.
6. **Тарифы кратко:** цена за точку в месяц (из API) и ссылка на `/tariffs`.
7. **Безопасность данных:** свой сервер, ежедневные проверенные копии, зашифрованные копии вне сервера, HTTPS,
   разграничение прав. Только верные утверждения.
8. **Вопросы и ответы** (тексты i18n).
9. **Призыв к заявке** — кнопка на `/connect`.
10. **Подвал** (якорь `#contacts`, на него ведёт пункт меню «Контакты»): оферта, политика ПДн, реквизиты
    поставщика (из `platform_settings`, если заполнены), контакты.

Название продукта, логотип, контакты и SEO по умолчанию — **настройки сайта** (таблица `site_settings`, одна строка,
как `platform_settings`), правятся в админке «Сайт → Настройки» (8). Название и логотип ещё не выбраны (пользователь,
2026-10-28), поэтому они не зашиваются в код: в шапке, `<title>`, Open Graph и подвале сайт берёт их из настроек.
Поля: название (RU/TG, обязательно для публикации сайта), слоган (RU/TG), логотип и favicon (из `site_media`,
PNG/WebP; SVG запрещён), картинка Open Graph по умолчанию, SEO-описание главной (RU/TG), телефон, e-mail, адрес (RU/TG),
ссылки Telegram и WhatsApp, часы работы (RU/TG). Пустое необязательное поле на сайте не показывается; пока логотипа
нет — в шапке название текстом. Отдаются публично в `GET public/site-info` (вместе с тарифами из 6.3). Выбор
названия и логотипа и заполнение настроек — пункт чек-листа запуска в prod.

Скриншоты — с синтетическими данными (CLAUDE.md: никаких реальных данных клиентов).

### 6.3 Тарифы и услуги

- Цена точки в месяц `store_monthly_price_dirams` и ставка НДС `vat_bp` — из `platform_settings`; подпись по логике
  биллинга: оплата за активные точки по дням месяца, НДС сверху (тексты сверить со спецификацией биллинга
  2026-10-15, A2–A3).
- Разовые услуги — видимые и не архивные строки `services` (название, описание, базовая цена; TJ — если задано).
- Калькулятор «N точек × цена + НДС» — моё предложение, необязательно; функции расчёта — из `libs/shared/domain`.

### 6.4 Форма заявки (`/connect`)

Поля: название сети (обязательно), город (обязательно), число аптек (1–500, обязательно), ФИО контактного лица
(обязательно), телефон (обязательно, E.164 по `normalizeIdentifier`), e-mail (необязательно), ИНН (необязательно,
9 цифр), удобное время звонка и комментарий (необязательно, до 500 символов), галочка согласия с политикой ПДн
(обязательно). Скрытое поле-ловушка и время заполнения (см. 7.3).

После отправки — экран «Заявка принята, оператор позвонит в рабочее время»; номер заявки не показывается
(нечего с ним делать). Ошибки — RFC 7807, тексты по `code`.

### 6.5 Техника

- Nx-проект генератором `@nx/next` (флаги — по `--help`), теги `type:app`, `scope:site`; FSD, Steiger (`nx fsd site`).
- `libs/ui`, токены `--ph-*`, Tailwind v4 — как у web/admin; шрифт — тот же self-hosted из `libs/ui`.
- i18n — use-intl (серверный `createTranslator` для серверных компонентов).
- Серверные запросы к API — свой тонкий клиент на `fetch` с типами `import type` из `@pharmacy/shared-dto`, базовый
  адрес — переменная `SITE_API_INTERNAL_URL` (`http://api:3000` в compose, `http://127.0.0.1:3000` в dev).
- Отрисовка текста статьи — свой рендер блоков (6.6) в React-элементы; `dangerouslySetInnerHTML` запрещён.
- dev: `npx nx dev site` на `127.0.0.1:4400`; `/api/v1/public/*` проксируется на `:3000` (только dev).

### 6.6 Формат текста статьи и документов

Моё решение (новые библиотеки не нужны): текст хранится в **ограниченном Markdown** — заголовки `##`/`###`, абзацы,
`**жирный**`, `*курсив*`, ссылки `[текст](https://…)` и относительные, маркированные и нумерованные списки, цитата,
таблица (pipe-синтаксис), картинка `![подпись](media:<id>)`. Свой парсер в `libs/shared/util` превращает текст в
дерево блоков; сайт и предпросмотр админки рендерят дерево в React-элементы. Всё, что парсер не знает, — обычный
текст (никакого HTML). Ссылки — только `https:`, `http:`, относительные и `mailto:`; внешние — `rel="noopener nofollow"`.
Парсер покрывается тестами (в том числе попытки `javascript:`, HTML-теги, вложенность).

## 7. API

Новые модули — в `app/platform/**` (роль `pharmacy_platform`, данные вне тенантов):

- `platform/site-content` — статьи, юридические документы, картинки; публичное чтение и операторские экраны.
- `platform/connection-requests` — заявки; публичная отправка и разбор оператором.

### 7.1 Таблицы (схема `pharmacy`, классы — в `table-classes.ts`)

**`articles`** — `id uuid`, `slug text unique` (`^[a-z0-9]+(-[a-z0-9]+)*$`, до 120), `status`
(`draft` | `published` | `unpublished` | `archived`; «Удалить» черновик = `archived`, такие статьи нигде не
показываются), `published_at`, `cover_media_id`, `created_by`/`updated_by` (операторы),
`created_at`/`updated_at`, `version int` (оптимистичная блокировка).
**`article_translations`** — `(article_id, locale)` PK, `locale in ('ru','tg')`, `title` (3–150), `excerpt`
(до 300), `body` (до 100 000 символов), `seo_title` (до 70), `seo_description` (до 160). RU обязательна для
публикации.

**`legal_documents`** — ревизии оферты и политики, append-only: `id`, `kind in ('offer','privacy')`, `locale`,
`title`, `body`, `effective_from date`, `published_at`, `published_by`. Текущая — последняя опубликованная с
`effective_from <= today` для `kind`+`locale`. Правка = новая ревизия; старые не меняются и не удаляются (на них
ссылаются согласия заявок). Черновик ревизии — отдельная строка `legal_document_drafts` (одна на `kind`+`locale`).

**`site_media`** — картинки в БД: `id`, `content_type in ('image/jpeg','image/png','image/webp')`, `bytes bytea`
(до 2 МиБ), `sha256` (для повторной загрузки того же файла), `width`, `height`, `alt`, `created_by`, `created_at`.
Моё решение: в БД, а не на диске — попадает в копии ADR-0019, не нужен записываемый том у API. SVG запрещён.
Тип проверяется по сигнатуре файла, не по расширению.

**`connection_requests`** — `id`, `status in ('new','in_progress','connected','rejected','spam')`, поля формы 6.4,
`privacy_document_id` (ревизия политики, с которой согласились), `locale`, `client_ip inet`, `created_at`,
`assigned_to` (оператор), `operator_note` (до 1000), `reject_reason` (5–500), `tenant_id` (сеть, созданная из
заявки), `decided_at`, `decided_by`. Индексы: `(status, created_at)`, телефон для поиска дублей.

**`site_settings`** — одна строка (`id = 1`), поля 6.2.

Все новые таблицы — класс `platform` (`table-classes.ts`): RLS включён и принудителен, политика `platform_all` для
`pharmacy_platform`, гранты `select, insert, update` — **без DELETE** (предел класса, проверяется
`catalog.int-spec.ts`). Поэтому строки не удаляются: черновик статьи — в `archived`, картинки не удаляются в этой
работе, ПДн заявок по сроку обезличиваются (7.4). `pharmacy_app` к этим таблицам доступа не имеет.

### 7.2 Эндпоинты

Публичный контур (`@Public()`, без сессии, отдельный префикс `/api/v1/public/*`):

| Метод и путь | Что делает |
|---|---|
| `GET public/site-info` | Настройки сайта (название, логотип, контакты, SEO), цена точки, НДС, видимые услуги |
| `GET public/articles?locale&limit&offset` | Опубликованные статьи: slug, заголовок, анонс, обложка, дата |
| `GET public/articles/{slug}?locale` | Статья целиком (тело — исходный ограниченный Markdown) |
| `GET public/legal-documents/{kind}?locale` | Текущая ревизия оферты или политики |
| `GET public/sitemap` | Слаги и даты изменения статей по языкам (для `sitemap.xml`) |
| `GET public/media/{id}` | Картинка; `Cache-Control: public, max-age=31536000, immutable` (id неизменяем) |
| `POST public/connection-requests` | Заявка; `201` без тела-идентификатора |

Публичные `GET` отдают только опубликованное; черновики видны лишь операторским предпросмотрам.

Контур оператора (`/api/v1/operator/*`, сессия оператора):

| Метод и путь | Право |
|---|---|
| `GET/POST operator/articles`, `GET/PUT operator/articles/{id}` | `content:manage` |
| `POST operator/articles/{id}/publish`, `.../unpublish`, `.../archive` (только черновик) | `content:manage` |
| `GET operator/legal-documents`, `PUT operator/legal-documents/{kind}/{locale}/draft`, `POST .../publish` | `content:manage` |
| `POST operator/site-media` (JSON `{contentType, dataBase64, alt}`, файл до 2 МиБ; свой предел тела JSON 3 МиБ по пути, как у загрузок `*-imports`), `GET operator/site-media`, `GET operator/site-media/{id}/content` (картинка для предпросмотра в админке: публичный контур на домене админки закрыт) | `content:manage` |
| `GET/PUT operator/site-settings` (PUT — со step-up) | `content:manage` |
| `GET operator/connection-requests?status&q&limit&offset`, `GET .../{id}` | `tenants:view` |
| `POST .../{id}/take`, `.../reject`, `.../mark-spam`, `PUT .../{id}/note` | `tenants:manage` |

Связь с сетью: `CreateTenantRequest` получает необязательное `connectionRequestId`; в той же транзакции, что
создание сети, заявка переходит в `connected` с `tenant_id` (409 `request_already_decided`, если уже решена).

Новое право `content:manage` — в `OPERATOR_PERMISSIONS` (роль `full_access` получает его автоматически). Сайтом
управляют операторы админки (решение пользователя 2026-10-28: «на админке будет раздел для управления сайтом»);
отдельная роль «только сайт» в эту работу не входит — право заводится отдельным, чтобы такую роль можно было добавить
позже без переделки.

Все действия оператора — в `platform_audit_log`: `article.created`, `article.updated`, `article.published`,
`article.unpublished`, `article.archived`, `legal-document.draft-saved`, `legal-document.published`,
`site-media.uploaded`, `site-settings.updated`, `connection-request.taken`, `connection-request.rejected`,
`connection-request.marked-spam`, `connection-request.noted`, `connection-request.connected` — без ПДн заявки в
параметрах (только id и статус).

### 7.3 Защита публичной формы

- Лимит по IP на `POST public/connection-requests` — существующим throttler'ом (Redis), переопределением
  `@Throttle({ default: … })`: 3 заявки в час с адреса (моё решение); общий дневной предел новых заявок — 200 (счёт
  строк за сутки в сервисе; сверх — 429 `too_many_requests`, чтобы спам не забил админку). Публичные `GET` —
  `@Throttle({ default: { limit: 1200, ttl: 60_000 } })`.
- Порядок проверок формы: политика ПДн (`privacy_not_published`) → спам → суточный предел → дубль → новая заявка.
- Поле-ловушка: заполнено — ответ `201` (боту не сообщаем), заявка сохраняется сразу со статусом `spam`; спам не
  считается в суточный предел, не бывает дублем и не порождает уведомления.
- Время заполнения: форма передаёт время открытия; меньше 3 с — `spam` тем же способом.
- Суточный предел проверяется до дубля: на пределе любой телефон получает один и тот же 429, поэтому ответ не
  раскрывает, есть ли у телефона открытая заявка.
- Дубль: тот же телефон со статусом `new`/`in_progress` за 24 ч — новая строка не создаётся, ответ `201`.
- Ответ не раскрывает, есть ли такая сеть или телефон в системе.
- CSRF: `CsrfGuard` проверяет `Origin`; для публичного контура (`isPublicPath` в `common/http/contour.ts`)
  разрешённый origin — новая переменная `SITE_ORIGIN` (обязательна; в prod — `https://`, как `WEB_ORIGIN`).
- Ответы API по умолчанию `Cache-Control: no-store` (`main.ts`); исключение — `GET public/media/{id}`
  (`public, max-age=31536000, immutable`), и в API, и в Caddy.
- Капча (reCAPTCHA, hCaptcha) — нет: внешний SaaS.
- Пока нет опубликованной политики ПДн на языке формы (с откатом на RU), API отвечает 409 `privacy_not_published`,
  а сайт вместо формы показывает «Приём заявок скоро откроется» и контакты. Опубликованные оферта и политика (тексты
  юриста, решение 7.3 ревью безопасности) — условие запуска сайта в prod, пункт чек-листа выкладки.

### 7.4 Уведомление и срок хранения

- Новая заявка (не спам) — уведомление оператору вида `connection_requested` (`platform_notifications`, тема для
  отключения — `leads`) и счётчик «Заявки» в меню админки (`platform/notifications`, число `new`).
- Срок хранения ПДн: у заявок `rejected` и `spam` через 180 дней после решения/создания ПДн обезличиваются
  (ФИО, телефон, e-mail, комментарий, удобное время, IP, заметка оператора — `null`, `anonymized_at` = сейчас) часовым
  проходом `platform/retention` (моё решение; срок указать в политике ПДн). Удаления строк нет — у класса `platform`
  нет DELETE. `connected` хранятся, пока существует сеть.

## 8. Админка (`apps/admin`)

В меню админки — **отдельный блок «Сайт»** (пожелание пользователя 2026-10-28), в нём всё управление сайтом:
«Заявки», «Статьи», «Документы», «Картинки», «Настройки сайта». Пункты блока видны по своим правам; блок скрыт,
если не виден ни один. Счётчик новых заявок — у пункта «Заявки».

**«Заявки»** (`tenants:view`): список с фильтром по статусу (по умолчанию `new` + `in_progress`), поиском по
названию и телефону, датой; карточка заявки — поля, история статусов, заметка оператора, кнопки «Взять в работу»,
«Создать сеть» (открывает «Новая компания» с `?request=<id>`: название, город, ИНН, ФИО, телефон, e-mail владельца
заполнены; логин по умолчанию — телефон), «Отклонить» (причина), «Спам». У заявки, похожей на существующую сеть (тот
же ИНН или телефон владельца), — предупреждение со ссылкой на сеть.

Остальные пункты блока (`content:manage`):
- **Статьи** — список (статус, язык RU/TJ, дата публикации), карточка: заголовок, slug (генерируется из RU-заголовка
  транслитерацией, правится), анонс, обложка, SEO-поля, текст в поле ввода с панелью вставки (заголовок, список,
  ссылка, картинка, таблица) и живым предпросмотром тем же рендером, что на сайте; вкладки RU/TJ; «Сохранить
  черновик», «Опубликовать», «Снять с публикации», «Открыть на сайте». Сохранение — с `version` (409 при чужой правке).
- **Документы** — оферта и политика RU/TJ: черновик, дата вступления, «Опубликовать новую редакцию», список
  прошлых редакций (только чтение).
- **Картинки** — загрузка (jpeg/png/webp, до 2 МиБ), подпись (alt), копирование ссылки `media:<id>`.
- **Настройки сайта** — поля `site_settings` (6.2): название, слоган, логотип, favicon, картинка Open Graph,
  SEO-описание главной, контакты, часы работы. Сохранение — повторный вход (step-up), как у настроек платформы;
  изменение — в `platform_audit_log`.

Публикация меняет сайт в течение минуты — подсказка об этом у кнопки.

## 9. Прокси, контейнер, среды

- `docker/site/Dockerfile` (или `apps/site/Dockerfile`, по образцу `apps/api`): multi-stage, Next `standalone`,
  non-root, код принадлежит root, без source map; `read_only`, кэш ISR — `tmpfs` (после перезапуска страницы
  отрисуются заново), без capabilities, `no-new-privileges`.
- Сервис `site` в `docker/compose.yml` (test, prod); в dev не запускается в Docker — `npx nx dev site`.
- Caddy, профиль `cloud`: `{$APEX_ADDR}` вместо редиректа — `handle /api/v1/public/*` → `api` (лимит тела 1 МиБ,
  `plain-body`, upstream 30 с; для `media` ответ кешируется браузером — исключение из общего `no-store`),
  остальное → `site:3000`; заголовки безопасности и CSP сайта (`img-src 'self' data:`; `connect-src 'self'`).
  `www.nurmed.online` — редирект на apex (нужна DNS-запись). На `app.` и `admin.` маршрут `/api/v1/public/*` — 404.
- Профиль `local` (test): адрес сайта — новая переменная `SITE_ADDR` (`https://pharmacy-test.localhost:8443`
  занят web — предлагаю `https://site.pharmacy-test.localhost:8443`); `SITE_ORIGIN` — тот же.
- `stack build` собирает образ `pharmacy/site` с тем же тегом; `stack init` дописывает `SITE_ADDR`, `SITE_ORIGIN`.
- `robots.txt` в test — `Disallow: /` (переменная `SITE_INDEXING=false`, в prod — `true`), чтобы стенд не попал в
  поиск.

## 11. Решения автора (проверьте при чтении)

| № | Решение |
|---|---|
| P1 | RU без префикса, TJ — `/tg/...`; код языка `tg` (в БД `locale in ('ru','tg')`) |
| P2 | Формат статей — ограниченный Markdown со своим парсером, без новых библиотек; HTML не допускается |
| P3 | Картинки — в PostgreSQL (`bytea`, до 2 МиБ, jpeg/png/webp), отдаются API с неизменяемым кешем |
| P4 | Оферта и политика — ревизии append-only с датой вступления; согласие заявки ссылается на ревизию |
| P5 | Новое право `content:manage` (пока у единственной роли `full_access`, отдельной роли нет); заявки — под `tenants:view`/`tenants:manage` |
| P6 | Защита формы: 3 заявки/ч с IP, 200 в сутки всего, ловушка, время заполнения, дубль телефона за 24 ч |
| P7 | У заявок `rejected`/`spam` ПДн обезличиваются через 180 дней; строки не удаляются (класс `platform` без DELETE) |
| P16 | Картинка загружается JSON с base64 (multipart в API нет; свой предел тела 3 МиБ по пути) |
| P8 | Свежесть сайта — `revalidate = 60`, без активной инвалидации |
| P9 | Тексты главной — в i18n кода, не в админке |
| P10 | Тарифы на сайте — из `platform_settings` и `services` |
| P11 | Статья без TJ-версии на TJ-сайте — 404, без hreflang |
| P12 | Название, логотип, контакты, SEO по умолчанию — `site_settings`, правятся в «Сайт → Настройки»; «Контакты» — якорь подвала |
| P15 | В меню админки — блок «Сайт»: Заявки, Статьи, Документы, Картинки, Настройки сайта |
| P13 | Без опубликованной политики ПДн форма закрыта (409 `privacy_not_published`); оферта и политика — условие запуска |
| P14 | Публичные `GET` — отдельный повышенный лимит по IP для всех; пререндера при сборке нет |
