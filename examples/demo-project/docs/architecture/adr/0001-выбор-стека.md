# ADR-0001: Выбор стека для сервиса уведомлений клиентов

- **Статус:** accepted
- **Дата:** 2026-09-01
- **Авторы:** команда «Сервис уведомлений клиентов» (пример)

## Контекст

Нужен стек для сервиса, который принимает события по счёту от АБС, хранит клиентов, шаблоны
и историю уведомлений, отправляет СМС через внешний шлюз и даёт оператору банка простой
веб-интерфейс. Данные — персональные (ФИО, телефон, сведения об операциях), поэтому выбор
ограничен технологиями радара со статусом «Утверждено» (при наличии — «Приоритет»). Команда
примера владеет .NET и Angular, сроки сжатые.

## Рассмотренные варианты

1. **C# (.NET) + Angular** — обе технологии утверждены радаром (Angular — приоритет), у команды
   есть компетенции в обеих, единая экосистема с другими сервисами банка.
2. **PHP + React** — обе технологии тоже утверждены радаром, но в команде-примере нет
   компетенций в PHP, а React уступает Angular по приоритету радара при прочих равных.

## Решение

Выбран стек C# (.NET) + Angular + PostgreSQL + Redis + REST: backend на .NET, административный
интерфейс на Angular, PostgreSQL как приоритетная СУБД радара, Redis как кэш и очередь
задач на отправку, REST — для интеграции с АБС, СМС-шлюзом и SPA.

## Последствия

- Положительные: команда сразу продуктивна в выбранном стеке; соответствует приоритетам
  техрадара; единая .NET-экосистема упрощает эксплуатацию и найм.
- **Отрицательные (обязательно):** двухкомпонентный стек требует двух компетенций в команде
  (backend на C#/.NET и frontend на Angular/TypeScript) — при уходе одного из специалистов
  требуется замена именно в этой технологии, а не любая свободная пара рук.
