> **Pharmacy:** адаптировано под стек Pharmacy — Jest + supertest в проекте `apps/api-e2e`, стандартный NestJS (Express) вместо Fastify, реальная PostgreSQL из docker compose локальной среды (Testcontainers — «согласовать»), миграции — инструментом из ADR (не Prisma). Ограничения: `CLAUDE.md`.

# NestJS Integration Testing — Setup

## Где живут e2e-тесты

`apps/api-e2e` — отдельный Nx-проект. Он **не импортирует код `apps/api`** (правило границ Nx: apps не импортируют друг из друга), а тестирует API как чёрный ящик:

- HTTP — `supertest` против запущенного api (`request(baseUrl)`);
- состояние БД — прямыми SQL-запросами через `TestDb` (сидирование и проверки);
- типы запросов/ответов — из `@pharmacy/shared-dto`.

Запуск: `npx nx e2e api-e2e` (Nx поднимает зависимость `api` через `dependsOn`/globalSetup).

## PostgreSQL для тестов

Только реальная PostgreSQL — никаких in-memory/SQLite-подмен: RLS, `SELECT … FOR UPDATE SKIP LOCKED`, ограничения уникальности идемпотентности и транзакции должны проверяться на той же СУБД, что в проде.

| Вариант | Как | Статус |
|---|---|---|
| **A. docker compose локальной среды** (по умолчанию) | Сервис `postgres` из `docker/` (ADR-0005), отдельная БД `pharmacy_test`; URL в `apps/api-e2e/.env.test` (в `.gitignore`, в git — только `.env.test.example`) | Доступно сейчас |
| **B. Testcontainers** | Контейнер PostgreSQL поднимается из globalSetup | Новая dev-зависимость `testcontainers` — **согласовать** перед использованием |

Обязательно:
- **Роль подключения приложения — не суперпользователь** и не владелец таблиц (или с `FORCE ROW LEVEL SECURITY`). Суперпользователь обходит RLS, и тест изоляции тенантов «пройдёт» ложно.
- Версия образа PostgreSQL — та же, что в compose облака/офлайн-точки.
- Миграции — тем же инструментом и теми же файлами, что в проде (инструмент фиксируется первым ADR разработки). Никакого schema-sync.

## Global setup: БД → миграции → api

```typescript
// apps/api-e2e/src/support/global-setup.ts
import { execSync } from 'node:child_process';
import { waitForPortOpen } from '@nx/node/utils';

export default async function globalSetup() {
  // Variant A: TEST_DATABASE_URL points to pharmacy_test in local docker compose.
  // Variant B (after approval): start a Testcontainers PostgreSQL here and export its URL.
  const databaseUrl = process.env.TEST_DATABASE_URL;
  if (!databaseUrl) throw new Error('TEST_DATABASE_URL is not set (see apps/api-e2e/.env.test.example)');

  // Apply migrations with the project's migration tool (chosen by ADR).
  // The command is a placeholder until that ADR exists.
  execSync('npm run db:migrate', { env: { ...process.env, DATABASE_URL: databaseUrl }, stdio: 'inherit' });

  // Seed synthetic tenants/employees with the project's seed script — it uses the same
  // password-hashing service as the app (no hashes hard-coded in tests).
  execSync('npm run db:seed:test', { env: { ...process.env, DATABASE_URL: databaseUrl }, stdio: 'inherit' });

  const port = Number(process.env.API_PORT ?? 3000);
  await waitForPortOpen(port, { host: 'localhost' }); // api is started by `nx serve api` (dependsOn)
}
```

## TestDb — прямой доступ к тестовой БД

Тонкая обёртка над драйвером PostgreSQL. Драйвер (обычно `pg`) придёт вместе с выбранным ORM/слоем доступа к данным; до ADR — это dev-зависимость только для e2e, **согласовать**.

```typescript
// apps/api-e2e/src/support/test-db.ts
import { Pool } from 'pg';

type Query = <T = unknown>(sql: string, params?: unknown[]) => Promise<T[]>;

export class TestDb {
  private readonly pool: Pool;

  constructor(connectionString = process.env.TEST_DATABASE_URL) {
    this.pool = new Pool({ connectionString });
  }

  async query<T = unknown>(sql: string, params: unknown[] = []): Promise<T[]> {
    const { rows } = await this.pool.query(sql, params);
    return rows as T[];
  }

  /** Runs statements in one transaction (needed for set_config(..., true) = SET LOCAL). Always rolls back. */
  async inTransaction<T>(fn: (q: Query) => Promise<T>): Promise<T> {
    const client = await this.pool.connect();
    try {
      await client.query('BEGIN');
      return await fn(async (sql, params = []) => (await client.query(sql, params)).rows);
    } finally {
      await client.query('ROLLBACK');
      client.release();
    }
  }

  /** Truncates application tables; keeps the migration-history table (name depends on the migration tool). */
  async reset(keep: string[] = ['schema_migrations']): Promise<void> {
    const tables = await this.query<{ tablename: string }>(
      `SELECT tablename FROM pg_tables WHERE schemaname = 'public' AND NOT (tablename = ANY($1))`,
      [keep],
    );
    if (tables.length === 0) return;
    const list = tables.map((t) => `"${t.tablename}"`).join(', ');
    await this.query(`TRUNCATE ${list} RESTART IDENTITY CASCADE`);
  }

  async close(): Promise<void> {
    await this.pool.end();
  }
}
```

- `TestDb` подключается под ролью-владельцем тестовой БД (для сидирования и `TRUNCATE`), приложение — под своей прикладной ролью. Если append-only таблицы аудита/журнала ПКУ защищены и от `TRUNCATE`, очищайте их этой же ролью или пересоздавайте схему между прогонами.
- Сид-данные, созданные в globalSetup (тенанты, сотрудники), в `reset()` не трогайте — передайте их таблицы в `keep` или пересидируйте.

## Каркас e2e-файла

```typescript
// apps/api-e2e/src/catalog/products.spec.ts
import request from 'supertest';
import { TestDb } from '../support/test-db';
import { TestSeeder } from '../support/seeder';
import { loginAs, TENANT_A } from '../support/auth';

const baseUrl = `http://localhost:${process.env.API_PORT ?? 3000}`;

describe('Catalog API (e2e)', () => {
  const db = new TestDb();
  const seeder = new TestSeeder(db);

  afterAll(() => db.close());

  it('POST /api/v1/products creates product in caller tenant', async () => {
    const agent = await loginAs(baseUrl, TENANT_A.owner);

    const res = await agent
      .post('/api/v1/products')
      .send({ nameRu: 'Парацетамол 500 мг', nameTj: 'Парасетамол 500 мг', isPrescription: false,
              isControlledSubstance: false, barcodes: ['4600000000017'] })
      .expect(201);

    const [row] = await db.query<{ tenant_id: string }>('SELECT tenant_id FROM products WHERE id = $1', [res.body.id]);
    expect(row.tenant_id).toBe(TENANT_A.id);
  });

  it('returns RFC 7807 problem on validation error', async () => {
    const agent = await loginAs(baseUrl, TENANT_A.owner);

    const res = await agent.post('/api/v1/products').send({ barcodes: [123] }).expect(400);

    expect(res.headers['content-type']).toMatch(/application\/problem\+json/);
    expect(res.body).toMatchObject({ status: 400, code: 'VALIDATION_FAILED', correlationId: expect.any(String) });
  });
});
```

```typescript
// apps/api-e2e/src/support/auth.ts
import request from 'supertest';
import { SEED } from './fixtures'; // synthetic seed users, same file the seed script reads

export const TENANT_A = SEED.tenants.a;
export const TENANT_B = SEED.tenants.b;

/** Logs in with project login+password auth (POST /api/v1/sessions); the agent keeps the session cookie. */
export async function loginAs(baseUrl: string, user: { tenantCode: string; login: string; password: string }) {
  const agent = request.agent(baseUrl);
  await agent.post('/api/v1/sessions').send(user).expect((res) => {
    if (res.status >= 300) throw new Error(`login failed: ${res.status}`);
  });
  return agent;
}
```

Способ передачи сессии (cookie/заголовок) и эндпоинт входа — по `nestjs-security-auth.md`. Cookie с флагом `Secure` агент supertest по `http://localhost` не отправит: в тестовой среде либо HTTPS, либо флаг `Secure` выключается конфигурацией только для test-окружения (согласовать вместе с ADR транспорта сессии). Тестовые учётные данные — синтетические, лежат в fixtures проекта; реальные пароли и данные клиентов в тестах запрещены.

## Внутрипроцессные интеграционные тесты (при необходимости)

Когда нужно подменить провайдер (например, заставить адаптер фискализации упасть), используйте `Test.createTestingModule({ imports: [AppModule] }).overrideProvider(FISCAL_REGISTRAR).useValue(...)` + `app.getHttpServer()` в supertest. Такие тесты импортируют код api, поэтому живут в `apps/api` (отдельный jest-конфиг/target, требующий PostgreSQL — название таргета **согласовать** с командой). Предпочтительно же вызывать сбой через данные (см. кейс атомарности в `nestjs-testing-integration-patterns.md`).
