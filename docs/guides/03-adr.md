# Шаг 3 вручную: ADR

Результат: файлы `docs/architecture/adr/NNNN-<слаг>.md` по `templates/adr-template.md`.

1. Номер = максимальный существующий + 1, с нулями до 4 знаков (первый — 0001).
2. Обязательный минимум на этапе проектирования:
   - **ADR-0001 — выбор стека**: краткая выжимка из stack.md с реальными причинами;
   - **ADR-0002 — стиль архитектуры**: монолит / модульный монолит / микросервисы — с
     аргументами именно для вашего проекта (команда, сроки, нагрузка), не «потому что модно».
     ADR-0002 — обязателен для Full-трека; для Lite достаточно ADR-0001.
3. В каждом ADR минимум 2 рассмотренных варианта и — обязательно — отрицательные
   последствия выбора. «Минусов нет» не бывает.
4. Новый ADR создаётся в статусе `proposed` — это ещё не решение, реализовывать нельзя.
   ADR принимает архитектор проекта (ревью — docs/architecture/APPROVAL.md); после принятия
   статус меняется на `accepted`. Новая технология, библиотека уровня фреймворка, интеграция
   или компонент вводятся именно так — ADR команды (см. ADR-0011).
5. ADR пишутся не только на старте: любое новое архитектурное решение по ходу разработки —
   новый ADR, сначала запись — потом код.
