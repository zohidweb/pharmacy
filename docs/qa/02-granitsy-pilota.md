# Границы пилота и известные ограничения

Что входит в MVP для облачного пилота, что сознательно не сделано и какое поведение задумано так. Пункты из этого
документа **не заводятся как дефекты**. Если поведение расходится с описанным здесь — это дефект.

Состояние: `main` на 2026-10-28 (после PR #86, мелких доработок перед пилотом G1–G6, истории смен, выгрузки в Excel, ценников и QR на чеке). Решения — в ADR (`docs/architecture/adr/`),
APPROVAL.md и спецификациях (`docs/superpowers/specs/`).

## 1. Объём пилота

| Входит | Не входит |
|---|---|
| Облачные аптеки и склады: работа через браузер, при обрыве связи касса продаёт из буфера | Офлайн-точки (своя копия системы на ПК аптеки) |
| Касса и смены, возвраты покупателям, весь склад, закупки и долги поставщикам, каталог, цены и скидки, отчёты, кабинет владельца | Выгрузка в 1С |
| Админка оператора: сети, операторы, счета и платежи, услуги, дашборд, статистика, уведомления, объявления | Лицензии и версии офлайн-точек в админке |
| Загрузка каталога, начальных остатков и поставщиков из `.xlsx` / `.csv`; выгрузка в Excel (`.xlsx`) — отчёты, журнал действий, остатки, статистика админки | |

## 2. Не сделано (заглушки и скрытые разделы)

| Что | Как выглядит | Почему |
|---|---|---|
| **Фискализация** | На чеке «Фискальные реквизиты — после выбора ККМ»; чек в ККМ не отправляется | Вендор ККМ не выбран (stack.md, вопрос 9). На пилоте аптека пробивает фискальный чек своей ККМ |
| **Эквайринг** | «Карта», «QR», «NFC» — только отметка способа оплаты; сверка с банковским терминалом вручную в смене | Интеграции с банком нет по решению проекта |
| Офлайн-точки | Пункта «Офлайн-точки» в web и раздела «Офлайн» в админке нет; контур `/api/v1/sync/*` выключен | Вне пилота (ADR-0014, решение 7.4 ревью безопасности) |
| Выгрузка в 1С | Кнопки нет | Вне пилота |
| Фото и скан рецепта ПКУ | Данные рецепта вводятся, файл не прикрепляется | Нужен ADR о хранении файлов |
| Общий справочник препаратов платформы | Подсказки из справочника при заведении товара пусты; аналоги по МНН ищутся только в каталоге сети | Справочник не наполнен |
| Агент печати | Печать — через диалог браузера, ширина ленты 80 или 58 мм | Отдельный компонент, вне MVP |
| Отправка заказа поставщику | Заказ печатается или сохраняется в PDF из окна заказа («Печать») и передаётся поставщику вне системы | Нет канала отправки в закрытом списке интеграций |
| Печать претензии по возврату поставщику | Нет | Отложено |
| Вход оператора «от имени» владельца | Нет | ADR-0008: не реализуется, решение пересматривается |
| Регистрация сети самой аптекой | Нет, сеть заводит оператор | Публичная регистрация вне MVP |
| Оплата счетов платформы онлайн | Оператор отмечает платёж вручную | Решение 2026-10-01 |
| Автотесты бизнес-логики | Есть для входа, изоляции сетей и части кассы; для склада, закупок, возвратов, биллинга, отчётов — нет | Тесты отложены до MVP — QA первая проверка этой логики |

## 3. Задуманное поведение (не дефекты)

**Деньги и цены**
- Только сомони (TJS), без валют и курсов (ADR-0016).
- Розничная цена точки появляется из начальных остатков (столбец «Розничная цена») или по наценке при первом приходе.
  Без цены касса товар не продаёт: «Нет цены — касса не продаст».
- Цена выше предельной сохраняется только после явного подтверждения (не запрет); ниже закупочной — предупреждение.
- Себестоимость штуки при делении упаковки округляется вверх; розница штуки — вверх до шага сети (10 дирамов).
- Скидка при частичном возврате не пересчитывается по порогам: к возврату — цена товара минус его доля скидки чека.
- Чек онлайн с ценой или скидкой не по правилам точки отклоняется; из буфера — уходит в карантин, принимает
  заведующий с правами на цены (ADR-0015, поправка 2026-10-23).

**Касса и склад**
- Остатки не хранятся — считаются из движений по партиям; партия при продаже — по FEFO (раньше истекает — раньше
  продаётся). Просроченная партия заблокирована без обхода.
- Возвраты покупателей — только при связи; при обрыве экран возвратов сообщает, что возвраты недоступны.
- При обрыве связи касса продаёт из буфера: не дольше 24 ч и 500 операций, ПКУ — 8 ч и 20 чеков (параметры сети);
  буфер досылается сам после связи, ни одна операция не теряется молча.
- Отмена проведения документа заблокирована, если по его партиям уже были движения.
- Ввод документов задним числом — не глубже 30 дней.
- Отложенные чеки видны всем кассирам точки и удаляются при закрытии смены.
- История смен — «Отчёты → Смены» (владелец, заведующий, бухгалтер; кассир её не видит): смены точек охвата, карточка
  смены, повторная печать Z-отчёта.
- Смену сломанной или недоступной кассы заведующий закрывает с другого компьютера (кнопка в карточке смены; право
  «Закрытие смены с другого компьютера» есть у шаблона «Заведующий точкой», у ролей, созданных раньше, его выдаёт
  владелец). Нужны пересчитанные наличные и причина, пароль вводится заново. Продажи, которые касса не успела
  отправить, приходят в эту смену позже: они учитываются в остатках, видны в карточке смены «после закрытия» и в
  Z-отчёт не входят. Касса после возвращения связи сообщает, что смена закрыта, и предлагает открыть новую.
- Отвязывать кассу после такого закрытия — только если компьютер не вернётся: отвязанная касса уже не досылает
  неотправленные продажи.

**Вход и безопасность**
- Вход по паролю: после 5 неудачных попыток по одному логину, телефону или e-mail вход по нему блокируется на 15 минут
  (повторно в течение суток — на час). Кроме того, у учётной записи сотрудника общий лимит — 10 неудачных попыток за
  сутки по всем его идентификаторам вместе с подтверждением и сменой пароля; затем блокировка на 1 ч, повторная — на
  6 ч (ADR-0008, поправка 2026-10-23). Несуществующий логин после 10 попыток отвечает так же — по ответу не понять,
  есть ли такой логин.
- Блокировку снимает новый пароль от заведующего или владельца, у владельца — новая активация. Каждая блокировка —
  запись «Вход заблокирован после неверных паролей» в журнале действий сети (у оператора — в журнале админки), отказы
  во время блокировки не пишутся. Владелец и другие сотрудники с охватом «вся сеть» и правом менять сотрудников
  получают уведомление «вход заблокирован»; заведующий точкой его не видит. Уведомление выключается в настройках сети.
- Частые пароли (`Password1`, `Qwerty123`, `Apteka2024`, `P@ssw0rd1`, клавиатурные ряды, один повторённый символ) не
  принимаются при задании пароля; заданные раньше продолжают работать.
- PIN кассира — не меньше 4 цифр, простые (`1111`, `1234`, `0000`) запрещены; после 10 неудачных попыток за 15 минут
  PIN на терминале блокируется (настройка развёртывания). В документе отступлений от ТЗ указано «3 попытки» —
  расхождение передано архитектору.
- Кассир входит по PIN только на привязанной кассе; касса привязывается в браузере, другой профиль браузера — другое
  устройство.
- Сотрудники, роли и терминалы при изменении требуют повторного ввода пароля, если он вводился давно.
- Оператор видит число и сумму чеков точек (статистика, карточка точки) и их активность; товаров, строк чеков и
  сотрудников сети — нет, журнала действий сети в админке тоже нет.
- Данные рецептов ПКУ хранятся 90 дней (настройка сети) и удаляются ежечасно; журнал ПКУ не удаляется.

**Ценники и QR на чеке** (ADR-0022)
- Ценник — из карточки товара («Печать ценника», нужно право на просмотр цен) или из остатков («Ценники» у выбранных
  строк). На нём название, «производитель · страна · уп. N шт.», штрихкод и цена упаковки выбранной точки; цены штуки
  нет. Товара без цены в точке ценник не печатается: в остатках такие строки пропускаются с примечанием.
- Размеры — 58 × 40 и 40 × 30 мм, каждый ценник — отдельная страница. В драйвере принтера этикеток размер бумаги
  должен совпадать с выбранным размером ценника.
- Штрихкод — по значению штрихкода товара: EAN-13, EAN-8, UPC-A (печатается как EAN-13 с нулём впереди) или Code 128.
  Кириллица, слишком длинный код или товар без штрихкода — ценник без штрихов, код (если есть) — текстом.
- На чеке продажи под подвалом — QR с id чека; экран возврата находит чек по его скану. 1D-сканер QR не читает — номер
  или код из 8 знаков вводят вручную.
- Читаемость штрихкода и QR на первой печати проверить сканером точки: ширину штриха и размер QR калибруют под принтер.

**Выгрузка в Excel** (ADR-0015, поправка 2026-10-27)
- Файл `.xlsx` строится в браузере из того, что показывает экран, с теми же правами и на языке интерфейса; сервер файлов
  не хранит. Кнопки видны с правами: отчёты — `reports:export`, журнал действий — `audit:export` (у заведующего по
  шаблону его нет), остатки — `inventory:export`; статистика админки — у всех операторов.
- Отчёты — все девять видов, включая журнал и сводку ПКУ; сверху — название, период, точка, время и примечания экрана.
  Строка «Итого» — как на экране (у «Движения товара» и ПКУ её нет), после одной пустой строки: сортировка из шапки её
  не трогает. У отчётов со штуками последняя колонка — «Штук в упаковке». Остатки: весь список по фильтрам экрана,
  «Надо заказать» или выбранные строки страницы.
- Журнал действий и остатки выгружаются одним запросом, не больше 20 000 строк. Больше — файла нет, экран просит сузить
  период или фильтр. Таких выгрузок — не больше 10 в минуту с одного экрана на сотрудника, дальше — «слишком много
  запросов», через минуту снова можно.
- В файле статистики админки строка компании жирная и равна сумме её точек: при сложении колонки её не берут вместе с
  точками.
- Деньги — числами в сомони с двумя знаками; штуки и упаковки — целыми числами (единица в шапке); штрихкоды, номера
  партий и документов — текстом, нули впереди сохраняются; время — по Душанбе. Текст, начинающийся с `=`, не
  вычисляется.
- Файл журнала ПКУ содержит данные рецептов, и срок их хранения в системе на файл не действует: за файл отвечает сеть.
- Сама выгрузка в журнал действий не пишется.

**Админка**
- В выпадающих списках «Записать платёж» и «Статистика» показываются первые 100 сетей или счетов.

## 4. Ожидает решения заказчика

Не дефекты, но может измениться после ответа заказчика (`docs/architecture/reviews/2026-10-01-tz-deviations-for-customer.md`,
stack.md, раздел 6):
- отказ от валют и курсов НБТ;
- урезанный функционал офлайн-точек;
- пересчёт скидки при частичном возврате;
- оператор без денежных сумм;
- перечень препаратов ПКУ и обязательных полей рецепта;
- законодательные ограничения возврата лекарств;
- выбор вендора ККМ.

## 5. Как заводить дефекты

- Окружение (вариант А/Б инструкции, браузер), сеть, точка, роль, шаги, ожидаемый и фактический результат.
- Номер документа или чека и время — по ним находится запись в «Журнале действий».
- Ошибка с экрана: текст и, если есть, `correlationId` из ответа API (вкладка Network браузера).
- Переводы на таджикский носителем ещё не вычитаны — ошибки перевода отдельной категорией.
