# ADR-0005: Утверждение Docker (категория «Контейнеризация» — на утверждении)

- **Статус:** accepted
- **Дата:** 2026-09-29
- **Авторы:** Zohid Saidov (z.saidov@eskhata.com), команда проекта Pharmacy

## Контекст

ТЗ «Административный продукт» v2.1 (раздел 4) прямо требует: автономная (офлайн) точка —
это отдельно устанавливаемая копия клиентского продукта на одном ПК точки, поставляемая как
**Docker-образ** с автозапуском (Windows 10/11 + WSL2 или Linux, от 8 ГБ ОЗУ), включая
вариант установки с флеш-накопителя без интернета. Категория «Контейнеризация» в техрадаре
v1.3 — «На утверждении»: использовать нельзя до решения Архитектурного комитета; подача
запроса по EXCEPTIONS.md ускоряет утверждение всей категории. Функционал нужен к волне 3
первого релиза; контейнерный деплой облачной части также желателен, но не обязателен.

## Рассмотренные варианты

1. **Docker (Docker Engine / Docker Desktop + docker compose)** — де-факто стандарт;
   заложен в ТЗ и в требования к ПК точек; воспроизводимая поставка «БД + приложение»
   одним образом; работает на Windows (WSL2) и Linux. Минус: категория радара ещё
   не утверждена; Docker Desktop на Windows имеет лицензионные условия для коммерческого
   использования (проверить; альтернатива — Docker Engine в WSL2 напрямую).
2. **Нативная установка без контейнеров** (Node.js + PostgreSQL как службы Windows/Linux
   на ПК точки) — не требует решения по радару, но: хрупкая установка и обновление на
   разношёрстных ПК аптек, ручная настройка каждой машины, сложный откат версий; противоречит
   тексту ТЗ и делает нереалистичным «установка ≤ 30 минут» (критерий приёмки W3-01).
3. **Подман/иные контейнерные движки (Podman и т.п.)** — те же выгоды, той же неутверждённой
   категории; меньше распространён на Windows; не даёт преимуществ перед Docker.

## Решение

Предлагаем утвердить Docker (Engine + compose) для: (а) дистрибутива офлайн-точки —
обязательное требование ТЗ, волна 3; (б) опционально — контейнерного деплоя облачной части.
Вариант без контейнеров отклонён как противоречащий ТЗ и операционно нереалистичный для
десятков независимых ПК в аптеках.

## Последствия

- Положительные: воспроизводимая поставка и обновление офлайн-точек; идентичность
  окружений (точка/облако/разработка); соответствие критериям приёмки W3-01.
- **Отрицательные (обязательно):**
  - требование к ПК точек: 64-бит ОС с WSL2/Docker и 8+ ГБ ОЗУ — часть машин заказчиков
    может потребовать апгрейда;
  - лицензирование Docker Desktop для Windows в коммерческой среде — нужна проверка
    и, возможно, переход на Docker Engine в WSL2;
  - у банка нет утверждённых практик эксплуатации контейнеров — реестр образов,
    сканирование уязвимостей, правила обновления базовых образов придётся определить
    в рамках этого решения;
  - обновление офлайн-точек остаётся ручным (через удалённый доступ, из ТЗ) — Docker
    упрощает, но не автоматизирует его.

## Только для исключений из техрадара

- Альтернативы из радара и почему не подходят: в категории «Контейнеризация» утверждённых
  технологий нет — категория целиком «На утверждении»; запрос подаётся в том числе для
  ускорения утверждения категории (см. RADAR.md, «Категории на утверждении»).
- **Апрув Архитектурного комитета:** Zohid Saidov, 2026-09-29 (см. docs/architecture/APPROVAL.md)
- **Апрув ИБ** (для security-категорий): не требуется напрямую; практики сканирования
  образов согласовать с ИБ при утверждении категории
- Исход по EXCEPTIONS.md: одноразовое (для этого проекта; утверждение категории — при
  пересмотре радара)
