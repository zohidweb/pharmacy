# Сервис уведомлений клиентов (эталонный пример)

Полностью заполненный пример по `ai-project-start`, показывающий, как должны выглядеть
артефакты проектирования после прохождения всех шагов (`/01-select-stack` → `/02-c4-model` →
`/03-adr` → Ревью архитектуры → `/04-generate-claude-md`). Ни одна строчка кода в этом примере
не пишется — здесь только артефакты проектирования, как и требует сам шаблон на этой стадии.

Фиктивный проект: сервис отправляет клиентам банка СМС/push-уведомления о движениях по счёту
(списание, зачисление, отказ операции). Full-траектория, Tier 2, обрабатывает персональные
данные (флаг апрува ИБ: ДА). Интеграции — АБС (источник событий) и внешний СМС-шлюз.

| Файл | Что показывает |

| `docs/architecture/stack.md` | все 6 секций шаблона `templates/stack-decision-template.md`, заполненные для этого проекта |
| `docs/architecture/c4/context.md` | C4 Context — система, роли, внешние системы |
| `docs/architecture/c4/container.md` | C4 Container — из чего состоит сервис |
| `docs/architecture/c4/deployment.md` | таблица размещения по контурам сети |
| `docs/architecture/adr/0001-выбор-стека.md` | ADR на выбор стека |
| `docs/architecture/adr/0002-стиль-архитектуры.md` | ADR на стиль архитектуры (модульный монолит) |
| `docs/architecture/adr/0003-исключение-rabbitmq.md` | пример оформленного исключения из техрадара (RabbitMQ, одноразовое) |
| `docs/architecture/APPROVAL.md` | результат ревью архитектуры в формате из README шаблона |
| `CLAUDE.example.md` | результат `/04-generate-claude-md` — шаблон `templates/project-claude-md.template` с заполненными плейсхолдерами под этот стек |

Сомневаетесь, как оформить свой артефакт, — сверяйтесь с соответствующим файлом здесь.

Файл называется `CLAUDE.example.md`, а не `CLAUDE.md`, чтобы Claude Code не подхватывал его
как инструкции при работе внутри `ai-project-start/`; в реальном проекте `/04` создаст
настоящий `CLAUDE.md` в корне проекта.
