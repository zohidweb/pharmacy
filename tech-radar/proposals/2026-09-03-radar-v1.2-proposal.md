# Проект решений по техрадару v1.2

**Кому:** Архитектурный комитет Банка Эсхата (+ ИБ по security-категориям)
**От:** команда ai-project-start
**Дата:** 2026-09-03
**Статус:** проект — ни одна позиция не действует до решения комитета

## Зачем этот документ

Тестирование шаблона ai-project-start (10 независимых проверок: симуляции веб-, мобильной и PHP-команд, анализ полноты радара по backend/frontend/данным) показало: радар v1.1 утверждает только «низовой» стек (язык, БД, кэш, API-стиль). Для реального проекта банковского уровня почти вся инфраструктурная обвязка находится в статусе «На утверждении» — команда упирается в 6–9 процедур исключения с SLA 3 дня каждая, последовательно. Радар из ускорителя превращается в узкое горло.

Документ сводит кандидатов в один список для **пакетного** утверждения. Формат: колонка «Решение комитета» заполняется на заседании (Утверждено / Приоритет / Отклонено / Отложено).

## Как читать приоритеты

- **П1 — блокирует каждый проект**: без этого нельзя заполнить stack.md или дойти до деплоя.
- **П2 — блокирует первую же команду конкретного стека**: без этого команда делает нерегулируемый выбор.
- **П3 — важно, но не блокирует старт**.

## П3. Процессные решения (не технологии)

### 3.1. Push-уведомления: правило payload-минимизации ⚠️ структурное противоречие

Нативный push не существует без инфраструктуры Google (FCM) и Apple (APNs) — а секция «Запрещено» блокирует «отправку клиентских данных во внешние SaaS». Сейчас каждый мобильный проект банка либо блокируется, либо тихо нарушает политику.

**Проект решения:** утвердить категорию «Платформенные push-сервисы (FCM/APNs)» со статусом «Утверждено с ограничением»: в push передаётся только идентификатор события / silent-триггер; содержимое (суммы, реквизиты, имена) всегда подтягивается приложением по защищённому API после получения; ПДн и банковская тайна в теле push запрещены. Требуется совместный апрув комитета и ИБ.
