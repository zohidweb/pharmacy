# Процедура исключения из техрадара

Нужна технология, которой нет в радаре со статусом «Утверждено»? Порядок:

1. **Команда пишет ADR-обоснование** по `templates/adr-template.md` в своём проекте
   (`docs/architecture/adr/NNNN-...md`). Обязательно заполнить:
   - какие альтернативы из радара рассмотрены и почему не подходят;
   - риски выбранной технологии (поддержка, безопасность, компетенции);
   - негативные последствия.
2. **Подача запроса**: issue или pull request в центральный репозиторий ai-project-start
   с приложенным ADR. Тема: `[Исключение] <технология> — <проект>`.
3. **Апрув**:
   - обычные категории — Архитектурный комитет;
   - security-категории (аутентификация, криптография, секреты, работа с клиентскими
     данными) — двойной апрув: Архитектурный комитет + ИБ.
   Имена и даты апрувов вписываются в поля ADR.
4. **SLA: 3 рабочих дня.** Просрочка или несогласие — эскалация на архитектурный комитет / CTO.
5. **Исходы**:
   - `approve (одноразовое)` — можно использовать только в этом проекте;
   - `approve (кандидат в радар)` — технология выносится на ближайший пересмотр радара;
   - `reject` — с обязательным указанием альтернативы из радара.
6. **Регистрация**: каждое решение вносится архитектором (владельцем радара) в реестр исключений
   (`GOVERNANCE.md`). 2+ одинаковых запроса — автоматический триггер пересмотра радара.

До получения апрува использовать технологию нельзя — в том числе «временно» и «для прототипа».
