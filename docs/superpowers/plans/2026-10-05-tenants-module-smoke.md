# Модуль «сети» — ручная проверка

Автотестов для модуля нет: решение 2026-10-05 откладывает их до готовности MVP, пробелы перечислены
в разделе «Долг по тестам» файла `2026-10-05-tenants-module.md`. Этот сценарий проверяет вручную
сквозной путь и Review Focus 1–5. Все данные синтетические, домен `pharmacy.test`. Тела запросов с
кириллицей отправляйте из файла (`--data-binary @body.json`): curl в Windows портит кириллицу в
аргументах.

## Подготовка

1. `npm run dev:deps`.
2. Кластер dev создан до 2026-10-05? Тогда один раз добавьте роль `pharmacy_provisioner`: команда в
   шапке `docker/postgres/initdb/03-provisioner-role.sql`.
3. `npx nx run api:migrate`.
4. Оператор с паролем: `create-operator.mjs`, затем `POST /operator/activations` (сценарий части 3).

## Через админку (рекомендуется)

```bash
npx nx serve api
npx nx run admin:dev-api      # второй терминал; админка на http://localhost:4300, режим partial
```

1. Вход оператора, затем «Компании»: список сетей идёт из API (блоки биллинга пустые).
2. «Создать компанию»: заполните сеть и владельца. Логин — латиница, не телефон и не почта.
   Ожидание: экран с кодом активации, код группами по 4 символа, «показывается один раз».
3. Повторите с тем же логином, телефоном или ИНН. Ожидание: ошибка у соответствующего поля
   (`409 *_taken`), сеть не создана.
4. Владелец входит в web (`npx nx dev web` или curl, `POST /api/v1/activations` с кодом) и задаёт
   пароль. Вход и `/me` → 200.
5. В карточке сети нажмите «Заблокировать» и укажите причину. Ожидание: следующий запрос владельца →
   401, новый вход → 401, в карточке видны оператор и причина.
6. «Разблокировать» → вход владельца снова 201.
7. «Новый код владельцу» → новый код. Старый код → `401 invalid_code`, новый → 204.

## Review Focus

1. **Функции не меняют существующую сеть.** В БД ролью `pharmacy_platform` вызовите
   `select pharmacy.provision_tenant(<id существующей сети>, …)`. Ожидание: ошибка ключа, данные сети
   прежние. `issue_owner_code` меняет только `one_time_code_hash` и `one_time_code_expires_at`
   владельца.
2. **Платформа не читает тенантные таблицы.** `select * from pharmacy.employees` ролью
   `pharmacy_platform` → `42501`. `npx nx run api:integration` (каталог-тест) зелёный.
3. **Блокировка гаснет даже без флага.** Заблокируйте сеть, затем удалите флаг в Redis
   (`DEL tenant-blocked:<tid>`) и сбросьте кэш версии (`DEL pv:<tid>:<eid>`). Следующий запрос
   владельца → 401 через перечитывание статуса сети.
4. **Дубли** — шаг 3 выше. В карточке ничего лишнего не появилось.
5. **Режимы админки.** `npx nx dev admin` (все запросы в моки) работает, как раньше, вкладки биллинга
   видны. В `admin:dev-api` вкладок биллинга нет, сети идут из API.
