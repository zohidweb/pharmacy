# ADR-0003: Исключение из техрадара — NestJS как бэкенд-фреймворк

- **Статус:** accepted
- **Дата:** 2026-09-29
- **Авторы:** Zohid Saidov (z.saidov@eskhata.com), команда проекта Pharmacy

## Контекст

Проект Pharmacy — мультитенантная SaaS-платформа автоматизации аптечных сетей (Full, Tier 2,
персональные данные, SLA 99,5% в рабочие часы; см. docs/architecture/stack.md). Жёсткий срок —
запуск первой волны MVP до конца 2026 года. Команда разработки владеет стеком
NestJS / Next.js / Angular (TypeScript) и не владеет ни C#, ни PHP. Техрадар банка (v1.3)
в категории Backend содержит только C# (.NET LTS) и PHP; Node.js-технологий в радаре нет.

## Рассмотренные варианты

1. **C# (.NET, актуальная LTS)** — из радара, «Утверждено». Плюсы: зрелая экосистема,
   поддержка банка, скиллы `dotnet-dev` уже описаны в стандартах. Минусы: у команды нулевые
   компетенции; обучение с нуля при сроке «до конца года» — прямой риск срыва срока и
   низкого качества первого продуктового кода.
2. **PHP (актуальная версия)** — из радара, «Утверждено». Плюсы/минусы аналогичны: компетенций
   в команде нет; экосистема слабее ложится на задачу (очередь синхронизации офлайн-точек,
   строгая типизация доменной модели партий/движений).
3. **NestJS (Node.js + TypeScript)** — вне радара. Плюсы: команда владеет; модульная
   архитектура фреймворка ложится на модульный монолит; единый язык TypeScript и общие
   типы/DTO с обоими фронтендами в Nx-монорепо (меньше расхождений контрактов API);
   зрелая экосистема (ORM, валидация, OpenAPI). Минусы: вне радара, в банке нет других
   Node.js-проектов — нет накопленной экспертизы сопровождения.

## Решение

Предлагаем утвердить NestJS (актуальная поддерживаемая версия, Node.js LTS, TypeScript)
как бэкенд-фреймворк проекта Pharmacy. Определяющие факторы: компетенции команды при
фиксированном сроке до конца 2026 года и сквозной TypeScript от БД-моделей до UI в одном
Nx-монорепо. Альтернативы из радара требуют переобучения команды и делают срок нереалистичным.

## Последствия

- Положительные: команда стартует немедленно; общие типы API между `apps/api`, `apps/web`,
  `apps/admin`; один язык — ниже порог взаимозаменяемости внутри команды.
- **Отрицательные (обязательно):**
  - прецедент Node.js-бэкенда в банке: нет существующей экспертизы сопровождения, мониторинга
    и security-ревью Node-стека — первую экспертизу придётся выращивать на этом проекте;
  - зависимость от npm-экосистемы (supply-chain-риски) — потребуется lock-файлы, аудит
    зависимостей и внутренние правила обновлений;
  - однопоточная модель Node.js требует дисциплины при CPU-тяжёлых операциях (отчёты,
    генерация PDF-счетов) — выносить в воркеры;
  - если комитет утвердит исключение как «одноразовое», переиспользовать стек в следующих
    проектах без нового запроса нельзя.

## Только для исключений из техрадара

- Альтернативы из радара и почему не подходят: C# (.NET LTS) и PHP — «Утверждено», но
  команда ими не владеет; при сроке до конца 2026 переобучение срывает срок и повышает риск
  дефектов в продуктовой системе Tier 2. Подробнее — раздел «Рассмотренные варианты».
- **Апрув Архитектурного комитета:** Zohid Saidov, 2026-09-29 (см. docs/architecture/APPROVAL.md)
- **Апрув ИБ** (для security-категорий): не требуется (категория Backend не security);
  аутентификация согласуется с ИБ отдельно (см. stack.md, раздел 2)
- Исход по EXCEPTIONS.md: одноразовое (для этого проекта)
