# Админка: карточка точки и журнал сети на API

- **Дата:** 2026-10-23
- **Статус:** черновик — ждёт утверждения архитектора
- **Основание:** аудит маршрутов админки 2026-10-23. Из 79 маршрутов 65 обслуживает `apps/api`. Три из
  оставшихся 14 нужны облачному пилоту: карточка точки, правка точки, журнал сети. Без них оператор на стенде QA и в
  prod получает ошибку на странице точки и на вкладке «Журнал» страницы сети. Остальные 11 — офлайн-точки, их на
  пилоте нет; их пункты меню прячет ветка `fix/qa-blockers-terminal-offline`.

## 1. Граница: ADR-0013 §5 не меняется

Платформа не читает сырые тенантные таблицы. Исключения — реестр `stores` (часть колонок) и витрины
`tenant-export`. Видеть или менять данные сети оператор может только через вход «от имени», а его нет (ADR-0008).
Поэтому все три маршрута строятся из того, что платформе уже доступно: реестр, витрины, платформенные таблицы. Одно
исключение — колонка `address` (решение A2), она требует поправки ADR-0013.

## 2. Решения

| № | Решение |
|---|---|
| A1 | `GET /operator/stores/{id}` (право `tenants:view`) — в модуле `app/platform/tenants`, рядом со списком точек сети. Данные — только из того, что платформе доступно (A2–A5). Точки нет или она чужая для реестра — 404 `store_not_found`. |
| A2 | **Адрес точки — в реестр.** Платформе открывается колонка `stores.address` (`grant select (address) … to pharmacy_platform`). Адрес аптеки — данные организации, а не ПДн, как `name` и `kind` (поправка ADR-0013 2026-10-19). Тот же адрес получает список точек сети `GET /operator/tenants/{id}/stores` (сейчас там пустая строка). **Поправка ADR-0013** — утверждается вместе со спецификацией. |
| A3 | Продажи точки за текущий месяц (чеки, сумма) — из витрины `store_sales_daily` по бизнес-датам месяца (Душанбе). Перед чтением — тот же пересчёт сети, что у её статистики, если пересчёт старше 5 минут (поправка ADR-0013 2026-10-19, п. 2). Пересчёт сейчас внутренний у `app/platform/stats`: модуль отдаёт новый экспорт (продажи точки за месяц с пересчётом), `app/platform/tenants` его вызывает; цикла нет — `stats` не зависит от `tenants`. В ответе `asOf` — время пересчёта. |
| A4 | **Без ПДн и данных, которых нет в витринах.** Из `StoreDetails` убираются `managerName`, `managerPhone` (данные сотрудника — тенантная таблица) и `cashiers` (витрина кассиров — по сети, не по точке; число кассиров сети уже есть на вкладке статистики). |
| A5 | Офлайн-поля карточки — пустые, пока нет офлайн-части админки. `license` — `null`, `syncHistory` и `syncQueue` — пустые, `installedVersion` и `latestVersion` — `null`, `licenseValidUntil` и `lastSyncAt` — `null`, как в списке точек сети сейчас. Офлайн-точка показывает режим; ключ и синхронизация появятся с офлайн-частью админки. |
| A6 | **Правки точки оператором нет.** `PATCH /operator/stores/{id}` не реализуется: точки создаёт, меняет и закрывает владелец сети (ADR-0013, `stores` — тенантная таблица; правка оператора — только через «от имени» или новый ADR). Маршрут и мутация удаляются из админки. Форма параметров становится карточкой только для чтения с подсказкой «Меняет владелец сети в кабинете». |
| A7 | **Вкладка «Журнал» страницы сети — журнал операторов по этой сети:** блокировки, услуги, счета, платежи, скидки, коды владельца. Данные — существующий `GET /operator/operator-audit-log?tenantId=` (право `platform:view`, `platform_audit_log`). Тексты событий — из сущности `operator-audit` админки, как на странице «Журнал операторов». Действия сотрудников сети оператор не видит: их журнал — у владельца в кабинете (web, «Журнал действий»). Маршрут `tenants.audit` и DTO `AuditEntry` удаляются. Вкладка называется «Действия операторов». |
| A8 | Моки админки (`NEXT_PUBLIC_API_MOCKS=true`) следуют новым DTO: карточка без менеджера и кассиров, журнал сети — из моков журнала операторов. `stores.get` добавляется в `REAL_API_ROUTES`. |
| A9 | Офлайн-маршруты (11) — вне объёма: лицензии, установки, версии, настройки лицензии, запрос синхронизации, перевод в облако, офлайн-параметры. Код экранов остаётся для полных моков. |
| A10 | Тесты отложены до MVP (решение 2026-10-05): новых автотестов нет, существующие наборы остаются зелёными; долг — в описании PR. Проверка — вживую: `admin:dev-api` и стенд `pharmacy-test` через прокси. |

## 3. Контракт

```ts
// libs/shared/dto/src/lib/platform-tenants.ts
export interface StoreDetails extends StoreSummary {
  tenantName: string;
  /** Date-only: created_at of the store. */
  connectedOn: string;
  /** Receipts of the current month (Asia/Dushanbe) from the marts. */
  monthReceipts: number;
  /** The time of the last refresh of the marts of the network; null — never refreshed. */
  asOf: string | null;
  /** Offline part of the admin — not in the pilot: null / empty (A5). */
  installedVersion: string | null;
  latestVersion: string | null;
  license: StoreLicense | null;
  syncHistory: SyncHistoryEntry[];
  syncQueue: Array<{ kind: SyncQueueKind; operations: number }>;
}
// removed: managerName, managerPhone, cashiers; UpdateStoreRequest; AuditEntry
```

`StoreSummary.monthSalesMinor` карточки — из витрины (A3); в списке точек сети он остаётся как сейчас.

## 4. Не входит

- Вход «от имени» (ADR-0008) — единственный путь к данным сети для оператора; решение пересматривается отдельно.
- Офлайн-часть админки (A9).
- Статистика по точке за произвольный период — только текущий месяц, как на карточке сейчас.
