# web — клиентский продукт (касса, склад, кабинет владельца)

Next.js static export (ADR-0004), FSD (ADR-0017), UI-кит `@pharmacy/ui` (ADR-0007),
данные — TanStack Query, формы — React Hook Form + zod, i18n — use-intl (ADR-0015).
Права — каталог `@pharmacy/shared-domain` (ADR-0018): интерфейс только скрывает и отключает
элементы, решает сервер.

```
npx nx dev web      # http://localhost:4200, API на моках
npx nx test web
npx nx fsd web
```

## Моки API

Пока `apps/api` не реализует эндпоинты клиентского продукта, `nx dev web` запускается с
`NEXT_PUBLIC_API_MOCKS=true` (таргет `dev` в `package.json`): запросы обслуживает
`src/shared/api/mocks` по тем же маршрутам, правам и кодам ошибок, что и будущий API (контракты —
`libs/shared/dto`, `tenant-*.ts`). Сборки (`nx build web`) флаг не получают: код моков в `out/`
не попадает.

Синтетические демо-данные — `src/shared/api/mocks/fixtures.ts`: сеть «Шифо», 4 точки
(точка №4 — офлайн), пароль всех демо-сотрудников — `Demo1234`.

Каталог кассы (10 товаров), открытая смена №218 на «Аптеке №3», отложенные чеки и чеки для возврата

## Касса и буфер перебоев (ADR-0015)

- Черновик чека — Zustand (`features/pos/model`), правила чека — чистые функции `receipt.ts`
  (FEFO, поштучная продажа, скидка по порогу из `@pharmacy/shared-domain`, смешанная оплата и сдача).
  Черновик зеркалируется в IndexedDB и переживает F5.
- `shared/lib/offline-queue` — outbox-first: продажа и операции смены (открытие, внесение/изъятие,
  закрытие) пишутся в IndexedDB одной транзакцией с черновиком, затем отправляются строго по одной
  (FIFO, Web Locks) с `Idempotency-Key` = UUIDv7 операции. Сетевая ошибка/5xx — повтор с задержкой
  до 60 с; 401/403 — пауза; 409/4xx — карантин «Требует разбора» на экране смены (не удаляется,
  отправляется снова с тем же ключом). Счётчик очереди всегда виден в шапке.
- Снимок каталога точки — в IndexedDB (`catalog`), с сервера приходят только изменения после версии;
  скан и поиск работают при перебое. Сканер — `shared/lib/scanner` (по `event.code`).
- Отложенные чеки, возвраты, склад — только онлайн (явное сообщение в интерфейсе).
- Связь определяет `shared/api/connectivity.ts` (ответы API + пинг `/health`), не `navigator.onLine`.

## Склад

Остатки не хранятся: в моках — точка → партия → штуки и журнал движений (`mocks/db-stock.ts`); касса
и склад видят одни остатки. Проведение документа пишет движения, отмена проведения проверяет
последующие движения по партиям (`documents.unpostCheck`) и без обхода блокируется. Приход —
один поставщик и одна накладная, розница предлагается по наценке (`suggestRetail`), себестоимость
штуки — с округлением вверх (`pieceCost`). Перемещение меняет остаток получателя только после
приёмки; недостача разбирается списанием или досылом. Склад офлайн-точки в облаке — только
просмотр (ADR-0014), закупочные цены — только с правом `finance:view-cost`. Excel, ценники и печать
претензии показаны неактивными до выбора библиотек.

## Закупки, каталог, цены

- Заказы поставщикам (`/orders`): черновик → подтверждён → частично поставлен → закрыт. «Заполнить
  по дефициту» берёт товары ниже минимума точки: до минимума плюс расход за 30 дней
  (`deficitQuantity`). «Оформить приход» открывает приход (`widgets/goods-receipt-editor`) с
  остатком строк заказа; проведение прихода закрывает заказ. Отправки заказа поставщику нет —
  канала нет в списке интеграций.
- Поставщики и долги (`/suppliers`): долг выводится из проведённых приходов, возвратов поставщику
  и оплат, оплаты гасят приходы с ранним сроком первыми (`supplierDebt`). Оплата — финансовая
  операция: один UUIDv7 на диалог как `Idempotency-Key`. Только TJS (ADR-0016), курсовых разниц нет.
- Каталог (`/catalog`, карточка — `/catalog/view?id=`): названия RU/TJ, МНН, форма, дозировка,
  несколько штрихкодов (сканер — цифры и Enter), отпуск, регулируемая предельная цена, наценка,
  минимум. Дубли товаров офлайн-точек только показываются — решает точка (ADR-0014).
- Цены и скидки (`/pricing`): цена точки поверх сетевой (`mocks/pricing.ts`, касса берёт её в
  снимке каталога); выше предельной — мягкое предупреждение с подтверждением, ниже закупочной —
  предупреждение (`priceWarnings`). Правила скидок с порогами, охватом и сроком; сетевые — только
  с `discounts:manage-network`. Конфликты цен офлайн-точек решает владелец.
- Импорт из Excel и печать ценников неактивны до выбора библиотек (ADR).

## Service Worker (облачная сборка)

`nx build web` после `next build` запускает `tools/scripts/build-sw.mjs`: в `out/sw.js` попадает
манифест всех файлов `out/` и версия (SHA-256 содержимого). SW регистрируется только в production и
только при `GET /api/v1/deployment` → `cloud`; `/api/*` не кэширует; новая версия включается, лишь
когда чек пуст. Kill-switch: выложить `sw/kill-switch.js` как `/sw.js` — кэши удаляются, регистрация
снимается при следующем открытии.

## i18n

Словари — `src/shared/i18n/messages/{ru,tg}.json`, ключи на английском, RU — эталон набора
ключей (тест сверяет TJ с RU). Язык — переключателем RU/TJ, у сотрудника сохраняется в профиле.
Переводы TJ требуют вычитки носителем языка.

## Маршруты

`app/` — только реэкспорты страниц из `src/pages`. Вход — `app/login`, экраны после входа —
группа `app/(shell)` с каркасом `widgets/app-shell` (касса — `/pos`, смена — `/shift`, возвраты —
`/returns`, склад — `/stock`, `/goods-receipts`, `/transfers`, `/write-offs`, `/supplier-returns`,
`/stock-counts`, закупки — `/orders`, `/suppliers`, каталог — `/catalog`, `/catalog/view`,
`/pricing`). Пункты меню следующих этапов (отчёты, кабинет владельца, настройки) уже на своих
местах и отмечены значком
«появится в следующих версиях»; их маршруты — в `src/shared/config/routes.ts`.
