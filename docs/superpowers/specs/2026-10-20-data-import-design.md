# Загрузка данных сети из файла — спецификация

Дата: 2026-10-20. Статус: утверждена архитектором 2026-10-20 вместе с решениями автора F1–F22 и поправкой ADR-0015.
Пользователь попросил начать без вопросов, поэтому все решения ниже — решения автора.

Связано:
- модель данных `docs/architecture/data-model/06-sync-audit-billing.md` (запланированная `import_jobs`: «частичной
  загрузки нет (КП 10)»), `02-catalog-prices.md` (товары, штрихкоды, категории, справочник форм),
  `03-batches-warehouse.md` (`opening_balance_lines`, `is_starting` — «стартовая партия», КП 3.4);
- спецификации `2026-10-07-catalog-pricing-design.md` (C4 «импорт из файла — отдельной итерацией после склада»,
  C7–C9), `2026-10-09-inventory-purchasing-design.md` (I3 «начальные остатки… позже его же заполнит импорт»),
  `2026-10-16-offline-sync-design.md` (лента изменений для офлайн-точек, E4);
- ADR-0015 (стек фронтенда, «свои» реализации), ADR-0012 (proposed: лимиты тела запроса на proxy), ADR-0014
  (документы офлайн-точки ведутся на точке), ADR-0018 (права);
- объём пилота: все точки облачные, офлайн-точек нет.

## 1. Цель и критерии успеха

Новая сеть начинает работу со своими данными, а не с пустого каталога. Сейчас всё вводится вручную по одной
карточке: на 2–5 тысяч товаров это дни работы и главный барьер пилота. Кнопка «Импорт из Excel» в каталоге
неактивна: «появится после выбора библиотеки для чтения файлов (ADR)».

Успех:
- **Каталог.** Владелец или заведующий загружает файл Excel или CSV со своими товарами. Товары создаются вместе со
  штрихкодами и категориями. Уже известные товары пропускаются.
- **Начальные остатки.** Файл с остатками точки превращается в черновики документа «Начальные остатки» (НО). Их
  проверяют и проводят как обычно.
- **Поставщики.** Список поставщиков загружается тем же способом.
- **Файл как есть.** Заголовки столбцов не обязаны совпадать с шаблоном: система узнаёт их сама, человек поправляет.
- **Всё или ничего.** Перед загрузкой видны все ошибки с номерами строк. С ошибками ничего не записывается.
- **Повтор безопасен.** Повторная загрузка того же каталога ничего не дублирует. Повтор остатков предупреждает.
- **Без новых зависимостей.**

## 2. Решения автора (на утверждение вместе со спецификацией)

| № | Вопрос | Решение |
|---|---|---|
| F1 | Объём | Три загрузки: каталог, начальные остатки точки, поставщики. Для запуска сети главные — каталог и остатки; поставщики идут той же механикой и почти ничего не стоят |
| F2 | Форматы | `.xlsx` (Excel 2007+, LibreOffice, Google Таблицы, выгрузки учётных систем) и `.csv`. `.xls` (Excel 97–2003), `.ods`, файлы с паролем — не читаются, с подсказкой «Сохраните как .xlsx (Книга Excel) или CSV» |
| F3 | Чем читать | **Своё чтение в браузере, без библиотек** (§3). `.xlsx` — это zip с XML: распаковку даёт `DecompressionStream('deflate-raw')`, разбор XML — `DOMParser`; оба встроены в Chrome/Edge, целевые браузеры. Нужны только значения ячеек листа, это около 300 строк кода. Поправка ADR-0015: в список «своих» добавляется чтение таблиц. Почему не библиотека и не только CSV — §3.1 |
| F4 | Где разбирается файл | В браузере. На сервер уходят типизированные строки JSON (DTO с class-validator). Сам файл не передаётся и не хранится: в журнале остаются только имя, SHA-256 строк и итоги. На API нет multipart и Multer, сервер не распаковывает zip и не разбирает XML — поверхности для zip-бомб на сервере нет |
| F5 | Столбцы | Заголовки узнаются по словарю синонимов RU/TJ/EN (§4). У каждого столбца файла можно выбрать поле или «Не загружать». Обязательные поля должны быть выбраны. Строка заголовков — первая строка, где узнано хотя бы два поля, иначе первая непустая. Есть кнопка «Скачать шаблон»: CSV с заголовками |
| F6 | Значения справочников (каталог) | **Категории:** незнакомая — «Создать категорию» (по умолчанию) или выбрать существующую; для пустых ячеек — категория по умолчанию. **Лекарственные формы:** выбрать форму из справочника или «Без формы». Новые формы не создаются: у справочника нет редактора, мусор нельзя было бы убрать. **Страна:** название RU/TJ или код ISO; незнакомая остаётся пустой с предупреждением. **Единица:** по синонимам; незнакомая — ошибка строки |
| F7 | Всё или ничего (КП 10) | Любая ошибка — не записывается ничего. Сначала «Проверить»: сухой прогон на сервере, все ошибки с номерами строк. Затем «Загрузить»: та же проверка в транзакции и запись. Если данные изменились между шагами — 422 `import_invalid`, экран повторяет проверку |
| F8 | Существующее не меняется | Товар, чьи штрихкоды уже в каталоге (в том числе архивный), — «уже в каталоге», строка пропускается. Поставщик с тем же названием пропускается. Обновлять карточки и цены из файла в этой итерации нельзя |
| F9 | Как найти товар | По штрихкоду. Строку без штрихкода ищут по наименованию, а если выбраны столбцы — ещё по форме и дозировке. Сравнение точное после нормализации: регистр, пробелы, `ё`/`е`. **Каталог:** штрихкоды строки у разных товаров или только часть у товара — ошибка `barcode_conflict`. **Остатки:** товар не найден — `product_not_found` («сначала загрузите каталог»), неоднозначно — `product_ambiguous`, в архиве — `product_archived` |
| F10 | Остатки — черновики НО | Загрузка создаёт черновики НО выбранной точки на выбранную дату (по умолчанию сегодня). В документе до 500 строк (лимит документа), остальные — в следующих документах. Комментарий: «Загрузка из файла <имя>, часть i из n». Проводятся как обычно, у каждого документа (`inventory:post`). Остатков без проведения нет. Правила те же, что у ручного НО: доступ к точке, офлайн-точка — 409 `offline_store_read_only` |
| F11 | Строка остатков | **Серия** пустая — «стартовая партия» (КП 3.4). **Срок годности** обязателен: `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`, `ММ.ГГГГ` (последний день месяца) или дата Excel. **Количество** — целое число упаковок: 0 — строка пропускается, дробное или отрицательное — ошибка. **Закупочная цена за упаковку** обязательна (0 допустим). **Розничная** — по желанию: пусто — цена точки не меняется |
| F12 | Деньги из файла | Сомони с не более чем двумя знаками после запятой или точки, пробелы между тысячами допустимы. Перевод в дирамы — `parseMoneyToMinor` (`libs/shared/util`). Больше двух знаков — ошибка, без округления |
| F13 | Предупреждения (не мешают загрузке) | В точке уже есть остатки (движения). Те же строки уже загружали в эту точку — с номерами документов. Страна не узнана |
| F14 | Права | Каталог — `catalog:create`. Новые категории — дополнительно `catalog:update`; без него можно только выбрать существующую. Остатки — `inventory:create` и точка в охвате сотрудника. Поставщики — `purchasing:create`. Новых прав нет |
| F15 | Повтор и одновременность | «Загрузить» отправляет `Idempotency-Key` (UUIDv7, новый после каждой проверки). Повтор с тем же ключом возвращает сохранённый итог. Тот же ключ с другими строками — 409 `idempotency_key_reused`. Загрузки одной сети идут по очереди: advisory-блокировка `imports:<tenant>`. Строку сети не блокируем — её блокирует биллинг |
| F16 | Журнал загрузок | `import_jobs` (класс `tenant`, только вставка) хранит только выполненные загрузки: вид, точку, имя файла, хэш строк, ключ идемпотентности, итог, автора. Статусов `validating` / `failed`, столбца `errors` и уникальности по хэшу нет — поправка модели данных 06. Проверка синхронная, неудачная попытка ничего не оставляет. Повтор того же файла разрешён с предупреждением (F13) |
| F17 | Аудит | Одна запись на загрузку с итогами: `catalog.imported`, `opening-balance.imported`, `supplier.imported`. Отдельных `product.created` на каждую строку нет |
| F18 | Где код | Каждая загрузка — в модуле своих данных и по его правилам: `catalog`, `inventory`, `purchasing`. Журнал `ImportJobs` — общий, в `core/imports` (глобальный, как `core/sync`). Новых доменных модулей и связей графа нет: `inventory` берёт товары через расширенный `ProductsReader` |
| F19 | Лимиты | Файл — до 10 МБ. Строк данных — до 20 000 (каталог, остатки), до 2 000 (поставщики). Распакованный лист — до 100 МБ. Тело запросов загрузки — до 10 МБ: свой body-parser для этих путей, как у sync. В ответе — до 1 000 ошибок и общее число. Клиент ждёт ответа загрузки до 2 минут |
| F20 | Интерфейс | Страница «Загрузка из файла» (`/imports?kind=catalog\|opening-balances\|suppliers`). Шаги: файл → столбцы → значения (только каталог и только если нужно) → проверка → готово. Входы — кнопки «Загрузить из файла»: в каталоге (вместо неактивной «Импорт из Excel»), в «Начальных остатках», у поставщиков. Пункта меню нет |
| F21 | Офлайн-точка | Загрузки есть только в облаке: модули `catalog`, `inventory`, `purchasing` и так регистрируются только там. На офлайн-развёртывании веба кнопок нет. Созданные товары, категории и поставщики попадают в ленту изменений офлайн-точек (§10) |
| F22 | Попутно (пилот) | Кнопка «Выгрузка в 1С» у владельца скрыта, пока маршрута нет на API (`isApiRouteAvailable('export1c.preview')`): выгрузка исключена из пилота |

## 3. Чтение файла в браузере (`apps/web/src/shared/lib/spreadsheet`)

### 3.1 Почему своё

- **SheetJS** (`xlsx`): на npm лежит 0.18.5 — устаревшая версия с известными уязвимостями (prototype pollution, ReDoS).
  Новые версии — только с CDN вендора, а правило проекта — зависимости только из публичного npm.
- **ExcelJS**: тяжёлая, тянет серверные зависимости (`archiver`, `unzipper`, `tmp`), выпусков нет с 2023 года.
- **read-excel-file** (MIT): лёгкая, но тянет четыре транзитивные зависимости и вышла 12 раз за последние три месяца.
  Это лишний риск цепочки поставок ради задачи на 300 строк.
- **Только CSV**:
  - Excel в формате «Общий» записывает 13-значный штрихкод как `4,6E+12` — код теряется безвозвратно;
  - русская Windows по умолчанию сохраняет CSV в cp1251;
  - пользователь получает лишний шаг «Сохранить как».

  CSV поддерживается, но как второй формат.

Распаковка и разбор XML — встроенные средства браузера. Криптографии нет; SHA-256 строк считает сервер через
`node:crypto`.

### 3.2 `.xlsx`

- **Zip.** Конец центрального каталога ищется в последних 64 КБ. Записи каталога дают метод сжатия, размеры и
  смещение локального заголовка.
  - Методы: 0 (без сжатия) и 8 (deflate).
  - Шифрование, zip64 и другие методы — ошибка «файл не читается».
  - Распакованный размер считается в потоке, больше 100 МБ на запись — ошибка (zip-бомба).
- **Книга.**
  - `xl/workbook.xml`: листы по порядку, скрытые пропускаются; флаг `date1904`.
  - `xl/_rels/workbook.xml.rels`: путь к листу.
  - `xl/sharedStrings.xml` (может отсутствовать): строка — это все `<t>` элемента `<si>` подряд, кроме фонетики
    `<rPh>`.
- **Лист.**
  - Строки `<row>`, ячейки `<c r="B2" t="…">`. Без `r` ячейки и строки идут по порядку (так пишут некоторые
    учётные системы).
  - Типы ячеек:
    - `s` — общая строка;
    - `inlineStr` — `<is><t>`;
    - `str` — строка формулы;
    - `b` — логическое;
    - `n` или без типа — число, значением служит текст `<v>`;
    - `e` — ошибка формулы, ячейка считается пустой;
    - `d` — дата ISO.
  - У формулы берётся сохранённое значение `<v>`.
- **Без пространств имён.** Элементы ищутся по локальному имени (`getElementsByTagNameNS('*', …)`), поэтому Strict
  OOXML тоже читается.
- **Несколько листов.** Если видимых листов больше одного, на шаге «Файл» предлагается выбрать лист; по умолчанию
  первый.
- **Результат:**

  ```ts
  type Cell = null | { text: string; number: number | null };
  interface Workbook { date1904: boolean; sheets: { name: string; rows: Cell[][] }[] }
  ```

  У числовой ячейки `text` — исходная запись `<v>`, без форматирования Excel (`4600000000017`, `12.5`). Поэтому
  штрихкоды и деньги не теряют знаков.

### 3.3 `.csv`

- **Кодировка.** BOM UTF-8 — UTF-8. Иначе `TextDecoder('utf-8', { fatal: true })`, а при ошибке — `windows-1251`
  (так сохраняет русский Excel).
- **Разделитель** — `;`, `,` или табуляция: тот, которого больше в первой строке вне кавычек.
- **Кавычки** — по RFC 4180 (`""` внутри, переносы строк внутри кавычек); переводы строк CRLF и LF.
- **Результат** — тот же `Workbook` с одним листом и `number: null` у всех ячеек: числа разбираются из текста.

### 3.4 Общее

- Тексты нормализуются: NFC, неразрывный пробел заменяется обычным, пробелы по краям убираются, повторы схлопываются.
- Номер строки в ошибках — номер строки листа, как его показывает Excel (с 1, заголовок включён).
- Пустые строки пропускаются.
- Больше 20 000 строк данных — ошибка «Разделите файл».
- Разбор идёт в основном потоке: `DOMParser` нет в Web Worker. На 20 000 строк это доли секунды.

## 4. Поля и значения

Поле, отмеченное «да» в колонке «Обяз.», должно быть выбрано у какого-то столбца, а его ячейка — непуста. Синонимы
сравниваются после нормализации и без учёта регистра, точек и знаков `№ % ,`. Полный словарь — в коде фичи. Ниже —
основные синонимы.

**Каталог** (`kind=catalog`)

| Поле | Обяз. | Синонимы (основные) | Значение |
|---|---|---|---|
| Наименование (RU) | да* | наименование, название, товар, номенклатура, name | ≤ 200 |
| Наименование (TJ) | да* | ном, номи мол | ≤ 200 |
| Штрихкод | — | штрихкод, штрих-код, ean, баркод, barcode | 8–14 цифр. В ячейке может быть несколько кодов через `,` `;` `/` или перенос строки; пробелы внутри кода убираются. Можно выбрать несколько столбцов. Запись `4,6E+12` — ошибка `barcode_scientific` с подсказкой «задайте столбцу текстовый формат» |
| Категория | — | категория, группа, раздел | По F6. Пустая ячейка — категория по умолчанию |
| Лекарственная форма | — | форма, лекарственная форма | По F6: выбор из справочника или «Без формы» |
| Дозировка | — | дозировка, доза | ≤ 200 |
| МНН | — | мнн, inn, действующее вещество | ≤ 200 |
| Производитель | — | производитель, изготовитель, фирма | ≤ 200 |
| Страна | — | страна, страна производства | Название RU/TJ или код ISO; иначе пусто с предупреждением |
| Единица | — | единица, ед изм | уп / упак / упаковка → `pack`; шт / штука → `piece`; мл → `ml`; пусто → `pack` |
| Штук в упаковке | — | в упаковке, кол-во в уп, фасовка | Целое 1–10 000; пусто → 1 |
| Продаётся поштучно | — | поштучно, делимый | да / нет / 1 / 0 / + / −; пусто → нет. «Да» при < 2 штук — `not_divisible` |
| Отпуск | — | отпуск, рецепт, рецептурный | без рецепта / нет → `none`; по рецепту / да / rx → `rx`; ПКУ → `controlled`; пусто → `none` |
| Предельная цена | — | предельная цена, макс цена | Деньги (F12); пусто → не регулируется |
| Наценка, % | — | наценка | Целое 0–1000, знак `%` допустим; пусто → по категории |
| Минимальный остаток, уп. | — | мин остаток, минимальный запас | Целое ≥ 0; пусто → 0 |

\* Обязателен столбец наименования на языке сети по умолчанию (`tenant_settings.default_language`, C8).

**Начальные остатки** (`kind=opening-balances`; на шаге «Файл» ещё выбираются точка и дата)

| Поле | Обяз. | Синонимы (основные) | Значение |
|---|---|---|---|
| Штрихкод | да** | как в каталоге | Ищет товар (F9) |
| Наименование | да** | как в каталоге | Ищет товар без штрихкода (F9) |
| Лекарственная форма, Дозировка | — | как в каталоге | Уточняют поиск по наименованию |
| Серия | — | серия, партия, лот | ≤ 60; пусто — стартовая партия (F11) |
| Срок годности | да | срок годности, годен до, срок | F11 |
| Количество, уп. | да | количество, кол-во, остаток | F11 |
| Закупочная цена за упаковку | да | закупочная цена, цена закупки, себестоимость | F12, ≥ 0 |
| Розничная цена за упаковку | — | розничная цена, цена продажи, цена | F12, ≥ 1; пусто → цена точки не меняется |

\*\* Нужен хотя бы один из двух столбцов. Тот же файл, из которого загружали каталог, подходит: лишние столбцы
получают «Не загружать» автоматически.

**Поставщики** (`kind=suppliers`)

| Поле | Обяз. | Синонимы (основные) | Значение |
|---|---|---|---|
| Название | да | поставщик, название, наименование, контрагент | ≤ 200 |
| ИНН | — | инн, рма, tin | 9 цифр после удаления пробелов, или пусто |
| Телефон | — | телефон, тел | ≤ 60 |
| Адрес | — | адрес | ≤ 300 |
| Отсрочка, дней | — | отсрочка, отсрочка платежа | Целое 0–365; пусто → 0 |

Ошибки разбора значений (не число, нет обязательного, неверная дата…) находит браузер ещё до запроса. На сервер
уходят только строки без таких ошибок. Пока они есть, кнопка «Проверить» неактивна.

## 5. Проверка и загрузка на сервере

Общий порядок для каждого вида:
1. DTO проверяет форму строк (class-validator). Ошибка — 400 `validation_failed`, `errors[]` с путями
   `rows.<i>.<поле>`; экран переводит индекс в номер строки.
2. **Проверка** (`…/checks`, 200). Справочники и сопоставления читаются набором запросов на весь файл, без
   запроса на строку: все штрихкоды файла — одним `= any(…)`, все наименования без штрихкода — одним, справочники
   — по разу. Ответ — итог и ошибки.
3. **Загрузка** (201):
   - запрос идёт с `Idempotency-Key`;
   - в одной транзакции: advisory-блокировка `imports:<tenant>`, поиск ключа в `import_jobs` (найден с тем же
     хэшем — сохранённый итог; с другим — 409);
   - затем та же проверка; есть ошибки — 422 `import_invalid` и ничего не записано;
   - затем запись пачками по 1 000 строк (многострочный `insert`), строка `import_jobs`, запись аудита.

**Каталог**
- **Категории.** Совпадение без учёта регистра с названием активной категории на любом языке даёт её. Совпадение
  только с архивной — ошибка `archived_category`. Иначе категория создаётся с названием на языке сети, под той же
  advisory-блокировкой `category-names:<tenant>`, что у ручного создания. Без права `catalog:update` создать
  нельзя — ошибка `unknown_category`.
- **Форма** должна быть в справочнике сети, иначе `unknown_form` (экран это уже исключил).
- **Штрихкоды:**
  - все коды строки у одного товара — строка «уже в каталоге»;
  - ни одного — новый товар;
  - иначе `barcode_conflict` с названием товара;
  - один код в двух строках файла — `duplicate_in_file` у второй строки.
- **Строка без штрихкода** — поиск по F9:
  - найден — «уже в каталоге»;
  - не найден — новый товар;
  - две такие строки с одинаковым ключом — `duplicate_in_file`.
- Правила карточки — те же, что у `ProductsService.create`: имя на языке сети, `not_divisible`, предел
  минимального остатка, страна из списка. Их проверка выносится в общую функцию, которую используют и форма, и
  загрузка.

**Начальные остатки**
- Точка проверяется тем же `StoreAccess`, что у ручного НО: охват сотрудника, активная точка; офлайн-точка — 409.
- **Товар** ищется по F9 среди товаров сети. Ошибки: `product_not_found`, `product_ambiguous`,
  `product_archived`, штрихкоды строки у разных товаров — `barcode_conflict`.
- **Строки** переносятся в черновики как есть и в порядке файла. Проверки строк — те же, что при сохранении
  черновика вручную (общий код `stock-documents.service`).
- **Номера документов** выдаёт обычная нумерация НО.
- **Предупреждения проверки:**
  - `storeHasStock` — в точке уже есть движения остатков;
  - `previousImports` — выполненные загрузки НО в эту точку с тем же хэшем строк: дата и номера документов.

**Поставщики**
- Совпадение названия без учёта регистра с существующим поставщиком (и архивным) — «уже есть», строка пропускается.
- Повтор названия в файле — `duplicate_in_file`.
- Остальные правила — как у `POST /suppliers`.

**Быстродействие.** Цель на 20 000 строк каталога: проверка — до 10 с, загрузка — до 30 с на dev-машине. Измеряется
на временной базе (§14). Транзакция загрузки не трогает остатки и чеки, поэтому касса во время загрузки работает.

## 6. Схема (одна миграция)

```sql
create table pharmacy.import_jobs (
  tenant_id uuid not null references pharmacy.tenants (id),
  id uuid not null,                                   -- UUIDv7 from the app
  kind text not null check (kind in ('catalog', 'opening_balance', 'suppliers')),
  store_id uuid,
  file_name text not null check (char_length(file_name) between 1 and 255),
  content_sha256 bytea not null check (octet_length(content_sha256) = 32),
  idempotency_key uuid not null,
  result jsonb not null,                              -- the response of the import, returned on a retry
  created_by uuid not null,
  created_at timestamptz not null default now(),
  primary key (tenant_id, id),
  unique (tenant_id, idempotency_key),
  check ((kind = 'opening_balance') = (store_id is not null)),
  foreign key (tenant_id, store_id) references pharmacy.stores (tenant_id, id),
  foreign key (tenant_id, created_by) references pharmacy.employees (tenant_id, id)
);
create index import_jobs_content_idx on pharmacy.import_jobs (tenant_id, kind, store_id, content_sha256);
```

- RLS `tenant_isolation` для `pharmacy_app`, как у всех tenant-таблиц. Гранты — `select, insert`: строки не меняются
  и не удаляются.
- Класс `tenant` записывается в `table-classes.ts`.
- Номер миграции должен быть больше всех на `main`, в ветках синхронизации (PR 3a: `1792488876303_sync-changes`) и в
  общих базах. Сверяется перед добавлением.

## 9. Веб (`apps/web`)

**Срезы FSD:**
- `shared/lib/spreadsheet` — чтение файлов (§3);
- `features/data-import`:
  - мастер;
  - описания трёх видов: поля, синонимы, разбор значений, сборка запроса, маршруты;
  - CSV-шаблон и CSV ошибок;
- `pages/data-import` и маршрут `app/(shell)/imports/page.tsx`. Вид загрузки — в query-параметре `kind`, неизвестный
  вид — «Страница не найдена».

**Шаги мастера:**
1. **Файл:**
   - вид и что в нём должно быть: обязательные поля;
   - «Скачать шаблон» — CSV в UTF-8 с BOM, разделитель `;`, заголовки на языке интерфейса;
   - выбор файла;
   - выбор листа, если листов несколько;
   - для остатков — точка из охвата и дата.
2. **Столбцы.** Таблица: заголовок столбца, первые три непустых значения, поле. Поля выбраны по синонимам. Если не
   выбрано обязательное поле — сообщение, «Далее» неактивна.
3. **Значения** (каталог, только если есть незнакомые категории или формы):
   - категории — «Создать» или существующая; «Создать» есть только при праве `catalog:update`;
   - формы — из справочника или «Без формы»; совпадение без регистра подставляется само;
   - категория по умолчанию для пустых ячеек.
4. **Проверка:**
   - сначала ошибки разбора в браузере, с номерами строк — «Проверить» неактивна, пока они есть;
   - затем ответ сервера:
     - итог: «Будет создано 2 140 товаров, 35 уже в каталоге — пропущены, новых категорий 12: …»; для остатков —
       «Строк 3 100 → 7 черновиков НО»;
     - предупреждения (F13);
     - ошибки списком: строка, поле, сообщение; не больше 1 000, с общим числом;
   - «Скачать ошибки (CSV)»;
   - «Загрузить» активна, если ошибок нет.
5. **Готово:**
   - итог;
   - для остатков — ссылки на черновики («Открыть НО-000012») и напоминание провести их;
   - для каталога и поставщиков — «Открыть каталог» или «Открыть поставщиков».

**Детали:**
- Повторный шаг назад сбрасывает результат проверки и ключ идемпотентности.
- Ответы 413 и `timeout` показываются понятным сообщением («Файл слишком большой — разделите его на части»). Таймаут
  загрузки — 2 минуты: параметр запроса в API-клиенте, по умолчанию 15 с.
- Кнопки входа видны при праве и при `isApiRouteAvailable(...)`. На офлайн-развёртывании их нет.
- Шесть маршрутов — в `REAL_API_ROUTES`. Моки повторяют API: каталог создаёт всё, что не совпало по штрихкоду с
  моковым каталогом; остатки дают черновики по 500 строк.
- Журнал действий показывает три новых события с подписями RU/TJ.
- Тексты — в пространстве `import` (RU и TJ, ключи совпадают). Перевод TJ ждёт общей вычитки.
- Экран рассчитан на 1280×800, без горизонтальной прокрутки. Таблицы столбцов и ошибок прокручиваются внутри.

## 10. Лента изменений офлайн-точек

В ветке PR 3a синхронизации (`feature/offline-sync-pr3a`, ещё не на `main`) каждая запись товара, штрихкодов и
категории в `CatalogRepository` записывает сущность в `sync_changes` (E4: «в репозитории, чтобы ни один путь записи
её не пропустил»).

Пакетные методы загрузки тоже живут в `CatalogRepository` (и в репозитории `purchasing` для поставщиков) и должны
записывать ленту одним многострочным `insert`, без запроса на строку. Кто сливается вторым, тот и добавляет запись
ленты в пакетные методы. Черновики НО в ленту не попадают: документы точки ведутся на точке. На пилоте офлайн-точек
нет, но лента не должна их пропустить.

## 16. Уточнения 2026-10-20 (план и реализация)

Решения ниже не меняют F1–F22; они уточняют то, о чём спецификация молчала или что не сходилось с кодом.

- **У1.** Тот же `Idempotency-Key` с другими строками — 409 `idempotency_conflict`, как у кассы, а не
  `idempotency_key_reused` (§2, F15).
- **У2.** События журнала названы так, чтобы попасть в существующие группы журнала:
  - каталог — `product.imported` (группа «Каталог»);
  - поставщики — `supplier.imported` («Закупки»);
  - остатки — `document.imported` с `details.type = 'opening_balance'` («Приход и НО»).

  Черновик НО, как и при ручном создании, пишет ещё `document.created` (F17, §11).
- **У3.** Загрузка остатков требует ещё права `finance:view-cost`, как ручной НО (ADR-0018 п. 6): в файле закупочные
  цены (F14).
- **У4.** Комментарий черновиков приходит от экрана на языке интерфейса (`comment` в `OpeningBalanceImportRequest`,
  до 450 символов). API дописывает ` (i/n)`, когда черновиков больше одного (F10).
- **У5.** Тексты мастера — пространство `dataImport` группы сообщений `stock`; лимиты F19 — `importLimits` в
  `libs/shared/domain`; ключ сравнения F9 — `matchKey` в `libs/shared/util`.
- **Штрихкод, которого нет в каталоге** (остатки): строка ищется по наименованию, форме и дозировке, как строка без
  штрихкода. Так находится товар, заведённый без этого кода (F9).
- **Проверка остатков** сразу проверяет точку: охват сотрудника, офлайн-точка — 409. Ошибка точки видна до
  загрузки.
- **Шаг «Значения»** пропускается, если выбирать нечего: все категории и формы знакомы и у каждой строки есть
  категория.
- **«Готово» у остатков** — номера черновиков и переход в журнал «Ввод начальных остатков». Отдельного адреса у
  документа нет.
- **Моки загрузок** — в мок-модулях своих данных (`handlers-catalog`, `handlers-stock`, `handlers-purchasing`), с их
  проверками.
- **Очередь загрузок без ожидания** (итоговое ревью). Вторая загрузка сети, пока идёт первая, сразу получает 409
  `import_in_progress`, экран просит повторить. Ждать нельзя: загрузка длится секунды, дольше `lock_timeout`
  запроса, а ожидание держало бы соединение пула, общего с кассой. Блокировка названий категорий берётся, только
  если загрузка создаёт категории.
- **`import_jobs` — только дописывается** (итоговое ревью): таблица в `APPEND_ONLY_TABLES`, триггер запрещает
  UPDATE, DELETE и TRUNCATE.
- **Лента офлайн-точек** (PR 3a уже на `main`): товары загрузки записываются в `sync_changes` одним многострочным
  `insert`, как товары карточки (§10).
