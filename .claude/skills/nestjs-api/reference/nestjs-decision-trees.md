# NestJS Decision Trees — Pharmacy

Деревья решений для apps/api (NestJS + Express, PostgreSQL, Redis, модульный монолит в Nx).
Если ни одна ветка не подходит без новой технологии — это ветка «нужен ADR».

---

## Нужна технология / библиотека / интеграция?

```
Есть в стеке (CLAUDE.md, stack.md)?
|
+-- Да -> используем
|
+-- Пока не выбрано (брокеры, секреты, логирование, мониторинг, CI/CD,
|   API gateway, криптобиблиотеки, push)?
|   -> Вводится только через ADR. До ADR — текущее решение:
|      брокер -> очередь-таблица PostgreSQL (SKIP LOCKED, ADR-0002), nestjs-messaging-basics.md
|      pino/winston/OTel -> встроенный Nest Logger + correlation ID, nestjs-observability.md
|      Vault -> env-файлы / переменные окружения
|      CI -> GitHub Actions (ADR-0009); пока workflow-файлов нет — `npm run check` перед PR
|      хеш паролей/PIN -> PasswordHasher = scrypt из node:crypto + pepper (ADR-0008);
|      самописная криптография запрещена
|
+-- Не выбрано проектом (Fastify, хранение файлов, раздача статики — ADR-0012 proposed, мониторинг)?
|   -> /03-adr (docs/architecture/adr/) ДО кода
|
+-- Новая внешняя система?
    -> Закрытый список: 1С (файлы), фискализация (адаптер), синхронизация точек (валюта только TJS — ADR-0016).
       Всё остальное (email, SMS, платёжные шлюзы, OAuth, Firebase, облачные SaaS-БД) — нет;
       реальная потребность -> ADR.
```

## Куда положить код?

```
Что это?
|
+-- Контракт API (request/response, query, коды ошибок) -> libs/shared/dto
+-- Доменный тип/перечисление, общее для api и фронтендов -> libs/shared/domain
+-- Деньги (дирамы, округление), даты, i18n RU/TJ -> libs/shared/util
+-- Логика одного домена -> apps/api/src/app/<module>
+-- Инфраструктура (БД, Redis, health) -> apps/api/src/core
+-- Сквозное (фильтр ошибок, correlation ID, маскирование) -> apps/api/src/common
+-- Сессии, PIN, права -> apps/api/src/app/auth
```

## Модулю нужны данные другого модуля

```
|
+-- Чтение (pos читает цены pricing, остатки inventory)
|   -> импорт модуля-владельца, вызов его ЭКСПОРТИРОВАННОГО сервиса
|   -> никогда: чужой репозиторий или SQL по чужим таблицам
|
+-- Запись в рамках одной бизнес-операции (чек -> движения партий -> аудит)
|   -> сервис-владелец операции открывает tenantTransaction и передаёт trx (TenantTransaction)
|      в публичные методы сервисов других модулей: одна транзакция, атомарно
|
+-- Реакция «потом», не блокирующая операцию (фискализация, отправка в синхронизацию)
|   -> запись в очередь-таблицу в ТОЙ ЖЕ транзакции (outbox), обработчик — воркер
|
+-- Циклическая зависимость модулей
    -> граница выбрана неверно: вынести общее в libs/shared/domain или пересмотреть
       владение; forwardRef() — не решение
```

Новый модуль или смена границ модулей — ADR (ADR-0002).

## Операция меняет остатки или деньги?

```
|
+-- Да
|   -> одна транзакция: документ/чек + stock_movements + audit_log
|   -> FOR UPDATE на партиях (стабильный порядок), проверка остатка = SUM(движений)
|   -> idempotency key (UNIQUE (tenant_id, key)), correlation ID
|   -> суммы integer дирамы; себестоимость штуки при делении упаковки — округление вверх
|   -> внешние вызовы — после коммита, через очередь-таблицу
|
+-- Нет -> обычная tenantTransaction (чтение/запись в пределах модуля)
```

## Аутентификация и авторизация маршрута

```
Кто вызывает?
|
+-- Сотрудник тенанта (web) -> серверная сессия (Redis) + @RequirePermission('<модуль>:<действие>'[, store scope]) — каталог ADR-0018
+-- Кассир на привязанном терминале -> PIN-сессия терминала, охват = точка терминала
+-- Офлайн-точка (sync) -> @Public() + LicenseKeyGuard, idempotency key на каждую операцию
+-- Оператор платформы (admin) -> отдельные операторские сессии и права; «от имени» не реализуется (пересматривается)
+-- Инфраструктура (health) -> @Public() + @SkipThrottle(), без данных
+-- OAuth / сервис-сервис токены / JWT без серверной сессии -> не стандарт; нужна причина -> ADR
```

## Стратегия тестов (Jest)

```
Что проверяем?
|
+-- Бизнес-правило в сервисе (FEFO, скидка «одно наиболее выгодное», округление денег)
|   -> unit (Jest), репозитории замоканы
|
+-- Изоляция тенантов, RLS, транзакционность, идемпотентность
|   -> интеграционный тест с реальной PostgreSQL (моки здесь бесполезны)
|
+-- Контракт эндпоинта (статусы, problem+json, валидация)
|   -> e2e apps/api-e2e (supertest)
|
+-- Нагрузка (касса ≤ 1 сек, 50 кассиров)
    -> отдельный прогон на стенде; инструмент — по решению команды
```

Подробности — `nestjs-testing-*.md`.

## Кэшировать?

```
|
+-- Каталог, действующие цены точки, скидочные правила (нужны кассе за ≤ 1 сек)
|   -> Redis, ключ ВСЕГДА с tenantId: t:{tenantId}:...; инвалидация при изменении
|
+-- Права роли
|   -> Redis/in-memory по roleId + roleVersion
|
+-- Остатки, суммы смены, долги поставщикам
|   -> НЕ кэшировать как источник истины: считать из движений/документов в транзакции
|
+-- Ответы для фронтенда -> HTTP-кэш не используем для данных тенанта
```

## Какой ответ об ошибке?

```
|
+-- Невалидный вход -> 400 (ValidationPipe), problem+json с errors[]
+-- Нет сессии -> 401 (AuthGuard); не бросать 401 из сервисов
+-- Нет права / точка вне охвата -> 403 (PermissionsGuard)
+-- Не найдено в тенанте (в т.ч. «чужое») -> 404
+-- Дубликат, unique violation, повтор ключа с другим телом -> 409
+-- Нарушение бизнес-правила (нет остатка, смена закрыта, ПКУ без рецепта) -> 422 с code
+-- Фискализация / синхронизация недоступны -> 502/503; касса не блокируется, фискализация в очереди
+-- Непредвиденное -> пусть летит в глобальный фильтр (500), без пустых catch
```

Формат — `nestjs-enterprise-patterns.md`.
