# ADR-0025: Сканирование штрихкода камерой — встроенный `BarcodeDetector`, иначе `barcode-detector` на `zxing-wasm`

- **Дата:** 2026-11-04
- **Авторы:** Zohid Saidov (z.saidov@eskhata.com), команда проекта Pharmacy (текст подготовлен с помощью AI)
- **Принимает:** архитектор проекта (docs/architecture/APPROVAL.md)
- **Спецификация:** `docs/superpowers/specs/2026-11-03-pos-store-ideas-design.md`, пункт I5 (решения D31–D35, утверждена

## Контекст

Сейчас штрихкод вводит USB-сканер — HID-клавиатура (`useBarcodeScanner`, `apps/web/src/shared/lib/scanner`). У
планшетов точек сканера часто нет, а 1D-сканер не читает QR чека (ADR-0022): экран возврата находит чек по скану QR
только 2D-сканером. Спецификация (D31–D33) добавляет кнопку «Камера» у полей, которые принимают скан:
- подбор товара кассы;
- поиск строки документа;
- инвентаризация;
- поиск чека на экране возврата;
- штрихкод в карточке товара.

Код из кадра уходит тому же обработчику, что и скан USB-сканера.

Требования к распознаванию (D34):
- пять форматов: EAN-13, EAN-8, UPC-A, Code 128, QR — в Chrome и Edge на Windows и Android;
- файлы со своего origin, без CDN, работа без сети;
- загрузка только при открытии окна камеры, не в начальном бандле кассы;
- лицензия MIT, Apache-2.0 или BSD; живой проект; версия закреплена точно.

Встроенный в браузер `BarcodeDetector` (Shape Detection API) есть на Android, ChromeOS и macOS, но не в Chrome и Edge на
Windows — а Windows-планшеты и ПК — основные устройства пилота.

Сейчас proxy запрещает камеру на всех хостах (`Permissions-Policy: camera=()`, ADR-0012), а CSP не разрешает компиляцию
WebAssembly.

## Рассмотренные варианты

1. **Только встроенный `BarcodeDetector`.** Плюс — ноль зависимостей. Минус — на Windows его нет: основные устройства
   пилота остаются без камеры. D34 не выполняется.
2. **`@zxing/browser` 0.2.1 + `@zxing/library` 0.23.0.** Чистый JS, CSP менять не нужно, MIT и Apache-2.0, около
   110 КБ gzip. Минусы:
   - README библиотеки объявляет «Project in Maintenance Mode Only» — изменения только из присланных патчей, требование
     «живой проект» не выполняется;
   - это порт старой Java-версии ZXing, на 1D-кодах из кадра камеры он слабее zxing-cpp;
   - своё управление камерой дублирует наше окно.
3. **`barcode-detector` 3.2.3 (ponyfill API `BarcodeDetector`) на `zxing-wasm` 3.1.6.** `zxing-wasm` — это zxing-cpp,
   собранный в WebAssembly.
   - Лицензии: MIT у обоих пакетов, внутри `.wasm` — zxing-cpp под Apache-2.0.
   - Один автор, выпуски каждый месяц, последние — 2026-10-19.
   - API тот же, что у встроенного `BarcodeDetector`, поэтому путь распознавания один.
   - Файл распознавания `zxing_reader.wasm` — 947 КБ, около 410 КБ в gzip.
   - Минусы: нужен `'wasm-unsafe-eval'` в CSP; по умолчанию `.wasm` грузится с jsDelivr, и это нужно переопределить.
4. **Другие библиотеки.**
   - `html5-qrcode` 2.3.8 — последний выпуск 2023-04, построена на `@zxing/library`.
   - `@ericblade/quagga2` 1.13.0 — только 1D-коды, QR чека не читает.
   - Свой распознаватель — большая работа, ошибки которой видны только на реальных упаковках. ADR-0022 написал своим
     кодом только кодировщики.

## Решение

Выбран вариант 3: встроенный `BarcodeDetector`, где он поддерживает все пять форматов, иначе ponyfill
`barcode-detector` на `zxing-wasm`.

1. **Зависимости** — только у `apps/web`, версии закреплены точно:
   - `barcode-detector` 3.2.3;
   - `zxing-wasm` 3.1.6 — зависимость первого, которую он сам закрепляет точно. В `package.json` она указана явно:
     сборка берёт из неё файл `.wasm`.

   Оба выпуска вышли 2026-10-19 — не меньше двух недель до решения (правило ADR-0024). Транзитивные зависимости —
   `type-fest` и `@types/emscripten`, только типы. `libs/ui`, `apps/admin` и `apps/site` пакеты не импортируют.
2. **Загрузка по требованию.**
   - Импорт — только `barcode-detector/ponyfill`, а не `polyfill`: глобальный `BarcodeDetector` не подменяется.
   - Импорт идёт динамическим `import()`, когда открывается окно камеры и встроенного распознавателя нет. В начальный
     бандл кассы библиотека не входит.
3. **Встроенный первым.** Если `globalThis.BarcodeDetector` есть, а `getSupportedFormats()` содержит `ean_13`, `ean_8`,
   `upc_a`, `code_128` и `qr_code`, используется он. Иначе — ponyfill с тем же списком форматов.
4. **`.wasm` со своего origin.** Файл распознавания входит в статику сборки web; путь к нему задаёт `prepareZXingModule({
   overrides: { locateFile } })` до первого распознавания. Адрес jsDelivr по умолчанию не используется, а `connect-src
   'self'` и так его блокирует. Имя файла содержит версию `zxing-wasm`, и сборка сверяет SHA-256 файла с
   `ZXING_WASM_SHA256` пакета.
5. **Без сети.** Service Worker облачной сборки предкэширует все файлы `out/` (`tools/scripts/build-sw.mjs`), в том
   числе чанк библиотеки и `.wasm`: после установки камера работает без связи. `.wasm` добавляется в предсжатие
   (`tools/scripts/precompress.mjs`, `.br` и `.gz`).
6. **Камера и кадры.**
   - Поток: `getUserMedia({ video: { facingMode: { ideal: 'environment' } }, audio: false })`.
   - Кадры читаются из `<video>` в браузере: ничего не сохраняется и не отправляется.
   - Поток останавливается, когда окно закрыто, вкладка скрыта, со страницы ушли или 60 с нет кода.
   - Кнопки «Камера» нет вне защищённого контекста (`isSecureContext`) или без устройства `videoinput`.
   - Вибрация и фонарик (`torch`) — там, где браузер их даёт.
7. **Поправка ADR-0012** (proxy, D35):
   - хост `app.` и офлайн-профиль web — `Permissions-Policy: camera=(self), microphone=(), geolocation=()` и
     `script-src 'self' 'unsafe-inline' 'wasm-unsafe-eval'`;
   - `admin.` и публичный сайт — прежние `camera=()` и CSP без `'wasm-unsafe-eval'`.

   Сниппет `static-files` получает параметры для этих двух значений.
8. **Лицензии.** Тексты MIT (`barcode-detector`, `zxing-wasm`) и Apache-2.0 (zxing-cpp) — в
   `apps/web/THIRD_PARTY_NOTICES.md` и в статике рядом с `.wasm`: его получает браузер, то есть файл распространяется.
9. **Обновление версии** — осознанным PR, с той же проверкой давности выпуска. Новая версия `zxing-wasm` меняет имя
   файла `.wasm`.

## Последствия

- **Положительные:**
  - камера работает на Windows-планшетах и Android одним кодом;
  - на Android и macOS — встроенный распознаватель без загрузки библиотеки;
  - экран возврата читает QR чека без 2D-сканера;
  - USB-сканер и его обработчики не меняются;
  - admin и сайт не затронуты.
- **Отрицательные:**
  - +4 пакета в `package-lock.json`, их обновления нужно отслеживать (цепочка поставок). В браузере кассы исполняется
    двоичный `.wasm` одного сопровождающего; доверие держится на закреплённой версии и сверке SHA-256;
  - `'wasm-unsafe-eval'` расширяет CSP хоста `app.`: любой скрипт страницы может компилировать WebAssembly. Рядом с уже
    разрешённым `'unsafe-inline'` риск растёт немного, но в цели «ужесточить CSP после MVP» пунктом больше;
  - `camera=(self)` позволяет любой странице `app.` запросить камеру. Браузер всё равно спрашивает пользователя, но
    при XSS запрос возможен;
  - каждая установка Service Worker скачивает ещё около 410 КБ, даже на ПК без камеры;
  - распознавание зависит от камеры: фронтальная камера без автофокуса у дешёвого планшета мелкий EAN-13 может не
    прочитать. Основным инструментом остаётся USB-сканер, камера — подмога;
  - на Android и Windows работают разные распознаватели (встроенный и zxing-cpp) — оба проверяются на пилоте;
  - разрешение камеры даётся на каждом устройстве: при первом открытии кассир должен разрешить, а отказ снимается
    только в настройках браузера.

Управление решениями — ADR-0011 (проект вне банковского контура).
