| D1 | Складские документы: общая шапка `documents` + таблицы строк по типам | Жизненный цикл, нумерация, проведение, синхронизация (`document.posted`) — один раз; строки строго типизированы |

| D3 | Кассовая смена — на терминал (кассу); кассиры меняются по PIN внутри смены | Свой денежный ящик и Z-отчёт у каждой кассы, как у ККМ |
| D4 | Карточка товара хранит все свои атрибуты; общий справочник препаратов — образец для заполнения, поиска аналогов и дублей | Аптека правит карточку сама; правка справочника оператором не меняет правила продажи у всех аптек молча |
| D5 | Юрлица сети — справочник `legal_entities`; точка ссылается на одно | Сеть на нескольких ИП; реквизиты чека, 1С и долгов поставщикам — по юрлицу |
| D6 | Названия справочных сущностей — `jsonb` `{"ru": …, "tj": …}` | Новый язык добавляется без миграции; обязателен язык сети по умолчанию |

## Сквозные соглашения

**Идентификаторы и ключи**
- `id uuid` — UUIDv7, генерирует приложение (библиотека `uuid`, ADR-0014 §2). `default` в БД нет: PostgreSQL 17 не умеет `uuidv7()`, а офлайн-точка создаёт строки сама.
- Таблицы классов `tenant` и `tenant-export`: `tenant_id uuid not null`, первичный ключ `(tenant_id, id)`. Все ссылки внутри тенанта составные: `(tenant_id, <x>_id) references <table> (tenant_id, id)`. База не даст сослаться на строку чужого тенанта.
- Таблицы классов `platform`, `shared`, `system`: первичный ключ `id`. Ссылка на точку или тенанта — через `(tenant_id, store_id)`.
- Человекочитаемые номера (ПР-000123, номер чека) — не ключи. Они уникальны в `(tenant_id, store_id, kind, number)` и берутся из счётчиков `document_counters` ([03](03-batches-warehouse.md)).

**Типы**
- **Деньги** — `bigint`, в дирамах, суффикс `_dirams` (`total_dirams`, `price_per_pack_dirams`). `float`/`numeric` для денег не используются (ADR-0016, CLAUDE.md).
- **Количество** — `integer`, в штуках (минимальная продаваемая единица), суффикс `_pieces`. Упаковка = `products.pieces_per_pack` штук. Товар, который не делится, имеет `pieces_per_pack = 1`.
- **Проценты** (наценка, скидка, НДС) — `integer` в базисных пунктах, суффикс `_bp`: 3 % = 300.
- **Цена штуки** — `ceil(цена упаковки / pieces_per_pack)` до дирама, в пользу аптеки. Это же правило — для себестоимости штуки (КП 3.1).
- **Время** — `timestamptz`. Бизнес-дата (`business_date date`) — дата в часовом поясе сети (`tenant_settings.timezone`, по умолчанию `Asia/Dushanbe`). По ней строятся отчёты, журнал ПКУ, Z-отчёт и биллинг.
- **Статусы и виды** — `text` + `check (col in (…))`, не enum: enum тяжело менять миграциями «только вперёд» (ADR-0006).
- **Многоязычные названия** — `name jsonb not null`, объект `{"ru": "…", "tj": "…"}`. Проверка `check (jsonb_typeof(name) = 'object' and name ? 'ru' …)`: обязательный язык — язык сети по умолчанию; значения — непустые строки. Проверку делает приложение по `tenant_settings.default_language`, база гарантирует непустой объект строк. Поиск — индексы `pg_trgm` по `(name->>'ru')` и `(name->>'tj')`. Названия юрлиц, поставщиков и адреса — обычный `text`: их не переводят.
- **Имена** — `snake_case` в БД, `camelCase` в коде (`CamelCasePlugin`, ADR-0006).

**Жизненный цикл строк**
- **Справочные сущности не удаляются, а архивируются:** точки, юрлица, товары, поставщики, сотрудники, роли, способы оплаты. Для этого `status` (`active` / `archived` или предметный) и `archived_at`. На них ссылаются факты, а синхронизация передаёт удаление как tombstone (ADR-0014 §3).
- **Только добавление** (`REVOKE UPDATE, DELETE` + триггер, запрещающий изменение): `stock_movements`, `audit_log`, `platform_audit_log`, `shift_cash_operations`, `controlled_sale_records`, `supplier_ledger_entries`. Исправление — новой записью (сторно, корректировка).
- **Технические колонки:** `created_at timestamptz not null default now()` у всех таблиц. `updated_at` — у изменяемых справочников и документов (обновляет приложение). Кто создал и провёл — явные колонки `…_by` (сотрудник).

**Секционирование** (месячные диапазоны по времени записи): `stock_movements` (`recorded_at`), `audit_log` (`recorded_at`), `sync_inbox` (`received_at`). Ключ секционированной таблицы включает колонку секционирования: `(tenant_id, id, recorded_at)`. На такие таблицы не ссылаются внешние ключи — ссылки внутри них (например, сторно) проверяет приложение. Секции на год вперёд создаёт плановая задача, старые — не удаляются (аудит ≥ 3 лет, КП 12).

**Изоляция и права** — по классам таблиц ADR-0013. Класс каждой таблицы указан в её разделе и попадает в манифест `apps/api/src/core/database/table-classes.ts`. RLS `enable` + `force` на классах `tenant`, `tenant-export`, `platform`, `system`. Политики только с `TO <роль>`. Гранты явные в каждой миграции.

**Владение данными офлайн-точки** (ADR-0014): у каждой таблицы указано, кто владеет строками офлайн-точки.
- **облако → точка** — строки ведёт облако, на точку приходят лентой;
- **точка → облако** — строки создаёт точка, в облако приходят операциями;
- **локально** — не синхронизируются.

## Порядок миграций

Модель вводится миграциями по модулям, в том порядке, в котором модули реализуются. Каждая следующая миграция только добавляет таблицы или колонки (ADR-0006, только Up).

1. **Первая миграция (план B, задача 4)** — всё из [01](01-platform-org.md), кроме `license_keys`, `impersonations`, `operators`/`operator_credentials`: без них пока нет потребителей. Добавляются `tenants`, `tenant_settings`, `legal_entities`, `stores`, `employees`, `employee_credentials`, `roles`, `role_permissions`, `employee_stores`, `terminals`.
2. **Каталог и цены** — [02](02-catalog-prices.md).
3. **Склад** — [03](03-batches-warehouse.md).
4. **Касса** — [04](04-pos.md) + `audit_log`, `idempotency_keys`, `job_queue` из [06](06-sync-audit-billing.md).
5. **Закупки** — [05](05-purchasing.md).
6. **Платформа и биллинг**, затем **синхронизация** — остальное из [01](01-platform-org.md) и [06](06-sync-audit-billing.md).

## Что уточнить в ADR при следующей правке

- **ADR-0014:**
  - в ленте «облако → точка» не хватает: `drug_reference` и `services` (ADR-0013 §6), `dictionary_values`, `payment_methods`, `legal_entities`, `categories`, `tenant_settings`;
  - долг поставщику по приходу офлайн-точки заводит облако при применении `document.posted`;
  - заказы, оплаты поставщикам и заявки на перемещение ведутся только в облаке;
  - операции синхронизации для отмены проведения нет — на офлайн-точке она запрещена до уточнения.
- **ADR-0013:** в список классов добавить `service_requests` (tenant-export), `store_billing` (platform), `legal_entities` (tenant).
- **Глоссарий:** «Юрлицо сети» (legal entity), «Бизнес-дата» (business date), «Счётчик номеров» (document counter).

## Вопросы заказчику

Модель уже содержит допущения по всем вопросам ниже. Ответ заказчика может изменить колонки, но не структуру таблиц.

| № | Вопрос | Допущение в модели |
|---|---|---|
| 1 | Состав полей рецепта ПКУ, хранится ли «документ покупателя», срок хранения журнала ПКУ | Поля рецепта — `jsonb` в `controlled_sale_records`; хранение — как аудит (≥ 3 лет) |
| 2 | Розничная цена штуки при делении упаковки: формула и округление | `ceil(цена упаковки / штук в упаковке)` |
| 3 | Излишек инвентаризации: в какую партию и по какой цене | Новая партия `inventory_surplus` по последней закупочной цене товара на точке, срок — ближайший из партий товара на точке |
| 4 | Пересчёт скидки при частичном возврате: формула и округление | Скидка пересчитывается по порогам от оставшейся суммы; к возврату — разница, округление в пользу аптеки |
| 5 | Нумерация: префиксы для возврата поставщику, начальных остатков, заявки, чека, возврата покупателя | Префиксы `ВП`, `НО`, `ЗП`, чек — число без префикса, возврат — `ВЗ` |
| 6 | Центральный склад: отличия от аптеки (касса, смены, биллинг) | `stores.kind = 'warehouse'`: без терминалов и смен, в биллинг не входит |
| 7 | Одна сеть на нескольких юрлицах — нужно ли делить выгрузку 1С по юрлицу | Выгрузка 1С — по юрлицу |
| 8 | Распределение оплат поставщику по приходам, предоплаты | Оплата распределяется на ранние по сроку приходы, можно выбрать вручную; предоплата — нераспределённый остаток оплаты |
| 9 | Возврат покупателю товара из партии с истёкшим сроком | Возврат в ту же партию; продать её касса не даст — далее списание |
| 10 | Минимальный остаток: на товар в сети или на товар в точке | На пару «товар × точка» (`store_products.min_stock_pieces`) |
| 11 | Часовой пояс сети, глубина ввода документов задним числом, закрытие периода после выгрузки в 1С | `Asia/Dushanbe`; ограничений глубины и закрытия периода в MVP нет |
| 12 | Статусы счёта платформы, связь платежа со счётом, цены услуг, стоимость ключа офлайн-точки | Счёт `issued` / `paid` / `cancelled`; платёж может ссылаться на счёт; цена услуги — в каталоге `services` |
| 13 | Состав реквизитов тенанта для счёта и реквизитов поставщика | Юрлицо, ИНН, адрес, банк — текстовыми полями |
| 14 | Нужна ли выручка в статистике оператора (АП 6) | Нет: витрины без сумм позиций (ADR-0013); только число чеков и активность |
| 15 | Отказ от мультивалютности (ADR-0016), «от имени» только просмотр (ADR-0008), урезанный функционал офлайн-точки (ADR-0014) | Модель следует ADR |
