# ADR-0005: Выбор Docker для контейнеризации

- **Статус:** accepted
- **Дата:** 2026-09-29
- **Авторы:** Zohid Saidov (z.saidov@eskhata.com), команда проекта Pharmacy

## Контекст

ТЗ «Административный продукт» v2.1 (раздел 4) прямо требует: автономная (офлайн) точка —
это отдельно устанавливаемая копия клиентского продукта на одном ПК точки, поставляемая как
**Docker-образ** с автозапуском (Windows 10/11 + WSL2 или Linux, от 8 ГБ ОЗУ), включая
вариант установки с флеш-накопителя без интернета. Функционал нужен к волне 3 первого
релиза; контейнерный деплой облачной части также желателен, но не обязателен.

## Рассмотренные варианты

1. **Docker (Docker Engine / Docker Desktop + docker compose)** — де-факто стандарт;
   заложен в ТЗ и в требования к ПК точек; воспроизводимая поставка «БД + приложение»
   одним образом; работает на Windows (WSL2) и Linux. Минус: Docker Desktop на Windows
   имеет лицензионные условия для коммерческого использования (проверить; альтернатива —
   Docker Engine в WSL2 напрямую).
2. **Нативная установка без контейнеров** (Node.js + PostgreSQL как службы Windows/Linux
   на ПК точки) — хрупкая установка и обновление на разношёрстных ПК аптек, ручная настройка
   каждой машины, сложный откат версий; противоречит тексту ТЗ и делает нереалистичным
   «установка ≤ 30 минут» (критерий приёмки W3-01).
3. **Подман/иные контейнерные движки (Podman и т.п.)** — те же выгоды; меньше распространён
   на Windows; не даёт преимуществ перед Docker.

## Решение

Выбран Docker (Engine + compose) для: (а) дистрибутива офлайн-точки — обязательное
требование ТЗ, волна 3; (б) опционально — контейнерного деплоя облачной части.
Вариант без контейнеров отклонён как противоречащий ТЗ и операционно нереалистичный для
десятков независимых ПК в аптеках.

## Последствия

- Положительные: воспроизводимая поставка и обновление офлайн-точек; идентичность
  окружений (точка/облако/разработка); соответствие критериям приёмки W3-01.
- **Отрицательные (обязательно):**
  - требование к ПК точек: 64-бит ОС с WSL2/Docker и 8+ ГБ ОЗУ — часть машин заказчиков
    может потребовать апгрейда;
  - лицензирование Docker Desktop для Windows в коммерческой среде — нужна проверка
    и, возможно, переход на Docker Engine в WSL2;
  - практик эксплуатации контейнеров у команды нет — реестр образов, сканирование
    уязвимостей, правила обновления базовых образов придётся определить в рамках этого
    решения;
  - обновление офлайн-точек остаётся ручным (через удалённый доступ, из ТЗ) — Docker
    упрощает, но не автоматизирует его.

Управление решениями — ADR-0011 (проект вне банковского контура).
