# Аутентификация, часть 1 — ядро и вход по паролю (облако). План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сотрудник входит в `apps/api` по логину, телефону или e-mail и паролю, получает JWT в HttpOnly-cookie, а каждый запрос проходит через неизменяемый контекст и guard'ы с правами ADR-0018.

**Architecture:** `SessionMiddleware` проверяет JWT (`@nestjs/jwt`, HS256, `kid`), одним `MGET` достаёт запись сессии и версию прав из Redis и собирает замороженный `RequestContext`; глобальные guard'ы (`AuthGuard`, `CsrfGuard`, throttler, `PermissionsGuard`, `FreshAuthGuard`) только решают. Сеть находится по глобально уникальному идентификатору через резолвер `resolve_login` (`SECURITY DEFINER`, ADR-0013), пароль проверяется scrypt + HMAC-pepper в `TenantDatabase.withTenant`.

**Tech Stack:** NestJS 11 (Express), TypeScript strict, Kysely + `pg`, node-pg-migrate (только Up), PostgreSQL 17, Redis (node-redis), `@nestjs/jwt`, `@nestjs/throttler`, `helmet`, `cookie-parser`, Jest (`@swc/jest`), Nx.

**Spec:** `docs/superpowers/specs/2026-10-02-auth-design.md` (разделы 2–7, 11, 12, 14, 15 — часть 1).

## Global Constraints

- Самописной криптографии нет: только `node:crypto` (scrypt, HMAC-SHA-256, `randomBytes`, `timingSafeEqual`) и `@nestjs/jwt` (ADR-0011).
- scrypt: `N=2^15, r=8, p=3`, `keylen` = 32, соль 16 байт, `maxmem` = 67108864; pepper — `HMAC-SHA-256(pepper, secret)` до scrypt; PHC `$scrypt$ln=15,r=8,p=3$<salt>$<hash>` (base64 без `=`).
- JWT: только `HS256`; при проверке `algorithms: ['HS256']`, `issuer: 'pharmacy-api'`, `audience` контура; `kid` в заголовке; claims — `jti`, `sub`, `tid`, `aud`, `iss`, `iat`, `exp`; прав и ПДн в токене нет.
- Ключи JWT и pepper — ≥ 32 байт, из env; никогда в логах, аудите, URL, ответах. Пароль, токены и коды — тоже.
- Cookie: `__Host-sid=<JWT>; Secure; HttpOnly; SameSite=Strict; Path=/; Max-Age=<абсолютный срок>`; CORS не включается (ADR-0008).
- Ответы входа не различают «нет идентификатора» и «неверный пароль» (код и время — фиктивный хеш).
- Каждый маршрут — `@RequirePermission('<модуль>:<действие>')` из `libs/shared/domain`, `@Authenticated()` (любой вошедший: своя сессия и профиль) или `@Public()`; запрет по умолчанию.
- Данные тенанта — только через `TenantDatabase` (RLS по `app.tenant_id`); до известного тенанта — только резолверы `ContextResolvers`.
- Ошибки — `application/problem+json` с `code` из таблицы спецификации, раздел 11.
- Значения по умолчанию: `SESSION_IDLE_TIMEOUT_MIN_SECONDS` 300, `SESSION_IDLE_TIMEOUT_MAX_SECONDS` 43200, `SESSION_ABSOLUTE_TTL_SECONDS` 43200, `STEP_UP_MAX_AGE_SECONDS` 900, `LOGIN_MAX_FAILURES` 5, `LOGIN_LOCK_SECONDS` 900 (повторно — 3600), `ACTIVATION_CODE_TTL_HOURS` 72.
- Новые npm-зависимости — точные версии, совместимые с Nest 11 и Node 22/24; лицензии MIT/BSD/Apache-2.0 проверяются `npm view <pkg> license` перед добавлением.
- Миграции — `apps/api/migrations/*.sql`, только Up; класс каждой новой таблицы — в `table-classes.ts`; после миграции `npx nx run api:db-types`.
- Код — английский, общение и документы — русский; Conventional Commits; полный `npm run check` запускает пользователь.

## Review Focus

1. **Повтор и гонка входа** — два одновременных входа с неверным паролем на границе лимита: блокировка наступает ровно после 5-й неудачи, а не «иногда на 6-й». Тест: `LoginLimiter` — конкурентные `recordFailure` (Task 9).
2. **Токен после выхода или блокировки** — старый JWT с действующей подписью после `DELETE /sessions/current` или блокировки сотрудника: 401, а не данные. Тест: e2e «logout invalidates the token», «blocked employee loses the session» (Task 12).
3. **Телефон в разных записях** — `+992 93 123-45-67`, `931234567`, `992931234567` находят одного сотрудника; мусор вроде `12` не уходит в резолвер. Тест: `normalizeIdentifier` (Task 8).
4. **Секция `audit_log` отсутствует** — вставка в месяц без секции должна падать громко, а не терять событие. Тест: интеграционный «insert outside partitions fails» (Task 4).
5. **Контекст изменяют после middleware** — код сервиса делает `Object.assign(getRequestContext(), …)`: должен получить TypeError, а не тихо сменить тенанта. Тест: `request-context.spec` «context is deeply frozen» (Task 6).
