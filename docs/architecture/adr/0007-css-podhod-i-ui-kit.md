# ADR-0007: CSS-подход и основа UI-кита libs/ui — Tailwind CSS v4 поверх токенов `--ph-*`, примитивы Base UI, стартовый код shadcn/ui

- **Статус:** proposed
- **Дата:** 2026-09-29
- **Авторы:** Zohid Saidov (z.saidov@eskhata.com), команда проекта Pharmacy (черновик подготовлен с помощью AI)

## Контекст

`apps/web` (касса, склад, кабинет владельца) и `apps/admin` — Next.js в режиме static export
(`output: 'export'`, без SSR и серверного рантайма, ADR-0004) с общим UI-китом `libs/ui`
(ADR-0002). Касса работает на сенсорных POS-экранах от 10″ (1280×800, масштаб Windows 125 %),
часто на слабом железе, а на офлайн-точке делит CPU с Docker, API и PostgreSQL (ADR-0005):
отзывчивость на скан штрих-кода (USB HID) и операция ≤ 1 сек — главный бюджет; плюс печать
чеков 58/80 мм через печать браузера, RU/TJ (глифы `cyrillic-ext`), WCAG 2.1 AA, сенсорные цели
44/48/64 px, никаких CDN (офлайн-точки, закрытый список внешних вызовов). Уже определён
источник истины дизайна — трёхуровневые токены CSS custom properties `--ph-*` в `libs/ui`
(скил `ui-standards-tokens`); не решено, чем писать стили компонентов и на каких примитивах
строить интерактивные компоненты. Срок — запуск волны 1 до конца 2026 года, т.е. около трёх
месяцев на десятки экранов склада, закупок и отчётов (плотные таблицы, формы) при одной
небольшой команде.

## Рассмотренные варианты

Решение принимается по двум независимым осям. Факты о версиях проверены на 2026-09-29
(npm-реестр, официальные changelog); оценки веса — ориентировочные, подтверждаются замером.

**Ось А — стилизация**

1. **CSS Modules + токены `--ph-*`** — встроено в Next.js, ноль новых зависимостей, ноль
   рантайма, скилы уже описывают этот вариант как базовый. Плюсы: полный контроль, привычный CSS,
   печать чека и сложные сетки пишутся естественно. Минусы: на каждый экран — отдельный
   `.module.css` и имена классов; раскладки десятков экранов склада/отчётов пишутся заметно
   медленнее; нет готового стартового кода компонентов (shadcn/ui и аналоги рассчитаны на
   Tailwind); дисциплину шкал контролирует только grep-аудит.
2. **Tailwind CSS v4 поверх тех же токенов** (актуально 4.3.x, MIT; `@theme inline` только
   ссылается на `var(--ph-*)`, дефолтная тема сброшена) — работает только на этапе сборки
   (`@tailwindcss/postcss`), рантайма и CDN нет; итоговый CSS — один кэшируемый файл.
   Плюсы: быстрая вёрстка плотных экранов, утилиты генерируются только из наших токенов (вне
   шкалы класса просто нет), совместим со стартовым кодом shadcn/ui, готовый скил
   `tailwind-patterns`. Минусы: новая зависимость и второе средство стилизации рядом с
   CSS Modules (правила каскадных слоёв), «длинные className», запрет arbitrary values требует
   контроля; в январе 2026 Tailwind Labs сократила большую часть инженерной команды — риск
   темпа развития проекта (релизы 4.x при этом продолжаются).
3. **CSS-in-JS с рантаймом (styled-components, Emotion)** — отклонён. styled-components с
   марта 2025 в режиме поддержки (только критические исправления); обе библиотеки опираются на
   React Context и в App Router требуют `'use client'` и registry для пререндеринга статического
   экспорта, иначе вспышка нестилизованного контента. Главное — генерация и вставка стилей во
   время рендера — это лишняя работа главного потока на каждый скан на слабом POS (INP).
4. **Zero-runtime CSS-in-TS (vanilla-extract, Panda CSS)** — типизированные токены без рантайма,
   совместимы с RSC. Отклонён: у команды нет опыта, интеграция с Next.js/Nx — через
   сторонние плагины сборки (дополнительный риск при обновлениях Next.js), экосистема готовых
   компонентов заметно меньше, выгода перед вариантом 2 при наших токенах-переменных невелика.

**Ось Б — примитивы компонентов**

5. **Собственные компоненты с нуля** — полный контроль и минимальный вес. Отклонён как основной
   путь: доступные Select/Combobox/Menu/Popover/Tabs/Toast с корректной клавиатурой, фокусом и
   ARIA — месяцы работы и постоянный источник a11y-дефектов; при сроке «три месяца» нереалистично.
   Остаётся для доменных компонентов (см. «Решение»).
6. **Radix UI Primitives** (MIT, сопровождает WorkOS) — зрелые, широко используемые, релизы
   идут. Минусы: нет Combobox/Autocomplete и NumberField (нужны для поиска товара и ввода
   количества), развитие идёт медленнее, чем у Base UI; ключевые авторы перешли в Base UI.
7. **Base UI** (`@base-ui/react`, MIT; 1.0 — декабрь 2025, сейчас 1.8.x; команда MUI на полной
   ставке, в числе авторов — создатели Radix и Floating UI) — headless, стилей не поставляет,
   есть Dialog, Popover, Menu, Select, Combobox, Autocomplete, NumberField, Tabs, Toast, Field.
   Плюсы: активное развитие, модульный импорт, встроенных строк почти нет (RU/TJ — целиком
   наши словари). Минусы: библиотека моложе Radix — меньше лет промышленной эксплуатации и
   готовых ответов; API через `render`-prop отличается от привычного по Radix `asChild`.
8. **React Aria Components** (Adobe, Apache-2.0) — эталонная доступность и i18n. Минусы:
   встроенные словари на ~30 языков (русский есть, таджикского нет) заметно добавляют к бандлу
   без плагина оптимизации локалей; более многословный API; в экосистеме shadcn не
   поддерживается; опыта у команды нет.
9. **shadcn/ui как копируемый код** (MIT; не зависимость, а сгенерированный исходник в нашем
   репозитории; поверх Tailwind v4 и Base UI либо Radix — с июля 2026 Base UI по умолчанию,
   Radix поддерживается наравне) — быстрый старт с доступными компонентами, код полностью наш.
   Минусы: собственные имена токенов (`--primary`, `--background`, `--ring`), модификаторы
   прозрачности (`bg-primary/90`), `dark:` и размеры под мышь (36–40 px) — каждый компонент
   придётся портировать под `--ph-*` и сенсорные цели; обновления upstream не приходят сами.
   Применим только вместе с вариантом 2.
10. **Готовые kits: MUI (v9), Mantine (v9), Ant Design (v6)** — максимум готового (формы, даты,
    уведомления; у Ant Design и MUI X — сильные таблицы). Mantine — самая сильная альтернатива:
    MIT, стили на CSS Modules без рантайма. Отклонены как основа: свой дизайн-язык и своя система
    переменных параллельно `--ph-*` (нарушает единый источник истины токенов), слабый контроль
    над эргономикой кассы (размеры, фокус, поведение по касанию «зашиты» в чужой код), больший
    вес бандла на слабых POS; у MUI стилизация по умолчанию всё ещё на Emotion (рантайм),
    продвинутые функции MUI X DataGrid — коммерческая лицензия; Ant Design — тяжёлый бандл и
    характерный внешний вид; таджикской локали, по нашим данным, нет ни у одного из них.

## Решение

Выбираем **Tailwind CSS v4 поверх токенов `--ph-*` (ось А, вариант 2)** и **Base UI как
headless-основу интерактивных компонентов, со стартовым кодом shadcn/ui (Base UI-вариант),
портированным в `libs/ui` (ось Б, варианты 7 + 9)**. Определяющие аргументы: срок — готовые
доступные примитивы и стартовый код вместо написания Combobox/Dialog/Menu с нуля; вес и
отзывчивость — ноль рантайма стилей и модульный импорт примитивов; контроль над кассой —
весь визуальный код лежит у нас и строится только из наших токенов. Radix — запасной вариант
без смены подхода (shadcn поддерживает оба с одной абстракцией), если Base UI на пилоте
покажет блокирующие дефекты.

Правила применения:

- Токены `--ph-*` в `libs/ui` остаются единственным источником истины; `@theme inline` только
  отображает их в утилиты (`tailwind-patterns`, §2–3); arbitrary values, дефолтная палитра,
  модификаторы прозрачности и `dark:` запрещены.
- **CSS Modules остаются** для ограниченного круга: печать чека 58/80 мм (`ReceiptPrint`),
  сложные сетки (`PosLayout`), случаи, где утилиты нечитаемы; одно свойство элемента — одним
  средством. Глобальные стили — `libs/ui/src/styles` (токены, `base.css`, `:focus-visible`);
  reset заменяется preflight Tailwind.
- Нативные элементы, где их достаточно (`button`, `input`, `table`, `form`); Base UI — для
  составных виджетов (Dialog, Popover, Menu, Select, Combobox/Autocomplete, NumberField, Tabs,
  Toast, Tooltip). Доменные компоненты — свои: поле скана, экранная цифровая клавиатура,
  `MoneyInput`/`MoneyText` (дирамы), `BatchStatusBadge`, `ReceiptPrint`.
- shadcn-компоненты переносятся **по одному, по мере надобности**, с обязательным портом:
  токены shadcn → `--ph-*`, размеры → `--ph-size-touch-*`, удаление `dark:`/`/NN`/arbitrary
  values, строки → i18n; происхождение и лицензия MIT — в шапке файла и в
  `THIRD_PARTY_NOTICES` кодового репозитория. CLI shadcn — только на машине разработчика,
  результат проходит обычное ревью; сборка и CI во внешний реестр не ходят.
- Приложения (`apps/*`) используют компоненты `libs/ui`, а не Base UI напрямую.

Согласуемые этим ADR зависимости (версии фиксируются в корневом `package.json`, single-version
policy Nx; всё — только сборка/бандл, без сетевых вызовов в рантайме):

| Пакет | Назначение | Лицензия |
|---|---|---|
| `tailwindcss` 4.x, `@tailwindcss/postcss` | утилиты из токенов, dev/build | MIT |
| `@base-ui/react` 1.x | headless-примитивы | MIT |
| `clsx` + `tailwind-merge` 3.x (`cn`) | склейка классов; `tailwind-merge` настраивается под нашу тему | MIT |
| `class-variance-authority` | словари вариантов компонентов | Apache-2.0 |
| `lucide-react` | иконки (SVG в бандле, импорт по одной) — **спорно, можно вынести в отдельное решение** | ISC |

`stack.md` не меняется — это библиотеки уровня ниже слоёв стека (внутри Next.js/React/TypeScript);
согласование — этим ADR и проверкой лицензий (правила «AI usage rules» CLAUDE.md монорепо).

## Последствия

- Положительные:
  - быстрый старт экранов склада/отчётов и кассы: доступные примитивы (клавиатура, фокус-трап,
    ARIA) не пишем сами, стартовый код компонентов — за часы, а не недели;
  - ноль рантайма стилей и отсутствие CSS-in-JS: на скан штрих-кода не тратится работа на
    вставку стилей; CSS — один кэшируемый файл, одинаковый для облака и офлайн-точки;
  - единый источник истины дизайна сохранён: вне шкалы токенов утилиты не существует, темы и
    плотность (`[data-theme]`, `[data-density]`) работают переопределением `--ph-*`;
  - код UI-кита целиком наш (shadcn — копия, Base UI — только поведение), поэтому эргономика
    кассы и печать не упираются в чужие решения; есть запасной путь на Radix без смены подхода.
- **Отрицательные (обязательно):**
  - до семи новых npm-пакетов и их supply-chain-риски; обновления Tailwind 4.x и Base UI 1.x
    нужно отслеживать и проверять на экране кассы;
  - устойчивость Tailwind Labs после сокращения команды в январе 2026 — риск замедления
    развития и исправлений; уход с Tailwind позже дорог (утилиты размазаны по всей разметке),
    смягчение — токены остаются в CSS и переживают любую смену подхода;
  - Base UI моложе Radix (стабилен с декабря 2025): вероятны дефекты и изменения поведения в
    минорных версиях, меньше готовых ответов; команде нужно освоить `render`-prop API;
  - порт каждого shadcn-компонента — ручная работа (токены, сенсорные размеры, i18n, удаление
    `/NN` и `dark:`); upstream-исправления переносятся вручную, код может «разъехаться» с оригиналом;
  - два средства стилизации (Tailwind + CSS Modules) — нужны явные правила разграничения,
    иначе конфликты каскада (неслоёные CSS Modules побеждают утилиты) и спор на ревью;
  - длинные `className` хуже читаются, а запрет arbitrary values до появления линтера держится
    только на grep-аудите и ревью; `tailwind-merge` требует ручной настройки под нашу тему;
  - этот выбор не даёт ни плотной таблицы данных (сортировка, фиксированные колонки,
    виртуализация), ни выбора даты, ни библиотеки форм — это отдельные решения (ADR на
    таблицы/виртуализацию и формы), и до них экраны отчётов строятся на нативной `<table>` с
    пагинацией API; готовый kit (Mantine, Ant Design) закрыл бы это сразу — осознанно платим
    временем за контроль и вес;
  - порог входа для новых разработчиков выше, чем у «одного kit»: токены + Tailwind-тема +
    Base UI + правила порта.
- **Что обновить в скилах после перевода ADR в `accepted`** (сами скилы этим ADR не меняются):
  - `tailwind-patterns`:
    - description, «Контекст и ограничения», Iron Law, §12 «Tailwind без ADR» — заменить условие
      «только после ADR» ссылкой на ADR-0007 (решение принято);
    - §1 «Что должен решить ADR» — заменить зафиксированными ответами: версия 4.3.x, `cn` и CVA
      согласованы, UI-основа — Base UI + порт shadcn, preflight вместо `reset.css`;
    - §5 — основной пример `Button` переписать на `cn` + `cva` (оставить вариант без них как
      справочный), добавить готовую конфигурацию `extendTailwindMerge` под нашу тему;
    - новый раздел «Порт компонента shadcn/ui»: таблица соответствия токенов shadcn → `--ph-*`,
      сенсорные размеры, удаление `dark:`/`/NN`/arbitrary values, i18n строк, шапка с
      происхождением и лицензией, запрет прямого импорта Base UI из `apps/*`;
    - стилизация состояний Base UI (`data-*`-атрибуты: open, disabled, highlighted и т.п.) —
      через `@custom-variant` или разрешённые варианты по атрибутам; поправить grep §13, который
      сейчас примет варианты вида `data-[…]:` за запрещённые arbitrary values;
    - §12 anti-pattern «shadcn/Flowbite «чтобы быстрее»» — уточнить: shadcn (Base UI) — только
      через порт, Flowbite/MUI/Mantine/прочие kits — по-прежнему только через новый ADR;
    - §13 Verify — добавить проверку фиксированных версий и отсутствия импортов `@base-ui/react`
      в `apps/*`.
  - `ui-standards-tokens`:
    - «Контекст и ограничения» и схема архитектуры токенов — убрать «до ADR — CSS Modules»,
      зафиксировать: основной способ — утилиты Tailwind из `--ph-*`, CSS Modules — для печати
      чека, сложных сеток и перечисленных исключений; UI-библиотеки: Base UI и порт shadcn
      согласованы ADR-0007, прочие — только через ADR;
    - `reference/ui-design-tokens.md` §0 и §10 — структура `libs/ui/src/lib` с портированными
      компонентами, `reset.css` не подключается (preflight), пример на CSS Modules пометить как
      пример для печати/сложных раскладок, добавить ссылку на Tailwind-вариант;
    - `reference/ui-accessibility-patterns.md` — паттерн `Modal` на нативном `<dialog>` согласовать
      с Base UI Dialog (управление начальным и возвратным фокусом в поле скана — сверить с API
      Base UI); правило: размеры shadcn по умолчанию (36–40 px) ниже `--ph-size-touch-min` и
      обязаны быть переопределены;
    - `reference/ui-localization-formatting.md` — все `aria-label`/служебные строки примитивов
      (закрыть, очистить, «ничего не найдено») — через i18n RU/TJ, без английских дефолтов из
      стартового кода shadcn;
    - раздел «Открыто / согласовать» — отметить решённое (CSS-подход, UI-основа, иконки — если
      `lucide-react` принят), Machine Enforcement — ссылка на проверки Tailwind.
  - Попутно (вне двух названных скилов): в `web-performance-optimization` снять пометку
    «Tailwind — не в stack.md, только после ADR» и добавить в бюджет бандла контроль веса
    импортов Base UI/иконок; агент `ui-standards-expert` — дополнить чек-лист правилами порта.
