# ADR-0024: Анимация публичного сайта — библиотека `motion`, только в `apps/site`

- **Статус:** accepted (2026-11-02, архитектор проекта — APPROVAL.md)
- **Дата:** 2026-11-02
- **Авторы:** Zohid Saidov (z.saidov@eskhata.com), команда проекта Pharmacy (текст подготовлен с помощью AI)
- **Принимает:** архитектор проекта (docs/architecture/APPROVAL.md)
- **Спецификация:** `docs/superpowers/specs/2026-11-02-public-site-redesign-design.md`

## Контекст

Публичный сайт (`apps/site`, ADR-0023) собран из кита `libs/ui`, в котором нет анимации. Пользователь (2026-11-02):
сайт выглядит «очень простым», нужен «премиум», «не вижу анимации». В редизайне сайту нужны:
- появление секций и элементов при прокрутке, с задержкой по порядку;
- параллакс и закрепление секций, привязанные к прокрутке;
- пружинная физика при наведении и нажатии.

Ограничения:
- все эффекты отключаются при `prefers-reduced-motion: reduce`;
- никаких `window.addEventListener('scroll')` и перерисовки React на каждый кадр прокрутки;
- касса, склад и админка анимации не получают: их бюджет бандла и требования к слабым ПК (ADR-0009, ADR-0015) не
  меняются.

## Рассмотренные варианты

1. **Только CSS:** переходы, `@keyframes`, `animation-timeline: view()` и `IntersectionObserver` своим кодом. Плюс —
   ноль зависимостей. Минус — нет пружин; scroll-driven animations в Firefox на 2026-11 ещё за флагом, нужен свой
   запасной путь. Закрепление и параллакс — ручной код с теми же ошибками, которые библиотеки уже исправили.
2. **`motion` (бывший Framer Motion) 14.4.0** — MIT, зависимости `framer-motion`, `motion-dom`, `motion-utils` (одни
   авторы) и `tslib`. React 19 поддерживается. Есть `whileInView`, `useScroll`, `useTransform`, пружины,
   `useReducedMotion`. Значения прокрутки идут мимо рендера React.
3. **GSAP + ScrollTrigger** — сильнее для сложной прокрутки, но лицензия не OSI (стандартная лицензия GSAP) и
   императивный API рядом с React.

## Решение

Выбран вариант 2.

1. Зависимость `motion` — только у `apps/site`, версия закреплена точно: `14.4.0`. Это последний выпуск, которому на
   дату решения не меньше двух недель (вышел 2026-10-19). `libs/ui`, `apps/web` и `apps/admin` её не импортируют. Граница
   проверяется так: в `package.json` этих проектов `motion` нет, и сборка web и admin не тянет пакет.
2. Импорт — только `motion/react`. Анимированные компоненты — клиентские «листья» (`'use client'`) в слоях FSD сайта.
   Серверные страницы остаются серверными: SEO и ISR (ADR-0023) не меняются.
3. Каждый анимированный компонент проверяет `useReducedMotion()`: при `reduce` элемент сразу виден, без движения,
   параллакса и закрепления.
4. Анимируются только `transform` и `opacity`. Прокрутка — `useScroll` и `useTransform`, без `useState` на кадр.
5. Обновление версии — осознанным PR, с той же проверкой давности выпуска.

## Последствия

- **Положительные:** анимация, которую просил пользователь, без своего движка; доступность учтена; приложения
  продукта не затронуты.
- **Отрицательные:**
  - +4 пакета в `package-lock.json`, их обновления нужно отслеживать (цепочка поставок);
  - клиентский JS сайта растёт: ориентир — до 45 КБ gzip на страницу с анимацией;
  - анимация, привязанная к прокрутке, может мешать на слабых телефонах: эффекты лёгкие, параллакс — только на
    широких экранах.

Управление решениями — ADR-0011 (проект вне банковского контура).
