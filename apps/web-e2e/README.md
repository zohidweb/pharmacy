# web-e2e — сквозные тесты кассы (Playwright)

То, чего не проверить в jsdom (ADR-0009, ADR-0015): Service Worker, настоящий IndexedDB,
`navigator.locks`, обрыв сети, перезагрузка страницы.

```
npx nx e2e web-e2e                         # собирает web и гоняет все сценарии
npx playwright test -c apps/web-e2e/playwright.config.mts --project=chrome   # без пересборки
```

- Тестируется production-сборка `apps/web/out`; её раздаёт `serve-out.mjs` (Node без зависимостей,
  `http://127.0.0.1:4400`). Моков приложения в сборке нет.
- `/api/v1/*` отвечает `src/support/fake-api.ts` через `context.route` — типизирован контрактами
  `@pharmacy/shared-dto`, хранит ключи идемпотентности, умеет обрыв связи, «потерянный ответ» и
  ошибку следующего чека. Когда появится `apps/api`, те же сценарии переводятся на настоящий стек.
- Браузеры — установленные Chrome и Edge (`channel`), с CDN Playwright ничего не скачивается.
- Новая версия Service Worker для одного теста — cookie `e2e-sw-release` его контекста.

Сценарии: продажа онлайн с `Idempotency-Key`; продажа при обрыве и досылка; потерянный ответ —
без второй продажи; 409 → «Требует разбора»; 401 → пауза очереди; буфер и черновик после F5;
касса без сети после первого визита; новая версия SW не включается посреди чека; вход по PIN;
axe на шаге PIN и на кассе (0 нарушений serious/critical).
