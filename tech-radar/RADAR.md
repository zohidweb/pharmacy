# Технологический радар — Банк Эсхата

Версия: 1.3 | Дата: 2026-09-04 | Источник: https://gitlab.eskhata.com/zsaidov/ai-project-start.git

Правила:
- Использовать можно только технологии со статусом **Утверждено**. Если в категории отмечен
  **Приоритет** — при прочих равных выбирается он.
- **На утверждении** — использовать НЕЛЬЗЯ, пока Архитектурный комитет не переведёт в «Утверждено».
- **Запрещено** — использовать нельзя ни при каких условиях без исключения (см. EXCEPTIONS.md).
- Технология вне радара → процедура исключения: `tech-radar/EXCEPTIONS.md`.
- Кто и как обновляет радар: `tech-radar/GOVERNANCE.md`.

## Категории на утверждении

Использовать технологии этих категорий до решения Архитектурного комитета НЕЛЬЗЯ.
Нужна технология отсюда — подайте запрос по `EXCEPTIONS.md` (это ускорит утверждение всей категории).

| Категория | Статус | Примечание |
|---|---|---|
| Брокеры сообщений | На утверждении | |
| Управление секретами | На утверждении | |
| Криптография (библиотеки) | На утверждении | |
| Логирование и аудит | На утверждении | |
| Интеграционный слой (API gateway / ESB) | На утверждении | |
| CI/CD | На утверждении | |
| Контейнеризация | На утверждении | |
| Мониторинг | На утверждении | |
| Desktop-приложения | На утверждении | |
| Платформенные push-сервисы (FCM/APNs) | На утверждении | кандидат-правило: payload-минимизация — в push только идентификатор события, содержимое подтягивается по защищённому API; утверждает Архитектурный комитет + ИБ |

## Запрещено

| Что | Причина |
|---|---|
| Самописная криптография | используются только проверенные утверждённые библиотеки |
| Отправка клиентских данных / банковской тайны во внешние LLM и SaaS | требование ИБ |
| Прямой доступ к БД АБС (чтение или запись) | интеграции только через утверждённый API-слой |
| Внешние SaaS-БД для чувствительных данных | данные не покидают контур банка |
