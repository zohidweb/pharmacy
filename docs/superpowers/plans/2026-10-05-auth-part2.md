**Goal:** заведующий привязывает браузер кассы к точке, кассир входит на нём по PIN, PIN-сессия
живёт только вместе с cookie устройства и отзывается при отвязке.

**Architecture:** новый модуль `apps/api/src/app/terminals` поверх ядра части 1: device-cookie
`__Host-term` хранит секрет устройства, в БД — только SHA-256; резолвер `resolve_terminal` находит
сеть до контекста (ADR-0013). PIN-сессия — обычная запись `SessionStore` с `auth: 'pin'`,
`terminalId` и `terminalCredentialHash`; `SessionMiddleware` (шаг 4) сверяет device-cookie и флаг
отзыва терминала. Выдача сессии выносится из `SessionsService` в общий `SessionIssuer`.

**Tech Stack:** NestJS 11 (Express), Kysely + pg, node-pg-migrate (только Up), node-redis 6,
`@nestjs/jwt`, scrypt `PasswordHasher` части 1.

**Spec:** `docs/superpowers/specs/2026-10-02-auth-design.md` — §8 (терминал и PIN), §5, §7 (шаг 4),
§11 (ошибки, конфигурация). Часть 1 — в `main` (PR #8).

## Global Constraints

- Ветка `feature/auth-part2` от актуального `main`; Conventional Commits; подпись GPG не обходить.
- Секрет устройства — `randomBytes(32)`; в `terminals.credential_hash` — SHA-256 (32 байта); сам
  секрет, PIN, токены — никогда в логах, аудите, URL и ответах.
- Cookie устройства: `__Host-term; Secure; HttpOnly; SameSite=Strict; Path=/; Max-Age=34560000`
  (400 дней); при `AUTH_TEST_COOKIES=true` — `term` (как `sid` в части 1).
- `TERMINAL_PIN_MAX_FAILURES` = 10, `TERMINAL_PIN_WINDOW_SECONDS` = 900 → `423 terminal_locked`.
- Блокировка PIN сотрудника — на 3-й ошибке подряд (`pin_failed_attempts`), `423 pin_locked`.
- PIN — `checkPin(pin, tenant_settings.pin_min_length)` из `libs/shared/domain`
  (`format`/`length` → `422 pin_length`, `trivial` → `422 pin_trivial`); хеш — `PasswordHasher`.
- Бездействие PIN-сессии — `cashier_session_idle_min`, в границах `SESSION_IDLE_TIMEOUT_*`; охват и
  рабочая точка — только точка терминала.
- Новые коды ошибок — только из §11 спеки и решений ниже; ответы не раскрывают, существует ли
  сотрудник или терминал в другой сети.
- Новые зависимости не добавляются. Docker-контейнеры не создаются; `.env` не читается и не
  правится (только `*.example`).
- Проверки каждой задачи: `npx nx lint api`, `npx tsc -b apps/api/tsconfig.spec.json`,
  `npx nx test api`; для задачи с миграцией ещё `npx nx run api:migrate`, `npx nx run api:db-types`,
  `npx nx run api:integration`. `run-many` и `npm run check` запускает пользователь.

## Review Focus

Тестов нет, поэтому это список для финального ревью и ручной проверки (задача 6):

1. **Украденная cookie сессии без cookie устройства** — запрос с `sid` PIN-сессии, но без `term` или
   с `term` другого терминала → гость (401), сессия уничтожена.
2. **Отвязка во время работы кассира** — после `DELETE /terminals/{id}` следующий запрос PIN-сессии
   → 401; `GET /terminals/current` → `404 not_bound`; новый PIN-вход невозможен.
3. **Расширение охвата PIN-сессии** — смена версии прав перечитывает охват сотрудника: у PIN-сессии
   он остаётся «только точка терминала»; сотрудник потерял доступ к точке → сессия уничтожена.
4. **Гонка неудачных PIN** — параллельные неверные PIN не дают больше 3 попыток до блокировки
   сотрудника и больше 10 по терминалу (счётчики атомарны).
5. **Повторная привязка того же браузера с тем же именем** — старый терминал отзывается, новый
   создаётся без `409`/`500` на уникальности имени.

## Решения, принятые при составлении плана

- **P1.** Уникальность `terminals (tenant_id, store_id, name)` заменяется частичной
  `where revoked_at is null` — иначе повторная привязка с тем же именем (§8) падает.
- **P2.** Неизвестный, неактивный или не имеющий доступа к точке `employeeId` и отсутствие PIN →
  тот же `401 invalid_pin`, что и неверный PIN, и тоже считается неудачей терминала (не перебор
  списка, но и не подсказка). Выравнивание времени не нужно: список кассиров терминал и так видит.
- **P3.** `DELETE /terminals/{id}`: точку из пути не взять, поэтому сервис сам проверяет, что точка
  терминала в охвате, иначе `404 not_found` (не раскрывать чужие терминалы).
- **P4.** `POST /me/pin`: `currentPin` проверяется, только если PIN задан и не заблокирован; при
  блокировке или отсутствии PIN достаточно step-up паролем (так кассир снимает свою блокировку).
  Неверный `currentPin` → `422 invalid_current_pin` с `errors[{ field: 'currentPin' }]` и лимитом
  `pin-change:<tid>:<eid>` (5 / 900 с, как смена пароля в части 1).
- **P5.** Флаг отзыва терминала в Redis живёт `SESSION_ABSOLUTE_TTL_SECONDS` — дольше любой
  PIN-сессии, созданной до отзыва; источник правды — `terminals.revoked_at`.
- **P6.** Список терминалов сети для заведующего (`TenantTerminal`, `tenant-staff.ts`) — вне части 2
  (модуль сотрудников); отвязка доступна по id из `GET /me/terminals` и ответа привязки.
