# Шаг 2 вручную: C4-модель

Результат: `docs/architecture/c4/context.md`, `container.md`, `deployment.md`
(Lite — только context.md). Предусловие: заполненный stack.md.

1. **context.md** — Mermaid-диаграмма `C4Context`: система одним блоком, вокруг — роли
   пользователей и внешние системы из секции «Интеграции» stack.md. Ничего лишнего.
2. **container.md** — `C4Container`: приложения, сервисы, БД, кэш и связи между ними.
   Технологии контейнеров = технологии из stack.md, других быть не должно.
3. **deployment.md** — для серверных контейнеров таблица:
   «Контейнер | Среда | Контур сети | Примечание». Уточните у инфраструктуры, если не
   знаете контур. Для контейнеров, распространяемых через магазин/MDM (мобильные и
   десктоп-клиенты) — ОТДЕЛЬНАЯ таблица: «Приложение | Канал дистрибуции (Google Play /
   App Store / MDM банка) | Подпись (ответственный за ключи) | Мин. версия ОС | Политика
   обновления» — «Среда/Контур сети» для таких приложений не заполняются. Если в проекте
   есть оба вида контейнеров — пишите обе таблицы.
4. Каждая внешняя система на диаграммах обязана присутствовать в секции «Интеграции».
5. Больше 2 внешних систем? Заполните глоссарий по `templates/glossary-template.md` в
   `docs/architecture/glossary.md`.
6. Пример хороших диаграмм — `examples/demo-project/docs/architecture/c4/`.
   С другим AI-инструментом — используйте текст `.claude/commands/02-c4-model.md` как промпт.
7. Нужны картинки (для презентаций/комитета)? Каждый Mermaid-блок можно выгрузить в PNG:
   вставьте блок на mermaid.live → Export PNG, либо (при установленном Node и Chrome/Edge):
   сохраните блок в файл `context.mmd` и выполните
   `npx -y @mermaid-js/mermaid-cli -i context.mmd -o img/context.png -b white -p puppeteer-config.json`,
   где puppeteer-config.json = `{ "executablePath": "C:/Program Files/Google/Chrome/Application/chrome.exe" }`.
   В самом GitLab схемы из .md отображаются автоматически.
