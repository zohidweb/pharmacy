# ADR-0001: Выбор технологического стека

- **Статус:** accepted (исключения ADR-0003/0004/0005 утверждены 2026-09-29 как одноразовые —
  см. docs/architecture/APPROVAL.md)
- **Дата:** 2026-09-29
- **Авторы:** Zohid Saidov (z.saidov@eskhata.com), команда проекта Pharmacy

## Контекст

Pharmacy — мультитенантная SaaS-платформа автоматизации аптечных сетей (Full, Tier 2,
персональные данные, SLA 99,5% в рабочие часы, RTO 4 ч / RPO 24 ч). Нагрузка на старте:
3 тенанта, ~30 точек, до 50 одновременных кассиров, касса ≤ 1 сек, запас роста ×5.
Жёсткий срок — запуск волны 1 до конца 2026 года. Команда владеет TypeScript-стеком
(NestJS, Next.js, Angular), не владеет .NET/PHP. Обязательное требование ТЗ — автономная
офлайн-точка (Docker на ПК аптеки). Полный профиль — docs/architecture/stack.md.

## Рассмотренные варианты

1. **Стек строго из радара: C#/.NET + Angular + PostgreSQL** — нулевой риск по процессу,
   но команда не владеет .NET: переобучение при сроке «до конца года» срывает срок и снижает
   качество продуктовой системы Tier 2.
2. **TypeScript-стек команды: NestJS + Next.js + PostgreSQL + Redis** — немедленный старт,
   сквозной TypeScript и общие типы в монорепо; но бэкенд и фронтенд-фреймворк вне радара —
   требуются исключения (ADR-0003, ADR-0004), решение Архитектурного комитета, SLA 3 раб. дня.
3. **Гибрид: NestJS + Angular (Приоритет радара)** — фронтенд без исключения, команда Angular
   владеет; минус — две экосистемы (React-паттерны NestJS-команды против Angular), меньше
   переиспользования в монорепо. Отклонён командой в пользу варианта 2; остаётся запасным
   при отказе комитета по Next.js.

## Решение

Выбран вариант 2 (решение команды, оформлено через процедуру исключений):

| Слой | Технология | Статус в радаре |
|---|---|---|
| Backend | NestJS (Node.js, TypeScript) | вне радара — ожидает ADR-0003 |
| Frontend (web, admin) | Next.js (React, TypeScript, SPA) | вне радара — ожидает ADR-0004 |
| БД | PostgreSQL | Приоритет |
| Кэш | Redis | Утверждено |
| API-стиль | REST | Утверждено |
| Аутентификация | Самописная (логин+пароль, PIN терминала) | Утверждено, не рекомендуется — согласование с ИБ |
| Контейнеризация (офлайн-точки) | Docker | категория «На утверждении» — ожидает ADR-0005 |
| Организация кода | Nx-монорепо `pharmacy-app` | тулинг вне категорий радара (см. ADR-0002) |

До апрувов исключений код на NestJS/Next.js не пишется; проектирование не блокируется.
Детальные обоснования по слоям — stack.md, раздел 3.

## Последствия

- Положительные: старт разработки без переобучения; сквозной TypeScript (общие DTO/типы
  между API и двумя фронтендами); PostgreSQL покрывает и облако, и офлайн-точку.
- **Отрицательные (обязательно):**
  - запуск волны 1 зависит от вердиктов комитета по трём исключениям (SLA 3 раб. дня;
    риск отказа по Next.js оценён как высокий — запасной план: React или Angular из радара);
  - прецедент Node.js в организации — экспертизу сопровождения придётся выращивать;
  - самописная аутентификация — полная ответственность команды за безопасность
    (хеширование, сессии, PIN, тайминги) и обязательный апрув ИБ на гейте;
  - supply-chain-риски npm-экосистемы — нужны lock-файлы и аудит зависимостей.

## Только для исключений из техрадара

- Альтернативы из радара и почему не подходят: см. отдельные ADR исключений —
  ADR-0003 (NestJS), ADR-0004 (Next.js), ADR-0005 (Docker); там же — поля апрувов.
  Данный ADR принимается после проставления апрувов в этих трёх документах.
- **Апрув Архитектурного комитета:** фиксируется в ADR-0003/0004/0005
- **Апрув ИБ**: по самописной аутентификации — на гейте архитектурного ревью (APPROVAL.md)
- Исход по EXCEPTIONS.md: см. ADR-0003/0004/0005
