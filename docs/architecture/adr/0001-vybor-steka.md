# ADR-0001: Выбор технологического стека

- **Статус:** accepted
- **Дата:** 2026-09-29
- **Авторы:** Zohid Saidov (z.saidov@eskhata.com), команда проекта Pharmacy

## Контекст

Pharmacy — мультитенантная SaaS-платформа автоматизации аптечных сетей (Full, Tier 2,
персональные данные, SLA 99,5% в рабочие часы, RTO 4 ч / RPO 24 ч). Нагрузка на старте:
3 тенанта, ~30 точек, до 50 одновременных кассиров, касса ≤ 1 сек, запас роста ×5.
Жёсткий срок — запуск волны 1 до конца 2026 года. Команда владеет TypeScript-стеком
(NestJS, Next.js, Angular), не владеет .NET/PHP. Обязательное требование ТЗ — автономная
офлайн-точка (Docker на ПК аптеки). Полный профиль — docs/architecture/stack.md.

## Рассмотренные варианты

1. **C#/.NET + Angular + PostgreSQL** — зрелая экосистема,
   но команда не владеет .NET: переобучение при сроке «до конца года» срывает срок и снижает
   качество продуктовой системы Tier 2.
2. **TypeScript-стек команды: NestJS + Next.js + PostgreSQL + Redis** — немедленный старт,
   сквозной TypeScript и общие типы в монорепо; выбор бэкенда и фронтенд-фреймворка
   детализирован в ADR-0003 и ADR-0004.
3. **Гибрид: NestJS + Angular** — команда Angular
   владеет; минус — две экосистемы (React-паттерны NestJS-команды против Angular), меньше
   переиспользования в монорепо. Отклонён командой в пользу варианта 2; остаётся запасным
   вариантом для фронтенда.

## Решение

Выбран вариант 2 (решение команды):

| Слой | Технология | Где зафиксировано |
|---|---|---|
| Backend | NestJS (Node.js, TypeScript) | ADR-0003 |
| Frontend (web, admin) | Next.js (React, TypeScript, SPA, static export) | ADR-0004 |
| БД | PostgreSQL | stack.md |
| Кэш | Redis | stack.md |
| API-стиль | REST | stack.md |
| Аутентификация | Самописная (логин+пароль, PIN терминала) | stack.md, ADR-0008 |
| Контейнеризация (офлайн-точки) | Docker | ADR-0005 |
| Организация кода | Nx-монорепо `pharmacy-app` | ADR-0002 |

Детальные обоснования по слоям — stack.md, раздел 3.

## Последствия

- Положительные: старт разработки без переобучения; сквозной TypeScript (общие DTO/типы
  между API и двумя фронтендами); PostgreSQL покрывает и облако, и офлайн-точку.
- **Отрицательные (обязательно):**
  - экспертизу эксплуатации и сопровождения Node.js-бэкенда придётся выращивать;
  - самописная аутентификация — полная ответственность команды за безопасность
    (хеширование, сессии, PIN, тайминги) и её обязательное ревью архитектором проекта;
  - supply-chain-риски npm-экосистемы — нужны lock-файлы и аудит зависимостей.
