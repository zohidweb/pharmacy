# Счётчики в меню — спецификация

Дата: 2026-10-15. Статус: утверждена архитектором 2026-10-15 (вместе с решениями автора E1–E11).

Связано:
- макет клиента (боковое меню: «Остатки 27», «Перемещения и заявки 1» — синие, «Цены и скидки 1» — красный);
- спецификации кабинета владельца `2026-10-14-owner-cabinet-design.md` (E4 — правило «мало на складе», E15 —
  предупреждение «ниже закупочной») и каталога и цен `2026-10-07-catalog-pricing` (предельная цена);
- ADR-0015 (web), ADR-0018 (права, охват, `finance:view-cost`).

## 1. Цель и критерии успеха

Меню подсказывает, где ждёт работа: что пора заказать, что пора принять, с какими ценами беда. Число стоит у пункта
меню, клик открывает экран уже отфильтрованным по этой работе.

Успех:
- «Остатки» показывает столько же товаров, сколько строк в новом фильтре «Надо заказать» экрана остатков за рабочую
  точку; у сотрудника с одной точкой (и в PIN-сессии) — столько же, сколько плитка «Мало на складе» на главной;
- «Перемещения и заявки» показывает перемещения в пути к точке; после приёмки число уменьшается;
- «Цены и скидки» показывает товары с проблемой цены; клик открывает экран цен с фильтром, где видно ровно их;
- нет права — нет числа; ноль — нет значка;
- числа не устаревают дольше минуты и меняются сразу после собственных действий сотрудника.

## 2. Решения, принятые при обсуждении (2026-10-15)

| # | Счётчик | Решение |
|---|---|---|
| N1 | «Остатки» (синий) | Мало на складе — надо заказать: число товаров ниже минимального остатка |
| N2 | «Перемещения и заявки» (синий) | Пришло перемещение — надо принять: число перемещений в пути к точке |
| N3 | «Цены и скидки» (красный) | Число товаров, у которых с ценой проблема — любая из трёх: цена выше предельной (нарушение), цена ниже закупочной (продажа в убыток), товар на остатке без цены (касса не продаст) |
| N4 | Куда ведёт «Остатки» | Новый фильтр экрана остатков «Надо заказать»: одна строка на товар — остаток, минимум, сколько не хватает; закончившиеся товары тоже в нём; правило то же, что у значка и главной. Существующий фильтр «Мало» (по партиям) не меняется |

## 3. Решения автора (на утверждение вместе со спецификацией)

| # | Тема | Решение |
|---|---|---|
| E1 | Один маршрут | `GET /api/v1/nav-counters?storeId=` в модуле `reports` (только облако): любой вошедший сотрудник (пароль или PIN). Каждое число — только с правом: «Остатки» — `inventory:view`, «Перемещения» — `inventory:receive` (видеть число, на которое нельзя ответить, бессмысленно), «Цены» — `pricing:view`. Нет права — поля нет в ответе. На офлайн-точке маршрута нет — значков нет |
| E2 | Какие точки | Значки считают рабочую точку из шапки: в web она выбрана всегда (без неё оболочка отправляет на вход), web передаёт её `storeId`, и клики открывают экраны по ней. API: `storeId` — точка охвата (иначе 403 `store_not_in_scope`); без него — все активные точки охвата (для других клиентов); PIN-сессия — всегда точка терминала |
| E3 | «Остатки» | Сумма `StockAlerts.lowStock` по выбранным точкам — то же правило, что у плитки главной и уведомления `low_stock` (E4 кабинета владельца): ассортимент точки (остаток или цена), активный товар с минимумом, остаток ниже минимума. Числа на главной и в меню совпадают |
| E4 | «Перемещения» | Перемещения `in_transit`, получатель которых — выбранная точка (в том числе перемещения закрытия другой точки — их тоже принимают). Заявки не считаются |
| E5 | «Цены» | Только аптеки (склад не продаёт: рабочая точка-склад даёт 0 — значка нет). Пары «товар × точка» (активный товар, аптека выборки), где есть хотя бы одна проблема; товар с двумя проблемами в одной точке — одна. Проблемы — предупреждения экрана цен: `above_max` (цена упаковки выше предельной), `below_cost` (включена настройка сети `warnBelowCost`, у сотрудника есть `finance:view-cost`, цена ниже последней закупочной цены упаковки — как экран цен сейчас) и новое `no_price` (у товара положительный остаток на точке, цены нет). Правило одно для счётчика и для фильтра экрана |
| E6 | Где правило цен | В модуле `pricing`: новый экспорт `PriceProblems` (счёт и выборка), остатки точки — через новый порт `StockedProducts`, который заполняет `inventory` (как `PurchasePrices`): `pricing` не зависит от `inventory`, который уже зависит от `pricing`. `reports` получает экспорты `inventory` (`StockAlerts`) и `pricing` (`PriceProblems`) |
| E7 | `no_price` на экране цен | Новое значение `PriceWarning` в `libs/shared/domain`; у пустой ячейки цены товара с остатком появляется пометка «Нет цены — касса не продаст» — только в колонках аптек |
| E8 | Клик | «Остатки» → `/stock?view=reorder&storeId=` — фильтр «Надо заказать» (N4): новый маршрут `GET /stock/reorder?storeId=` (модуль `inventory`, `inventory:view`) по правилу `StockAlerts.lowStock`, строка — товар (название, остаток, минимум, нехватка — в упаковках и штуках); «Перемещения» → `/transfers?incoming=1` — новый фильтр «К приёмке» (перемещения в пути к рабочей точке); «Цены» → `/pricing?problems=1&storeId=` — новый фильтр «Только с проблемами»: `GET /prices?problems=true&storeId=` возвращает товары с проблемой в этой аптеке (без `storeId` — в любой аптеке охвата). Экраны читают фильтр из адреса при открытии (как `catalog/view?id=`) |
| E9 | Свежесть | Ключ запроса web `['nav-counters', storeId]`: обновление раз в 60 с, пока видно меню и вкладка активна; сразу — после приёмки перемещения, изменения цен, проведения складских документов и смены точки. Ошибка запроса не показывается — значки просто не обновляются |
| E10 | Вид | `CountBadge` из `libs/ui`: `primary` (синий) у «Остатков» и «Перемещений», `danger` (красный) у «Цен»; ноль — значка нет; больше 99 — «99+»; подпись для экранного диктора («27 товаров мало на складе» и т. п.) |
| E11 | Касса | На маршрутах кассы, где меню скрыто (полноэкранный режим), запрос не выполняется |

## 4. Схема

Без миграции.

## 5. API

| Маршрут | Модуль | Право |
|---|---|---|
| `GET /nav-counters?storeId=` | `reports` | вошедший сотрудник; поля — по правам (E1) |
| `GET /prices?…&problems=true&storeId=` | `pricing` | `pricing:view` (как сейчас) |
| `GET /stock/reorder?storeId=` | `inventory` | `inventory:view` |

Ответ `NavCounters`: `{ lowStock?: number; incomingTransfers?: number; priceProblems?: number }`.

## 6. Контракт

- `libs/shared/dto`: `NavCounters`, `NavCountersQuery { storeId?: string }`; `PriceListQuery` + `problems?: boolean`,
  `storeId?: string`; `ReorderLine { productId, productName, stockPieces, minPieces, shortagePieces, piecesPerPack }`,
  `ReorderQuery { storeId?: string }`.
- `libs/shared/domain`: `PriceWarning` + `'no_price'`; `priceWarnings` получает признак остатка.

## 7. Web (`apps/web`)

- Маршрут клиента `navCounters.get` в `REAL_API_ROUTES`; мок по данным моков (минимумы, перемещения, цены).
- Боковое меню: значки по E10 у трёх пунктов; запрос по E9, E11.
- Экраны: «Остатки» — чип «Надо заказать» со своей таблицей (товар, остаток, минимум, нехватка) и `view` из адреса; «Перемещения» — фильтр «К приёмке» и `incoming`; «Цены» — фильтр
  «Только с проблемами» и `problems`, пометка `no_price`.
- Инвалидация `['nav-counters']` в мутациях E9.
- i18n RU/TJ: подписи значков, фильтры, пометка `no_price`.

## 10. Проверка

Новых автотестов нет (решение «тесты до MVP»). Существующие наборы — зелёные, включая `nx test api`; `npm run check`
— у пользователя.

Живая проверка на dev-API (curl и браузер, режим `partial`):
- точка A: товары ниже минимума, в том числе закончившийся — «Остатки» = строкам «Надо заказать» за A = плитке главной у
  сотрудника одной точки A; клик открывает этот фильтр;
- перемещение B → A в пути — у A 1, у B 0; после приёмки — 0;
- цена выше предельной, ниже закупочной (настройка включена / выключена, с правом себестоимости и без), товар на
  остатке без цены — каждое даёт +1; товар с двумя проблемами — 1; фильтр экрана цен показывает ровно эти товары;
  склад рабочей точкой — значка «Цены» нет, пометок «Нет цены» в колонке склада нет;
- сотрудник без `pricing:view` — нет поля `priceProblems`; кассир по PIN — числа точки терминала; чужая `storeId` — 403;
- клики открывают экраны с фильтрами; ноль — без значка; после приёмки и изменения цены число меняется сразу.
