# Запуск для QA: от первого оператора до первого чека

Пошагово: поднять систему, создать оператора платформы, сеть, владельца, точку, загрузить демо-данные, завести кассира,
привязать кассу и пробить чек. Весь путь проверен вживую 2026-10-23, около 20 минут; с PR #86 он проходит на `main`.

Данные в этой инструкции и в `demo-data/` синтетические. **Реальные данные аптек, сотрудников и пациентов в тестовую
среду не вводить** (CLAUDE.md, раздел «Security constraints»).

## 0. Версия

Всё нужное для QA уже в `main`: привязка кассы из web и скрытие офлайн-разделов (PR #86), reverse proxy (Caddy) и
стенд test по HTTPS (PR #75, раздел 1, вариант Б), лимиты попыток входа и запрет частых паролей (PR #82). Стенд,
собранный из более старого `main`, пересобрать; локальную dev-базу догнать миграциями (`npx nx run api:migrate`).

## 1. Где запустить

### Вариант А. Локально (Windows)

Нужны Docker Desktop, Node.js 24 (файл `.nvmrc`), Git, браузер Chrome или Edge.

```bash
npm ci
npm run dev:deps
npx nx run api:migrate
```

- `.env` — из `.env.example`. Ключи сессий и pepper — командой из CLAUDE.md (раздел «Local development secrets»).
- `npm run dev:deps` поднимает PostgreSQL и Redis в Docker.
- `api:migrate` применяет миграции к dev-базе.

API для браузера по `http://localhost` запускается с тестовыми именами cookie: Chrome не принимает cookie `__Host-` по
http. В PowerShell:

```powershell
$env:APP_ENV = 'test'; $env:AUTH_TEST_COOKIES = 'true'; npx nx serve api
```

Фронтенды — в двух отдельных терминалах:

```bash
npx nx run web:dev-api
```

```bash
npx nx run admin:dev-api
```

| Что | Адрес |
|---|---|
| Клиентский продукт (касса, склад, кабинет) | http://localhost:4200 |
| Админка оператора | http://localhost:4300 |
| API (проверка) | http://localhost:3000/api/v1/health → `{"status":"ok"}` |

**Не используйте `npm run dev`, `npx nx dev web` и `npx nx dev admin`:** они работают на встроенных моках, а не на API.
Всё, что видно в таком режиме, — демонстрационные данные.

### Вариант Б. Стенд test по HTTPS

Ближе всего к prod: Caddy, HTTPS, cookie `__Host-*`, собранные образы. Подробности — CLAUDE.md, раздел
«Environments».

```bash
npm run stack -- test init
npm run test-env:build
npm run test-env:up
```

- `init` создаёт `docker/env/test.env` без секретов: пароли и ключи — файлы `docker/secrets/test`, их создаёт `up`
  (ADR-0021). Файлы секретов не открывать и не пересылать. В env-файле, созданном раньше, `init` допишет новые
  переменные и перенесёт его секреты в файлы с прежними значениями — стенд и входы сохраняются; пока секреты в
  env-файле, `up` откажет. `WEB_ORIGIN` и `ADMIN_ORIGIN` файла, созданного до proxy, нужно поправить вручную на адреса
  ниже.
- `OPERATOR_ALLOW` — откуда пускают в админку: локально `private_ranges`, на общем стенде — адреса тестировщиков.
- Корневой сертификат Caddy доверяется один раз (команда — в CLAUDE.md), иначе браузер не примет cookie и вход не
  пройдёт.

| Что | Адрес |
|---|---|
| Клиентский продукт | https://pharmacy-test.localhost:8443 |
| Админка оператора | https://admin.pharmacy-test.localhost:8443 |

Скрипты из раздела 2 на стенде запускаются из образа `api` (`docker compose … run --rm --no-deps api node scripts/…`,
полная команда — в CLAUDE.md, раздел «Containers»), а не через `node --env-file=.env`.

## 2. Первый оператор платформы

Оператора создаёт скрипт, а не интерфейс. Он печатает одноразовый код активации, срок действия — 72 ч:

```bash
node --env-file=.env apps/api/scripts/create-operator.mjs --login qa-operator@example.test --name "Оператор QA"
```

Админка → ссылка «Первый вход» на странице входа (`/activate`): рабочая почта, код активации, новый пароль дважды.
Пароль — не короче 8 символов, с заглавной буквой и цифрой и не из частых: `Password1`, `Qwerty123`, `Apteka2024`,
`Dushanbe2026` не подойдут. Затем вход по почте и паролю — откроется «Дашборд».

## 3. Сеть и владелец

1. Админка → «Компании» → «Создать компанию» (`/companies/new`).
2. Заполнить: название сети, город, ИНН (9 цифр), ФИО и телефон владельца, логин владельца (латиница, цифры, точка,
   дефис — например `qa.owner`). Почта необязательна.
3. «Создать компанию» → на экране **код активации владельца**. Он показывается один раз, действует 72 ч; потерянный —
   выдаётся заново в карточке компании.
4. Web → «Войти по логину и паролю» → «Первый вход по коду активации» (`/activate`): логин владельца, код, пароль дважды
   (те же правила пароля, что у оператора).
5. Вход владельца → экран «Первая точка»: название, код точки (1–8 латинских букв и цифр, например `QA1` — входит в
   номера документов и потом не меняется), тип «Аптека», адрес для чека, юридический адрес юрлица → «Создать точку и
   продолжить». Откроется дашборд сети.

Код активации можно выдать и скриптом `apps/api/scripts/create-activation-code.mjs --login <логин>` (CLAUDE.md).

## 4. Демо-данные

Файлы — в [demo-data/](demo-data/README.md). Загружать в этом порядке, под владельцем:

| Шаг | Где | Файл | Результат |
|---|---|---|---|
| 1 | «Каталог» → «Загрузить из файла» (`/imports?kind=catalog`) | `01-catalog.xlsx` | 28 товаров, новая категория «Фиточаи» (мастер предложит «Создать») |
| 2 | «Поставщики» → «Загрузить из файла» (`/imports?kind=suppliers`) | `02-suppliers.xlsx` | 4 поставщика |
| 3 | «Ввод начальных остатков» → «Загрузить из файла» (`/imports?kind=opening-balances`), выбрать точку | `03-opening-balances.xlsx` | Черновик НО на 32 строки |
| 4 | «Ввод начальных остатков» → открыть черновик → «Провести» | — | Партии на складе, розничные цены точки |

Мастер загрузки: «Файл» → «Столбцы» (заголовки распознаются сами) → «Значения» (только для каталога) → «Проверка» →
«Загрузить». С ошибками не записывается ничего.

**Розничная цена.** Цена точки берётся из столбца «Розничная цена за упаковку» начальных остатков или считается по
наценке при первом приходе. Товар без цены касса не продаёт: «Цены и скидки» показывают «Нет цены — касса не продаст».
В демо-данных без цены специально оставлены два товара (см. demo-data).

## 5. Кассир

«Сотрудники и роли» → «Сотрудник»: ФИО, телефон, логин (`qa.cashier`), пароль, **PIN терминала** (не меньше 4 цифр;
простые вроде `1111` или `1234` запрещены), роль «Фармацевт-кассир», точка «Аптека № 1» → «Сохранить».

## 6. Привязка кассы

Касса — это браузер, привязанный к точке (cookie устройства). Кассир входит по PIN только на привязанном браузере.

1. Под владельцем или заведующим: «Сотрудники и роли» → вкладка «Терминалы» → «Привязать этот компьютер как кассу».
   Кнопка есть и на экранах «Касса» и «Смена» непривязанного браузера.
2. Точка, название кассы (например «Касса 1», в точке не повторяется) → «Привязать». Если пароль вводился давно,
   система попросит подтвердить его.
3. Сообщение «Компьютер привязан как касса … Чтобы работать на кассе, выйдите и войдите по PIN».

Привязка хранится в браузере и общая для всех адресов на `localhost`. Чтобы проверять две сети или две кассы, используйте
разные профили браузера. Новая привязка заменяет прежнюю (экран предупреждает).

## 7. Вход по PIN, смена, первый чек

1. Меню пользователя → «Выйти». Экран входа покажет «PIN кассира · Аптека № 1 · Касса 1».
2. Выбрать кассира, набрать PIN на цифровой клавиатуре → «Войти» → откроется «Касса».
3. «Открыть смену» → «Наличные на начало» (например, 100) → «Открыть смену». Номер смены — `СМ-QA1-2026-000001`.
4. Товар в чек: отсканировать штрихкод (сканер — USB-клавиатура; поле поиска выбирать не нужно), набрать штрихкод и
   Enter или нажать плитку товара. Пример — «Глюкометр Демо», штрихкод `2000000000282`, 250,00 с.
5. Способ оплаты «Наличные» → «Оплатить 250,00 с» → «Чек оплачен», чек `ЧК-QA1-2026-000001`; «Печать» — 80 или 58 мм.

На чеке строка «Фискальные реквизиты — после выбора ККМ» — это ожидаемо (фискализация на пилоте — заглушка, см.
«Границы пилота»).

## 8. Дальше

Сценарии для проверки — по разделам меню: приход от поставщика по заказу, перемещения между двумя точками, списание,
инвентаризация, возврат покупателю, закрытие смены и Z-отчёт, отчёты, роли и права, счета и услуги в админке.
Что сознательно не сделано и не считается дефектом — [02-granitsy-pilota.md](02-granitsy-pilota.md).

### Частые проблемы

| Симптом | Причина |
|---|---|
| Вход проходит, но сразу снова экран входа | API запущен без `APP_ENV=test` и `AUTH_TEST_COOKIES=true` (вариант А) |
| В интерфейсе «демо-данные» или чужие цифры | Запущен `npx nx dev …` или `npm run dev` — режим моков |
| Любое сохранение отклоняется с кодом 403 | `WEB_ORIGIN` / `ADMIN_ORIGIN` в `.env` не совпадают с адресом в браузере (проверка `Origin`) |
| Касса и смена предлагают привязать компьютер | Шаг 6 не выполнен в этом профиле браузера или привязку заменили в другом окне |
| «Нет цены — касса не продаст» | У товара нет розничной цены точки (раздел 4) |
| Код активации не принимается | Истёк срок 72 ч или код уже использован — выдать новый |
