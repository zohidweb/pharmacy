# Разбор UI-макетов и ТЗ «Клиентский продукт» v3.1 против принятых ADR

- **Дата:** 2026-09-30
- **Источники:** архив «UI mockups для клиентского продукта» (25 экранов `*.dc.html`, `kp-shared.js`,
  дизайн-система `neo-eskhata-ds`, скриншот формы заказа) и ТЗ «Клиентский продукт» v3.1 (сентябрь 2026)
  из того же архива. Архив в репозиторий не добавлен — хранится у команды.
- **Сверено с:** принятыми ADR-0001…0011, 0013, 0014, 0016; proposed — ADR-0012, 0015; модель
  авторизации ещё не решена.
- **Правило:** при расхождении макета или ТЗ с принятым ADR решающим считается ADR; расхождение
  выносится на согласование с заказчиком или на пересмотр ADR (решение архитектора проекта 2026-09-30).
- Разбор подготовлен с помощью AI.

## 1. Что в макетах (продукт «Дорухона»)

**Каркас.** Шапка: выбор точки (облачная/офлайн), «Синхронизировано 12:40 · Очередь: 0», уведомления,
меню пользователя (RU/TJ, профиль, выход), переключатель роли (только демо). Сайдбар из 8 групп: Главная ·
Касса (касса, смена, возвраты) · Склад (остатки, приход, перемещения, списание, возврат поставщику,
инвентаризация) · Закупки (заказы, поставщики) · Каталог (товары, цены) · Отчётность (отчёты, журнал) ·
Кабинет владельца (точки, сотрудники) · Настройки (настройки, офлайн-точка). Пункты фильтруются по роли.

| Экран | Ключевые UX-решения |
|---|---|
| **Касса (pos)** | Обычный и полноэкранный режим; одно поле «скан / название», плитки категорий; нет товара — аналоги по МНН. Партия FEFO со ссылкой на модалку выбора партии; просроченная партия заблокирована без обхода; поштучная продажа. Рецептурный — предупреждение; ПКУ — модалка с данными рецепта и документа покупателя, право «Продажа ПКУ». Смешанная оплата (наличные, карта через терминал банка, QR, NFC), сдача. Скидка по порогу суммы. Отложенные чеки — видны всем кассирам точки, удаляются при закрытии смены. Отмена — только до оплаты, после — возвратом. Предпросмотр чека 80/58 мм с местом под фискальные реквизиты ККМ |
| **Смена (shift)** | Внесение/изъятие с причиной; выручка по способам оплаты; сверка наличных (ожидается/факт/расхождение с причиной); карта/QR/NFC сверяются вручную с терминалом; журнал смены, Z-отчёт |
| **Возврат (return)** | Поиск по номеру или QR чека; без чека — по товару и дате, отдельное право; срок 14 дней — настройка сети; пересчёт скидки при падении суммы ниже порога; деньги — тем же способом, товар — в ту же партию; журнал ВЗ |
| **Приход (goods-receipt)** | Один приход = один поставщик и одна накладная; связь с заказом (частичная поставка); строки: партия, срок, количество, цена факт vs цена в заказе; розница пересчитывается по наценке как черновик; Черновик/Проведён; отмена проведения блокируется, если по партии были движения |
| **Инвентаризация** | Область: вся точка/категория/выборочно; касса продолжает работать («продано с начала» учитывается); проведение — излишки оприходовать, недостачи списать |
| **Перемещения (transfer)** | Заявки ЗП (Черновик/Отправлена/В работе/Частично/Выполнена/Отклонена) и перемещения ПМ (Черновик/В пути/Ждёт подтверждения/Принято); сборка по FEFO в пределах остатка; приёмка с фактом по строкам; расхождение — «Списать» или «Дослать» |
| **Списание, возврат поставщику** | Причины списания (просрочка, бой, брак, пересорт, расхождение при перемещении), «добавить просроченные партии»; ВП со ссылкой на приход или без, претензия, уменьшает долг поставщику |
| **Заказы, поставщики** | Заказ: Черновик/Подтверждён/Частично получен/Закрыт, «заполнить по дефициту» (минимум и расход за 30 дней), «оформить приход»; поставщики — долг, срок оплаты, просрочка, оплаты, история |
| **Каталог, карточка товара** | Поиск по наименованию/МНН/штрихкоду; RU/TJ наименования, МНН, категория, форма, дозировка, производитель, страна, единица, штук в упаковке, несколько штрихкодов, признаки «Рецептурный / ПКУ / Регулируемая цена» (предельная), наценка, минимальный остаток; импорт Excel; конфликты дублей с офлайн-точек; ценники 58×40 и 40×30 |
| **Цены (pricing)** | Цены по точкам с предупреждениями «выше предельной» (без запрета) и «ниже закупочной»; скидочные правила-пороги (сеть или точки, период); конфликты цен облако/точка |
| **Остатки (stock)** | По сети или точке; партии: Норма / Мало / Истекает / Нет в наличии / «Минус после слияния офлайн»; массовые действия (ценники, Excel) |
| **Отчёты, журнал** | 8 отчётов (продажи, остатки на дату, движение, долги, маржа по FEFO-себестоимости, кассиры, списания, журнал ПКУ); выгрузка в 1С (CommerceML, сопоставление по штрихкоду или артикулу); аудит — только чтение, «источник: оператор», «документ от … · введено …» |
| **Кабинет владельца** | Точки (Активно/Ожидает активации/Закрыта), мастер закрытия точки с передачей остатков; услуги (1С, фискализация, Telegram/SMS, агент печати, этикетки); биллинг за активную облачную точку; баннер «оператор входил от вашего имени» |
| **Сотрудники** | Сотрудники; роли — конструктор «модуль × действие» + спецправа + охват точек; терминалы (привязка/отвязка) |
| **Настройки, профиль, дашборд** | Параметры сети, наценки по категориям, справочники, уведомления; профиль — пароль, PIN, мои терминалы; дашборд — KPI, продажи по точкам, напоминания |
| **Офлайн-точка** | Последняя синхронизация, операций в очереди, срок ключа (после истечения новые операции блокируются), очередь в исходном порядке, конфликты дублей и цен, модули, доступные офлайн |
| **Вход** | Три шага: логин и пароль (сброс — владелец или заведующий) → выбор точки → PIN на привязанном терминале с выбором кассира, цифровая клавиатура 60 px |

## 2. Техника макетов — что переносим

- **Формат x-dc**: шаблоны с `{{ }}`, `<sc-if>`, `<sc-for>`; рантайм `support.js` загружает React 18,
  ReactDOM и Babel standalone **с CDN unpkg**. Бандл дизайн-системы (≈ 888 КБ) подключён, но в экранах не
  используется. Шапка, сайдбар, модалки и тосты скопированы в каждый файл; стили inline, много сырых hex и px.
- `kp-shared.js`: 45 SVG-путей иконок в стиле Lucide, словари RU/TJ ≈ 863 ключа (TJ наследует RU;
  21 ключ не переведён), демо-роли. Язык — в `localStorage`, `<html lang>` не выставляется.
- Не реализовано: печать (`@media print`, `@page`, `window.print`), обработчик сканера, клавиатурные
  сценарии, состояние «нет связи / буфер» облачной кассы. Сенсорные цели 32–44 px (норма проекта — касса
  ≥ 48, главные действия 64); только в полноэкранной кассе — 56 px.
- SSR-предположений нет — совместимо с ADR-0004 (static export).

| Решение | Что |
|---|---|
| **Переносим как есть** | Структуру экранов и навигации; UX-потоки (FEFO по умолчанию, блок просрочки, отложенные чеки, смешанная оплата, отмена проведения с блокировкой, двухшаговая приёмка перемещений, шаги входа и PIN); тексты RU/TJ как основу словарей; состав полей форм и отчётов |
| **Адаптируем** | Всё собираем заново на `libs/ui` (ADR-0007): `<dialog>`, Popover API, `DataTable`, `Combobox`; иконки — свой SVG-набор (пути Lucide — с атрибуцией ISC); токены `--ph-*` + Tailwind вместо inline-стилей; сенсорные цели 48/64; настоящая печать `ReceiptPrint`; `<html lang>`; деньги и даты через `libs/shared/util`; документы — маршруты `?id=` (ADR-0015); состояние «нет связи» и счётчик неотправленных операций |
| **Не переносим** | Рантайм x-dc и CDN (офлайн-точка без интернета); бандл, бренд, палитру и шрифт банка (раздел 3); валюты и курсы (ADR-0016); роль и права в `localStorage` — только сервер |

## 3. Дизайн-система и бренд — требует решения

Макеты построены на **Eskhata Neo** — дизайн-системе мобильного приложения Банка Эсхата: бренд-синий
`#0050C8`, статусные цвета, шрифт **TT Norms Pro** (TypeType). В файлах о лицензии шрифта есть только
слово «licensed», файла лицензии нет. Проект вне банковского контура (ADR-0011) — бренд, палитра и шрифт
банка в продукте для аптек без явного разрешения правообладателей не используются. Переносится
**структура** токенов (primary с ramp и состояниями, success/warning/error/info с подложками, текст,
линии, шкала отступов по 4, тени, motion 120/200 ms) — с пересчётом в OKLCH под свою палитру; конкретные
бренд-значения и шрифт — отдельное решение (открытый вопрос скила `ui-standards-tokens`).

## 5. Требования без ADR, влияющие на архитектуру

- Уведомления и напоминания (сроки годности, долги, истечение ключа, вход «от имени») — сущность и
  фоновые задачи-сканеры.
- Агент печати (ТЗ §5) — локальный компонент; вызов localhost из https-страницы (CORS, Private Network Access).
- Генерация штрихкодов и QR (ценники; QR на чеке для возврата) — свой код или ADR на библиотеку.
- Импорт/экспорт Excel (каталог, остатки, отчёты, журнал ПКУ), PDF счетов — библиотеки не выбраны.
- Язык сотрудника в профиле — i18n по ADR-0015 (proposed); профиль принадлежит облаку.
- Новые сущности: сопоставление номенклатуры для 1С и «артикул» (нет в глоссарии), отложенные чеки,
  заказ поставщику с частичной поставкой и платежи поставщику, наценка на товар/категорию, предельная
  цена, настройки сети и точки, история платежей в кабинете, алиасы дублей товаров.
- Справочники тенанта «фиксированные + свои» (ТЗ §10.1) при общем `drug_reference` оператора (ADR-0013).
- Отмена проведения при append-only движениях — сторнирующие движения и проверка последующих движений.

## 6. Входные данные для ADR об авторизации

- **Модули:** точки; услуги; оплата/счета; сотрудники и роли; терминалы; склад (приход, перемещение и
  приёмка, списание, инвентаризация, возврат поставщику, начальные остатки, остатки); закупки (заказы,
  поставщики, долги); касса и смены; ПКУ; цены; скидки; возвраты; 1С; отчёты; каталог; справочники;
  аудит; синхронизация; настройки.
- **Действия:** просмотр, создание, изменение, проведение, удаление; дополнительно — отмена проведения,
  приёмка перемещения с фактом, экспорт, запрос услуги.
- **Охват точек:** вся сеть, одна точка, список точек; выбор точки при входе; PIN-сессия — только точка
  терминала (ADR-0008).
- **Роли:** Владелец (вся сеть), Заведующий (свои точки), Фармацевт-кассир (своя точка, склад — чтение,
  закупочные цены скрыты), Бухгалтер (вся сеть, чтение, себестоимость, выгрузка в 1С), кастомные
  (пример — «Старший кассир»).
- **Спецправа:** продажа ПКУ; возврат без чека; выбор партии на кассе; цены — заведующий своей точки,
  владелец всех, кассир никогда; сетевые скидки — владелец, локальные — и заведующий; отмена проведения —
  заведующий или владелец; видимость себестоимости и маржи; выгрузка в 1С; привязка терминала —
  заведующий, отвязка — заведующий или владелец; ручная синхронизация; текст подвала чека — владелец;
  добавление значений в справочники; точки, услуги и оплата — только владелец.
- **Кто кого создаёт:** владелец — любых сотрудников сети; заведующий — кассиров своей точки (запрет
  выдавать права выше своих); сброс пароля — владелец или заведующий. В ТЗ не указано, кто создаёт
  кастомные роли; дубль товара решает то добавивший сотрудник (§10), то заведующий (§11) — ТЗ противоречит себе.
- **Ограничения из ADR:** step-up по паролю для сотрудников, ролей и терминалов (ADR-0008); «от имени» —
  только просмотр (ADR-0008, 0013); на офлайн-точке права и блокировки — после синхронизации (ADR-0014);
  складские записи по офлайн-точке из облака запрещены независимо от роли (ADR-0014).
