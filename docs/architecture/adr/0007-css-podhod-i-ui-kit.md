# ADR-0007: CSS-подход и UI-кит — Tailwind CSS v4 поверх токенов `--ph-*`, собственный кит `libs/ui` на нативной платформе

- **Статус:** proposed
- **Дата:** 2026-09-30
- **Авторы:** Zohid Saidov (z.saidov@eskhata.com), команда проекта Pharmacy (текст подготовлен с помощью AI)
- **Принимает:** архитектор проекта (docs/architecture/APPROVAL.md)

## Контекст

`apps/web` (касса, склад, закупки, отчёты, кабинет владельца) и `apps/admin` — Next.js в режиме
static export (ADR-0004) с общим китом `libs/ui` (ADR-0002). Касса работает на сенсорных POS-экранах
от 10″, часто на слабом железе, на офлайн-точке — рядом с Docker, API и PostgreSQL: отзывчивость на
скан штрих-кода и операция ≤ 1 сек — главный бюджет. Нужны печать чеков 58/80 мм, RU/TJ (глифы
`cyrillic-ext`), WCAG 2.1 AA, сенсорные цели ≥ 44 px (на кассе ≥ 48). Источник истины дизайна уже
определён — токены CSS custom properties `--ph-*` в `libs/ui` (скил `ui-standards-tokens`).
Поддерживаемые браузеры — **только Chrome и Edge последних двух версий** (C4 deployment), и на
облачных, и на офлайн-точках. Команда фронтенда работала с Tailwind CSS и с Angular Material /
PrimeNG. Решение команды: собственный UI-кит со своими стилями, без чужого дизайн-языка.

Нативная платформа целевых браузеров (проверено 2026-09-30): Popover API — Chrome/Edge 114+;
CSS anchor positioning — 125+; кастомизируемый `<select>` (`appearance: base-select`,
`::picker(select)`) — 135+; `<dialog>` с модальностью, `inert` и фокус-трапом — давно стабилен.

## Рассмотренные варианты

**Ось А — стилизация**

1. **CSS Modules + токены** — встроено в Next.js, ноль зависимостей; но вёрстка десятков плотных
   экранов склада и отчётов медленнее, а дисциплину шкал держит только аудит.
2. **Tailwind CSS v4 поверх токенов** — команда его знает; работает только на этапе сборки
   (`@tailwindcss/postcss`), рантайма нет; утилиты генерируются только из наших токенов (класса вне
   шкалы просто нет); готов скил `tailwind-patterns`. Минусы: новая зависимость сборки, длинные
   `className`, запрет arbitrary values нужно контролировать; в январе 2026 Tailwind Labs сократила
   большую часть инженеров — риск темпа развития (релизы 4.x продолжаются).
3. **CSS-in-JS с рантаймом (styled-components, Emotion)** — отклонён: вставка стилей во время
   рендера — лишняя работа главного потока на каждый скан; в App Router требует `'use client'` и
   registry; styled-components с 2025 года в режиме поддержки.
4. **Zero-runtime CSS-in-TS (vanilla-extract, Panda)** — отклонён: опыта нет, интеграция с Next/Nx
   через сторонние плагины, выгоды перед вариантом 2 при токенах-переменных мало.

**Ось Б — компоненты**

5. **Готовые киты (MUI, Mantine, PrimeReact, Ant Design)** — максимум готового (таблицы, даты,
   формы); PrimeReact близок к опыту команды с PrimeNG. Отклонены: чужой дизайн-язык и своя система
   переменных параллельно `--ph-*`, эргономика кассы (размеры, фокус, касание) зашита в чужой код,
   больший вес бандла на слабых POS; таджикской локали нет.
6. **Headless-примитивы (Base UI, Radix, React Aria) + свои стили** — доступность и поведение
   готовые, внешний вид наш. Отклонены решением команды: дополнительная зависимость рантайма и
   чужой API компонентов; для Chrome/Edge-only матрицы большая часть их ценности (позиционирование,
   модальность, фокус-трап) закрывается нативной платформой.
7. **shadcn/ui как копируемый код** — быстрый старт, но опирается на Radix/Base UI, свои имена
   токенов, `dark:` и размеры под мышь — каждый компонент пришлось бы портировать. Отклонён вместе
   с вариантом 6.
8. **Собственный кит полностью с нуля на нативной платформе** — ноль UI-зависимостей в рантайме,
   API и дизайн полностью наши, поведение опирается на `<dialog>`, Popover API, anchor positioning,
   кастомизируемый `<select>` и нативные элементы форм. Минусы: сложные виджеты (Combobox, DataTable,
   Toast) и их доступность — наша работа и наша ответственность.

## Решение

Выбраны **Tailwind CSS v4 поверх токенов `--ph-*` (вариант 2)** и **собственный UI-кит `libs/ui`,
написанный с нуля на нативной платформе Chrome/Edge (вариант 8)**.

Стили:

1. Токены `--ph-*` — единственный источник истины; `@theme inline` только отображает их в утилиты,
   дефолтная тема Tailwind сброшена (скил `tailwind-patterns`). Запрещены arbitrary values
   (`p-[13px]`), дефолтная палитра, модификаторы прозрачности (`/90`) и `dark:`; тема — через токены.
2. CSS Modules — только для печати чека 58/80 мм (`ReceiptPrint`, `@media print`) и сетки экрана
   кассы (`PosLayout`). Одно свойство элемента — одним средством.
3. Склейка классов — собственный `cx()` (без `clsx`/`tailwind-merge`); варианты компонентов —
   типизированные карты `Record<Variant, string>` (без CVA). Конфликты классов исключаются дизайном
   API: внешний `className` компонента — только для раскладки (отступы, позиция в сетке), не для
   цвета, типографики и размеров.

Компоненты:

4. База — нативные элементы и API платформы:
   | Компонент | Основа |
   |---|---|
   | Button, TextField, Checkbox, Radio, Switch, NumberField | нативные `button` / `input` + токены |
   | Select | `<select>` с `appearance: base-select` и `::picker(select)` |
   | Dialog, Drawer, ConfirmDialog | `<dialog>` + `showModal()` (модальность, фокус-трап, Esc) |
   | Menu, Popover, Tooltip, выпадающие панели | Popover API (`popover`, `popovertarget`) + CSS anchor positioning |
   | Combobox (поиск товара на кассе, выбор поставщика) | свой, по паттерну ARIA APG «Combobox with listbox popup» поверх Popover API |
   | Tabs | свой, по ARIA APG «Tabs» (roving tabindex) |
   | Toast | `aria-live`-регион + `popover="manual"` |
   | DataTable | свой: нативная `<table>`; сортировка, фильтры и пагинация — на сервере (limit/offset, API); виртуализации нет (ADR-0015) |
5. Доменные компоненты — свои: поле скана (клавиатурный поток сканера, ADR-0015), экранная цифровая
   клавиатура, `MoneyInput` / `MoneyText` (integer-дирамы), `BatchStatusBadge`, `ReceiptPrint`.
6. Иконки — собственный набор SVG-компонентов в `libs/ui` (~30–40 штук под кассу, склад и статусы).
   Исходники SVG можно брать из Lucide (ISC) копией, без npm-зависимости; происхождение и лицензия —
   в шапке файла и в `libs/ui/THIRD_PARTY_NOTICES.md`.
7. Доступность — требование к каждому интерактивному компоненту: чек-лист ARIA APG в шапке файла,
   тест клавиатурного сценария и автоматическая проверка axe (инструменты — ADR-0009); видимый фокус
   (`:focus-visible`) и сенсорные цели — через токены `--ph-size-touch-*`.
8. Приложения (`apps/*`) используют только компоненты `libs/ui`; своих «одноразовых» кнопок и
   диалогов в экранах нет.

Зависимости, согласуемые этим ADR (только сборка, без сетевых вызовов в рантайме):
`tailwindcss` 4.x и `@tailwindcss/postcss` (MIT). UI-зависимостей рантайма нет.

## Последствия

- Положительные:
  - один дизайн-язык на токенах `--ph-*`, эргономика кассы (размеры, фокус, касание) полностью наша;
  - ноль UI-кода в рантайме, кроме своего: минимальный бандл на слабых POS, CSS — один кэшируемый
    файл, одинаковый для облака и офлайн-точки;
  - нет зависимости от темпа и API чужих китов; обновления Next.js не ломаются о сторонние компоненты;
  - поведение Dialog/Popover/Select даёт браузер — меньше своего JS, чем в классическом «с нуля».
- **Отрицательные (обязательно):**
  - **объём работы**: Combobox, DataTable, Tabs, Toast, NumberField, поле скана — недели разработки
    при сроке запуска до конца 2026; кит становится отдельным потоком работ и может задержать экраны;
  - **доступность — целиком наша ответственность**: ошибки клавиатуры, фокуса и ARIA в своих
    виджетах — частый источник дефектов; без обязательных тестов (п. 7) риск высок;
  - **привязка к Chromium**: кастомизируемый `<select>` и часть поведения рассчитаны на Chrome/Edge
    135+. Если заказчику понадобятся Firefox/Safari или старые версии Chrome — нужны фолбэки
    (нативный `<select>` без кастомизации, JS-позиционирование) и пересмотр ADR;
  - нет готовой сложной таблицы (группировки, закрепление колонок, редактирование в ячейке): каждая
    такая функция — отдельная задача; при появлении требований — отдельный ADR (например TanStack Table);
  - знания кита сосредоточены в команде (bus factor); нужна документация компонентов и примеры
    (страница-каталог в dev-режиме или тесты как документация);
  - Tailwind — новая зависимость сборки с риском темпа развития upstream; длинные `className`.
- После перевода в `accepted` обновить:
  - `.claude/skills/tailwind-patterns/SKILL.md` — снять «только после ADR»; убрать упоминания
    `clsx`/`tailwind-merge`/CVA как вариантов «на согласование»; `cx()` и карты вариантов;
  - `.claude/skills/ui-standards-tokens/` — компоненты на нативной платформе (Select base-select,
    Dialog, Popover + anchor), требования п. 7, иконки;
  - `.claude/skills/react-dev/SKILL.md` и агент `ui-standards-expert` — «только компоненты `libs/ui`»,
    запрет UI-библиотек без ADR;
  - `.claude/skills/web-performance-optimization/` — UI-зависимостей рантайма нет;
  - CLAUDE.md (раздел «Ещё не решено», таблица стека), `docs/architecture/stack.md`.
