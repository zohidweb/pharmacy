# Глоссарий домена — Pharmacy (SaaS-платформа автоматизации сети аптек)

Основа — «Бэклог MVP и модель данных» v1.1, раздел 6.1; дополнено по принятым ADR (0008, 0013,
0014, 0018) и модели данных (`docs/architecture/data-model/`). AI и разработчики используют эти
термины в коде и документации, а не изобретают свои.

| Термин (RU) | Термин в коде (EN) | Значение | Синонимы в смежных системах |
|---|---|---|---|
| Тенант | tenant | Клиент платформы — владелец сети или одиночной аптеки; полная изоляция данных между тенантами | Контрагент (в 1С — организация) |
| Точка | store | Аптека или центральный склад тенанта. Режим: облачная / офлайн / `offline-pending` (комплект для перевода в офлайн выпущен, складская запись в облаке закрыта — ADR-0014). Статус: активна / закрыта | Торговая точка, склад |
| Юрлицо сети | legal entity | Юридическое лицо или ИП тенанта (справочник `legal_entities`); точка относится к одному юрлицу. По юрлицу — реквизиты чека, выгрузка в 1С (отдельный файл на юрлицо) и долги поставщикам | Организация (1С) |
| Сотрудник | employee | Учётная запись человека у тенанта: логин/пароль + PIN; может работать на нескольких точках | Пользователь |
| Роль | role | Именованный набор прав, который владелец сети создаёт и меняет сам (динамические роли тенанта, стартовые шаблоны при создании сети). У сотрудника ровно одна роль; охват точек задаётся сотруднику, а не роли (ADR-0018) | — |
| Право | permission | Строка каталога `модуль:действие` (например `pos:sell-controlled`, `finance:view-cost`); каталог — в `libs/shared/domain`, новые права добавляются только кодом. Проверяется на сервере; UI лишь скрывает элементы (ADR-0018) | — |
| Охват точек | store scope | Точки, на которых действуют права сотрудника: все точки сети или список. Выдавать роль и охват можно только в пределах собственных прав (запрет эскалации, ADR-0018) | — |
| Оператор платформы | platform operator | Команда владельца платформы: тенанты, биллинг, ключи, услуги, вход «от имени» | Админ платформы |
| Вход от имени | impersonation | **Решение пересматривается, не реализуется** (ADR-0008, поправка 2026-10-02): способ доступа оператора к данным тенанта выбирается отдельным обсуждением. Прежний замысел — ограниченная по времени сессия оператора только на просмотр, с постоянным баннером и записью в аудит тенанта и платформы | — |
| Платформенные данные | platform data | Таблицы оператора (класс `platform`, ADR-0013): тенанты, операторы, ключи, счета, услуги тенантов, платформенный аудит. Доступ — роль `pharmacy_platform` через `PlatformDatabase`; тенант видит только свои строки | — |
| Витрина тенанта | tenant export | Таблица агрегатов, которую пишет тенант, а читает платформа (класс `tenant-export`, ADR-0013): использование точек по месяцам, счётчики без ПДн и сумм позиций, заявки на услуги. Через неё оператор видит данные тенантов без доступа к самим данным | — |
| Товар | product | Карточка номенклатуры: названия (RU/TJ), МНН, форма, дозировка, производитель, делимость упаковки, признаки «рецептурный»/«ПКУ», штрихкоды | Номенклатура (1С) |
| МНН | inn (int'l nonproprietary name) | Международное непатентованное наименование — действующее вещество; основа поиска аналогов на кассе | Действующее вещество |
| Партия | batch | Конкретное поступление товара на точку: срок годности, закупочная цена в TJS (дирамы, ADR-0016), поставщик. Единица учёта остатков | Серия, лот |
| FEFO | fefo | First Expired — First Out: при продаже первой списывается партия с ближайшим сроком годности (кассир может выбрать другую вручную) | — |
| Движение остатка | stock movement | Атомарное ±количество по партии с указанием источника (документ или чек). Остаток = сумма движений — отдельной таблицы остатков нет | Регистр (1С) |
| Переносящее движение | carry-over movement | Движение с `origin = cloud-snapshot` во флеш-комплекте офлайн-точки: одно на партию, равно облачному остатку на момент выпуска; в outbox не попадает (ADR-0014) | — |
| Документ | document | Складская операция: приход, перемещение, списание, инвентаризация, возврат поставщику, ввод начальных остатков. Статусы: черновик → проведён (перемещение: → в пути → принято) | Накладная |
| Счётчик номеров | document counter | Счётчик `document_counters` по точке, типу документа и году; даёт человекочитаемый номер `<префикс>-<код точки>-<год>-<номер>` (например `ПР-01-2026-000123`). Номер — не ключ | Нумератор (1С) |
| Бизнес-дата | business date | Дата операции в часовом поясе сети (`tenant_settings.timezone`, по умолчанию `Asia/Dushanbe`); по ней строятся отчёты, журнал ПКУ, Z-отчёт и биллинг | Дата документа |
| Чек | receipt | Продажа: строки (партия, кол-во, цена), скидка, оплаты. Статусы: отложен / оплачен / возвращён (частично) | Чек ККМ |
| Смена | shift | Кассовая смена на точке: наличные на начало/конец, инкассация, расхождение, Z-отчёт | Кассовая смена |
| Оплата | payment | Часть суммы чека одним способом: наличные, карта, QR, NFC; чек допускает смешанную оплату | — |
| Скидочное правило | discount rule | Пороги по сумме чека, охват точек, срок действия; применяется одно наиболее выгодное | Акция |
| ПКУ | controlled substance | Предметно-количественный учёт: препараты строгого учёта; отдельное право продажи, обязательные поля рецепта, журнал по позиции и точке | Строгий учёт |
| Поставщик | supplier | Контрагент закупок: реквизиты, история заказов, баланс долга (кредиторская задолженность) | Контрагент (1С) |
| Терминал | terminal | Устройство (POS/ПК), привязанное к точке заведующим/владельцем; только на привязанном терминале кассир входит по PIN. Отвязка — мгновенно (из ТЗ, stack.md) | Касса, рабочее место |
| PIN-сессия | pin session | Сессия кассира на привязанном терминале после ввода PIN (≥ 4 цифр); таймаут — настройка сети тенанта | — |
| Лицензионный ключ | license key | Активация офлайн-точки: уникален для точки, гибкий срок, отзыв при следующей синхронизации | — |
| Очередь синхронизации | sync queue | Операции офлайн-точки, ожидающие отправки в облако (`sync_outbox`); идемпотентная доставка без дублей | — |
| Операция синхронизации | sync operation | Доменный факт точки (`receipt.completed`, `document.posted`, `return.completed`…) с UUIDv7 и номером `storeSeq`; пишется в outbox в той же транзакции, что и факт; облако применяет её один раз (`sync_inbox`) (ADR-0014) | — |
| Лента изменений | change feed | Изменения облачных данных для точки (`sync_changes`): каталог, цены, роли, настройки сети; точка забирает их страницами по курсору (ADR-0014) | — |
| Курсор ленты | feed cursor | Последний применённый точкой номер изменения ленты (`change_seq`); сохраняется в одной транзакции с применённой страницей | — |
| Карантин | quarantine | Состояние операции синхронизации, которую облако не смогло применить: сохраняется с причиной, точка считает её доставленной; разбирается вручную, ни одна операция не удаляется молча (ADR-0014) | — |
| Сверка остатков | stock checkpoint | Операция `stock.checkpoint`: точка сообщает число партий, сумму и хеш остатков, облако сравнивает со своим расчётом; расхождение — красный статус в админке, без автоисправления | — |
| Конфликт синхронизации | sync conflict | Расхождение офлайн/облако: цена (решает владелец в облаке) или дубль товара (решает точка) | — |
| Счёт тенанта | invoice | Начисление за активные облачные точки за период: пропорция по дням, НДС отдельной строкой, PDF | Счёт на оплату (1С) |
| Активная точка | active store | Облачная точка, у которой в расчётном месяце была хотя бы одна продажа — единица тарификации | — |
| Услуга | service | Платная допуслуга платформы; подключается на всю сеть после подтверждения оператором | — |
| Аудит | audit log | Неизменяемый журнал действий «кто, когда, что, точка», включая действия оператора «от имени»; хранение ≥ 3 лет | Журнал регистрации (1С) |
